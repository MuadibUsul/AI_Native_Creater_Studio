# Kinora launch trailer (≈50 s)

The homepage/launch trailer for **Kinora**, the proposed product name (D-02, see `docs/brand/README.md`; until the owner confirms it, internal names stay ANCS). About 50 seconds, 1920×1080, 30 fps, H.264 + AAC. It is built entirely from this repository, with no paid calls, no vendor keys and no third-party footage or music.

| File | What |
|---|---|
| `kinora-launch-trailer.mp4` | The cut, web encode (for a homepage `<video>` or a launch post). v2: Kinora brand and the visual polish below. v1 (ANCS wordmark) is in git history at commit `7c749f9`. |
| `poster.jpg` | Poster frame (end card) |
| `storyboard.jpg` | Contact sheet, one frame per scene |

## How it was made

| Layer | Source | Real or staged |
|---|---|---|
| Product UI | Real screenshots of the current build in a real browser (English, dark, 2×, with the Kinora logo and name in the app), taken by `scripts/promo/capture-ui.mjs`. It runs the studio in-process the same way the browser checks do, including real FFmpeg probing, proxies, previews, effect rendering and export. | **Real product.** The AI director is the repo's scripted stand-in (`scripts/lib/scripted-director.mjs`), not a model. Its plan, cut, effects and replies follow fixed rules. Voice captions come from the local fake speech-recognition service with a fixed sentence. |
| "Footage" | Four original procedural landscapes (aurora, coast sunset, road, waterfall) drawn in code: `apps/render-worker/src/promo/landscapes.tsx`. Rendered to MP4 and uploaded into the product as if they were the user's clips. | Generated by code. No stock footage, no generative model. |
| Effects | The product's own effect template code (`EFFECT_TEMPLATES`: burst, shockwave, sparkles, glow, light leak), run by the same `EffectLayer` the product renders with. Effects also appear inside the UI shots, where the product itself rendered them. | Real product code. |
| Exported video | The montage includes frames from the 12-second video the product exported during capture, with its "AI-generated" label. | Real product output. |
| Music | Original electronic track synthesized in code at 120 BPM: `scripts/promo/soundtrack.mjs`. Every cut and impact sits on its beat grid (1 beat = 15 frames). | Original, no samples. |
| Edit | Remotion composition `LaunchTrailer` (`apps/render-worker/src/promo/LaunchTrailer.tsx` + `trailer-kit.tsx`). | — |
| Logo | The Kinora mark (playhead stem + voice-cone arms + one sound wave), drawn on screen stroke by stroke; same geometry as `apps/web/src/brand/brand.tsx`. | Proposed brand |

The end card says so in small print: *"Pre-release build. In this preview the AI's replies and speech recognition are scripted; the footage is generated by code."* There are no numbers, statistics or customer claims anywhere in the cut.

## Re-render

Requirements: PostgreSQL test database (`ANCS_TEST_DATABASE_URL`), FFmpeg, built packages (`pnpm build`), the web app served on 127.0.0.1:3000 (`next start`), Chromium with H.264 (`ANCS_BROWSER_EXECUTABLE`), and a Remotion browser (`REMOTION_BROWSER_EXECUTABLE`). Fonts: Inter Display and DejaVu Sans Mono.

```bash
OUT=/path/to/promo-work
# 1. Procedural footage clips, plus ambient audio so the timeline shows waveforms
node apps/render-worker/src/promo/run-promo.ts --out $OUT --clips
mkdir -p $OUT/footage
ffmpeg -i $OUT/clips/aurora.mp4 -f lavfi -i "anoisesrc=color=brown:amplitude=0.35:duration=6:seed=1,lowpass=f=400,volume=1.5" -map 0:v -map 1:a -c:v copy -c:a aac -shortest $OUT/footage/aurora.mp4
ffmpeg -i $OUT/clips/coast.mp4 -f lavfi -i "anoisesrc=color=pink:amplitude=0.4:duration=6:seed=2,lowpass=f=1800,tremolo=f=0.35:d=0.8" -map 0:v -map 1:a -c:v copy -c:a aac -shortest $OUT/footage/coast.mp4
ffmpeg -i $OUT/clips/road.mp4 -filter_complex "sine=frequency=72:duration=6,volume=0.5[a];anoisesrc=color=brown:amplitude=0.3:duration=6:seed=3,lowpass=f=600[b];[a][b]amix=inputs=2,tremolo=f=6:d=0.2[out]" -map 0:v -map "[out]" -c:v copy -c:a aac -shortest $OUT/footage/road.mp4
ffmpeg -i $OUT/clips/waterfall.mp4 -f lavfi -i "anoisesrc=color=white:amplitude=0.3:duration=6:seed=4,lowpass=f=3500,highpass=f=200" -map 0:v -map 1:a -c:v copy -c:a aac -shortest $OUT/footage/waterfall.mp4
# 2. Real UI capture (scripted director, no paid calls) → $OUT/public/*.png|jpg + capture.json + export.mp4
#    REMOTION_BROWSER_EXECUTABLE must be set here too: the in-process worker renders the effect trials with it
node scripts/promo/capture-ui.mjs --clips $OUT/footage --out $OUT/public
# 3. Soundtrack
node scripts/promo/soundtrack.mjs --out $OUT/soundtrack.wav
# 4. Stills to check, then the silent trailer
node apps/render-worker/src/promo/run-promo.ts --out $OUT --frames 60,200,300,540,780,1000,1320,1440
node apps/render-worker/src/promo/run-promo.ts --out $OUT --trailer
# 5. Mux with loudness normalisation (-14 LUFS) and encode the web version
ffmpeg -i $OUT/trailer-silent.mp4 -i $OUT/soundtrack.wav -map 0:v -map 1:a \
  -af loudnorm=I=-14:TP=-1:LRA=9 -c:v libx264 -preset slow -crf 21 -maxrate 3.5M -bufsize 7M -pix_fmt yuv420p \
  -c:a aac -b:a 192k -ar 48000 -movflags +faststart -shortest docs/marketing/launch-trailer/kinora-launch-trailer.mp4
```

## v2 polish (same look, pushed further)

The owner liked the v1 look, so v2 keeps its palette, type, pacing and beat grid and adds finish on top:

- **Depth:** soft bokeh orbs drift in the backdrop; each product window casts a blurred light spill of its own picture onto the background.
- **Glass:** a specular highlight sweeps across each UI window once as it lands.
- **Motion:** the four headline cuts whip in and out with directional motion blur; anamorphic lens streaks on the three big hits (logo, montage, end card).
- **Guidance:** callout rings with short labels point at the live caption and the delivery card, so the UI reads at a glance.
- **Logo:** the new mark draws itself stroke by stroke; the wordmark rises letter by letter with a blur-in.
- **Sound:** bandpass whooshes on the four headline cuts and a five-note chime on the logo.
- **Clarity:** the voice trial shot now shows the shockwave mid-ring, with the caption moved out of the way.

## Found while capturing

Capturing the real flow found product bugs, each fixed with a regression test that fails without the fix.

Round 1 (v1):

1. **"Let AI finish the edit" + "Use it if the check passes" could leave the studio stuck on "Preview failed".** If the studio loaded the AI's trial edit before the AI adopted it, the cached proposal stayed "open". The studio kept asking for a preview of an already adopted proposal, and the server refused. The studio now re-reads the trial proposal whenever the project version changes (`apps/web/src/studio/StudioRoom.tsx`; test in `studio.test.tsx`).
2. **Saying "add X here" while pointing at a clip put the effect at 0:00.** `add_effect` without a time used the pointed time range, else 0. It now falls back to the start of the pointed clip, matching the generation tools (`packages/domain/src/agent-effects.ts`; integration test in `apps/worker/src/effects.integration.test.ts`).

Round 2 (v2):

3. **Uploaded images stayed "Processing" forever.** Found in an exploratory pass with a vertical video, an MP3 and a PNG. Images don't need media probing (`probeStatus = NOT_REQUIRED`), but the studio treated "no probe" as "still processing". The footage card spun forever, "Let AI finish the edit" waited until its footage timeout, and the AI's `list_footage` tool told it footage was still processing. Both now treat `NOT_REQUIRED` as ready (`packages/domain/src/studio.ts`, `agent-tools.ts`; real-PostgreSQL test `apps/api/src/studio-footage-readiness.integration.test.ts`).
4. **Dated model snapshots were treated as unpriced.** With a monthly AI cap, a model name like `vendor-pro-2026-09-01` didn't match the price entry `vendor-pro`, so the cap would refuse to call it. Prices now resolve a snapshot suffix (`-YYYY-MM-DD`, `-YYYYMMDD`, `@YYYYMMDD`, `-latest`) to its base entry, and nothing looser (`resolveModelPrice` in `packages/contracts/src/agent.ts`, used by cost accounting and the cap; tests in `env.test.ts`). Found by reading the code, not observed live.
5. **"Preview failed" flashed when the AI adopted its own trial quickly.** Found in the v2 frames: in "Let AI finish the edit" with "Use it if the check passes", the AI adopted its first cut half a second after making it. The studio saw the trial before its next poll of the project, asked for a preview of a proposal that was already adopted, and the server rightly refused (409, proposal no longer open). The monitor showed "Preview failed / Retry" and the stale "Keep it / Discard" card until the next poll, up to 2.5 s later. A refusal because the trial is no longer open now makes the studio re-read the proposal and the project at once instead of showing an error. A refusal for an open trial (the project changed after it) still shows the error (`apps/web/src/studio/StudioRoom.tsx`; two tests in `studio.test.tsx`). The v1 regression test for the same area checked for the wrong Chinese string, so its "no error shown" assertion could never fail. It now checks the real text.
6. **A failed effect render said only "Node.js v22.22.0".** Found when a re-capture ran without `REMOTION_BROWSER_EXECUTABLE`. Remotion in the sandboxed effect process tried to download a browser, the download failed offline, and the process crashed with an unhandled error. The worker reported only the last line of the crash output, so the AI and the operator saw "特效渲染失败：Node.js v22.22.0". It now reports the actual error ("Error: getaddrinfo ENOTFOUND remotion.media"). Production sets the browser in the Dockerfile, so this is about being able to diagnose it (`apps/worker/src/effect-renderer-process.ts`; unit test with a real crashing child process).
