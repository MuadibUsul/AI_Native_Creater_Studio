# N01-08｜版本、快照与补偿事件扩展

日期：2026-10-09。状态：**VERIFIED**。依赖 N01-05、N01-06、N01-07 均已 VERIFIED。

## UI 交付卡

- **用户目标 / 角色 / 空间：** 创作者和 AI 在同一工程中裁剪素材、修改关键帧或音频参数后，可以可靠撤销、重做、恢复版本，并在并发或重复提交时保持唯一权威状态。
- **入口 / 对象 / 范围：** 复用 `POST /projects/:projectId/edits`、SDK `projects.edit`、版本与 Undo/Redo 入口；扩展 Clip、Animation、AudioRegion、ObjectLock、EditEvent、Outbox 和 ProjectVersionSnapshot。
- **主流程 / 恢复：** 编辑携带 Project revision → Project 行锁内重检 → 保存对象完整 before/after 与稳定引用 → 状态、事件、Outbox 同事务；Undo/Redo 写补偿事件；版本恢复重建完整 Composition 与对象锁。
- **权限 / 费用 / 锁定：** 沿用 `project:write`；版本恢复会检查当前全部对象锁，必须显式解锁才可覆盖。无 Provider 调用和费用。
- **设计覆盖：** UI 不适用。本任务是 History、专业时间轴和 AI 提案后续共用的恢复内核；没有新增页面或临时管理表单。
- **真实业务 / 证据：** 真实 PostgreSQL 覆盖源裁剪、关键帧、音频、锁补偿、并发竞争和完整版本恢复；既有 HTTP/SDK 幂等集成测试证明同键重放不重复 EditEvent。

## 实现

- 新增 `update_clip`、`update_animation`、`update_audio_region` 公共契约，严格校验非空变更、时间范围、线性映射、关键帧顺序、音轨和淡入淡出边界。
- 迁移 0062 为 `edit_events` 增加 `object_kind`、`object_id` 与项目对象索引，并保留 `scene_id` 兼容旧消费者。
- 对象编辑保存完整 before/after DTO；对象锁保存前后维度和原因。Undo/Redo 只追加 `UNDO_*` / `REDO_*` 补偿事件。
- Project revision 是结构编辑统一 CAS 条件。同一 revision 的并发对象写入只有一方成功，失败方得到 `VERSION_CONFLICT`。
- ProjectVersionSnapshot 兼容旧快照，并新增完整 ProjectDocument 与锁集合。快照固化 Sequence、Track、Clip、VisualObject、Effect、Animation、Caption、AudioRegion、AssetVersion 引用及依赖边。
- Restore 在一个事务内按依赖顺序替换规范化 Composition 和对象锁，再恢复兼容 SceneGraph；旧的仅 SceneGraph 快照保持可读，不误删后来建立的规范化数据。
- Outbox `project.updated` 增加 `objectRefs`。API 与 SDK 继续复用统一类型化编辑入口，没有第二套状态、revision 或幂等规则。

## 限制与回滚

- 单对象编辑目前激活 Clip、Animation、AudioRegion；VisualObject/Effect 完整状态已进入快照和依赖图，其 v2 写操作由 N01-11 注册后沿用同一事件、锁和补偿模式。
- 旧 `0.x` 快照没有 `document` 时只恢复旧 SceneGraph，不猜测或删除当时未快照的 Composition v2 数据。
- 回滚应用前应停止对象编辑写入。0062 两列对旧代码无害；回滚迁移前需确认没有消费者依赖对象引用，再删除索引与两列。
