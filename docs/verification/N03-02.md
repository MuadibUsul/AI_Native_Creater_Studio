## 实现证据

- **契约（5 个新规范原语）**：`packages/contracts/src/composition-edits.ts` 新增 `splitClipOperationSchema`（`clipId` + `at` + 可选 `createdClipId`/`createdAudioClipId`）、`trimClipOperationSchema`（源范围 + 序列范围）、`moveClipOperationSchema`（目标轨与／或目标区间，至少其一）、`duplicateClipOperationSchema`、`replaceClipSourceOperationSchema`（源版本／嵌套序列恰一）。`EDIT_OPERATION_TYPES` 20→25，`editOperationSchema` 联合与 `EDIT_OPERATION_REGISTRY` 同步登记（含 readSet/writeSet/preconditions/postconditions，`EVENT_INVERSE` 补偿）。
- **v2 覆盖层**：`packages/contracts/src/edit-operation-v2.ts` 把 `move_clip`／`trim_clip` 从 `COMPILED_ALIAS` 提升为 `NATIVE`（规范操作即自身，不再编译成 `update_clip`），`split_clip`／`duplicate_clip`／`delete_clip` 由 `PLANNED` 翻为 `NATIVE`，并新增来源操作 `replace_clip_source`（`SOURCE_EDIT_OPERATION_TYPES` 33→34）；遗留的 `plannedSchemas.delete_clip/split_clip/duplicate_clip` 与重复的 move/trim 源形状一并删除，`moveClipSourceOperationSchema`／`trimClipSourceOperationSchema` 改为指向规范 schema（不再另立一套形状）。`packages/domain/src/edit-operation-v2.ts` 的编译器删掉已成死代码的 move/trim 别名分支，NATIVE 分支直接按规范 schema 透传。
- **事务执行器**（`packages/domain/src/edits.ts`）：
  - `split_clip`：切点必须在片段内部（`SPLIT_POINT_OUTSIDE_CLIP` 422）、要求 1:1 前向映射（`SPLIT_UNSUPPORTED_MAPPING` 422）；左段保留原 id 并前移出点，右段新建且 `parentClipId` 指向原片段（**子片段血缘**）；AV 关联片段按同一左段时长同步切分；绑定音频区域跨切点 → 409 `CLIP_BOUND_AUDIO_REGION_UNSUPPORTED`（fail-closed，区域级重算属 N03-06）。
  - `trim_clip`：源/序列时长必须相等（`TRIM_RANGE_DURATION_MISMATCH` 422，不隐式改速或改长）、1:1 映射要求、源侧越界（`SOURCE_RANGE_OUT_OF_BOUNDS` 422）、序列侧越界（`SEQUENCE_RANGE_OUT_OF_BOUNDS` 422）、同轨重叠（`CLIP_OVERLAP` 409）；AV 关联片段同步裁到同一序列区间。
  - `move_clip`：保持时长（`MOVE_REQUIRES_EQUAL_DURATION` 422）、轨类型必须一致（`TRACK_KIND_MISMATCH` 422）、目标轨锁定（`TRACK_LOCKED`／`EDIT_IMPACT_LOCKED` 409）、目标区间重叠（`CLIP_OVERLAP` 409）；`CLIP_LOCAL` 基的绑定音频区域随片段平移（局部时钟不变并落 UPDATE_AUDIO_REGION 事件），非局部基 → 409 fail-closed；AV 关联片段按同一 delta 平移（跨轨移动时留在各自轨道上保持对齐）。
  - `duplicate_clip`：只复制时间线引用（**复制不触碰 `assets`／`asset_versions`**，同一 `assetVersionId`），锚点默认源片段自身、可指定 `afterClipId`；目标位置被占 → 409；AV 对一并复制并组成新的关联组；`parentClipId` 指向源片段。
  - `replace_clip_source`：新源范围时长必须等于片段当前序列时长（`SOURCE_DURATION_MISMATCH` 422）＋ READY/校验和/边界检查；`SOURCE` 基的绑定音频区域 → 409 fail-closed；AV 关联片段换用同一新源。
  - **对象锁纵深防御**：新增 `assertObjectLockAllows`，五种操作分别检查主片段（CONTENT/DURATION/POSITION）与移动目标轨（POSITION/DURATION）上的显式对象锁；`move_clip` 的影响面在给出 `trackId` 时一并声明目标轨（锁定目标轨由影响面门先拒）。
- **undo/redo**（`packages/domain/src/undo-redo.ts`）：五个操作各自落一条以操作名命名的事件（`SPLIT_CLIP`／`TRIM_CLIP`／`MOVE_CLIP`／`DUPLICATE_CLIP`／`REPLACE_CLIP_SOURCE`），补丁即显式操作对象本身 + before/after；`planUndo` 给出精确逆操作（切分→恢复左段、复制→删除引用、移动→回原位与轨道、裁剪→回原入出点、换源→换回原源），`reconstructOperation` 供 Redo 用同一 id/参数重放。

## 发现并修复的真实缺陷

**裁剪时 AV 关联片段的源出点被放大 1000 倍**：`trim_clip` 把裁剪时长从"秒分数"换算到关联片段的源时基时，误把序列时基的换算系数又乘了一遍（`exactTicks({ num: num*den_seq, den: den*num_seq }, sourceTimebase)`），测试抓到 `srcTo` 变成 `3001000`（期望 4000）——即真实在 1000 时基下会把音频关联片段的源范围放大 1000 倍。修复：直接把秒分数交给 `exactTicks(trimSeconds, siblingTimebase)`（与 N03-01 插入路径同一写法），并由集成用例锁死。
