# N02-01｜有界内存的批量分片直传

日期：2026-10-09。状态：**VERIFIED**。依赖 N00-06、N01-02 已 VERIFIED。

## 实现范围

- Contracts：增加 `SINGLE | MULTIPART` intent、分片状态／目标／完成 DTO，以及流式 `composeObjects` 存储 seam。
- Migration：`0064_pretty_inertia.sql` 为 upload intent 增加模式、分片大小和数量，并建立工作区隔离的 `upload_parts`。
- Domain/API：创建与读取 intent、短时分片目标、服务端大小及 SHA-256 校验、取消、完整性检查、流式合并和既有最终确认／去重。
- SDK：Blob/File 按 slice 读取，分片并发固定在 1—6（默认 3）；支持进度、暂停、继续、取消和 `resumeIntentId`；批量文件依次创建 intent，避免额度竞争。
- UI：素材上传对话框支持多选、逐文件队列、真实进度、暂停／继续／取消和错误恢复。
- 存储：Local provider 按顺序流式拼接到临时文件后原子替换，不把完整产物读入内存。

## 边界、限制与回滚

- 真实边界是本地 MP4、真实数据库、真实登录、真实本地磁盘和签名 URL；未使用 S3/R2，也不描述为第三方对象存储实测。
- 浏览器端不读取完整 File；服务端本地签名上传端点一次最多缓冲一个受限分片（当前上限 64 MiB），最终对象采用流式合并。生产云存储直传由后续 provider adapter 延续相同契约。
- 当前页面会话内可从断网／暂停继续；SDK/API 在给定 intent ID 和原文件时可跳过已确认分片。浏览器重启后自动恢复本地文件授权不在本任务范围。
- 回滚可删除 `upload_parts` 及 upload intent 的三个新增列，恢复旧单文件入口和 SDK；已经完成的素材对象与 AssetVersion 不需要删除。
