# N01-10｜MediaSource 与 ClipInstance 单一权威映射

日期：2026-10-09。状态：**VERIFIED**。依赖 N01-03、N01-05 已 VERIFIED。

## UI 交付卡

- **用户目标 / 角色 / 空间：** Web、Native 和自动化客户端从同一 ProjectState 识别“不可变原始媒体”与“时间线使用实例”，同一源文件可在多个区间复用而不复制源事实。
- **入口 / 对象 / 范围：** 沿用 `GET /projects/:projectId/state` 与 SDK `projects.state`；响应新增 `mediaSources`、`clipInstances`。分析和代理状态由内部 `upsertMediaDerivativeState` 更新关联对象。
- **主流程 / 恢复：** READY AssetVersion 成为 MediaSource → Clip 引用形成 ClipInstance → 分析／代理写入 `media_derivatives` → ProjectState 返回稳定投影。旧毫秒字段只做单向投影；旧更新先编译为正式 `update_clip`。
- **权限 / 费用 / 锁定：** 沿用 `project:read`／`project:write` 和 workspace 归属；跨租户派生版本返回 404。本任务无 Provider 调用和费用。
- **设计覆盖：** UI 不适用。本任务统一状态与兼容边界，现有 Studio 页面没有新增可见操作；后续媒体索引和播放界面消费该公共契约。
- **真实业务 / 证据：** 真实 PostgreSQL、Fastify、Better Auth 和 SDK 覆盖一源多实例、分析与代理状态、旧写兼容、精度拒绝和跨租户隔离。

## 实现

- `MediaSourceView` 以 `AssetVersion.id` 为唯一源身份，公开不可变 checksum、媒体元数据和派生状态；`ClipInstanceView` 以规范化 Clip 为唯一实例身份。
- 迁移 0063 新增 `media_derivatives`。数据库约束枚举、profile、源 checksum、源／输出不可同一版本，并要求 READY 代理绑定输出 AssetVersion。
- 创建或更新 Clip 时，引用的 AssetVersion 必须为 READY、时长已知且具有 SHA-256；分析和代理状态不会修改源版本行。
- 派生状态更新锁定源版本，强制 workspace 隔离，并拒绝开始跟踪后源 checksum 变化。
- 旧毫秒投影只在无精度损失时生成；旧写编译为类型化 `update_clip`，不能提交 AssetVersion、source identity 等权威字段。
- ProjectState 和 SDK 返回 MediaSource／ClipInstance；旧 Scene 写入后两组投影保持不变。

## 限制与回滚

- N01-10 只建立权威媒体身份、Clip 投影和派生状态关系；代理生成、探测与完整 Media Index 分别由 N02 任务交付。
- ProjectState 是读取投影；写入仍只走正式编辑协议或派生状态服务，不开放任意对象补丁。
- 回滚需先删除 0063 的 `media_derivatives` 表，再移除 ProjectState 新字段与服务；AssetVersion、Clip 及旧 SceneGraph 数据无需回写。
