- **implementationSummary**：
  1. **退避与抖动**（迁移 0012：`jobs.next_attempt_at` + 认领索引含退避列）：`computeBackoffSeconds` = `min(base·2^(attempts-1), cap) · (1 ± jitterRatio)`（base 5s / cap 300s / 抖动 ±20%，可经 `DomainDeps.retryPolicy` 注入随机源做确定性测试）；`failJob` 置 `FAILED_RETRYABLE` 时写入 `nextAttemptAt` 并在事件中记录 `backoffSeconds/nextAttemptAt`；**`claimJob` 不认领退避未到期的任务**；进入 QUEUED 的任何路径（自动重试推进/租约回收/人工重试）都清退避（单点保证，避免残留等待）。
  2. **自动重试推进**：`promoteRetryableJobs`（退避到期 → QUEUED + `job.queued(BACKOFF_ELAPSED)`，行锁复核、可重入）；`retryJob`（人工）立即清退避生效。
  3. **失败检查**：`inspectJobs`（状态计数 / 需对账数量 / FAILED_FINAL 清单）；`resolveStuckDependents`（**孤儿等待**——依赖已全部终态但仍 WAITING_DEPENDENCY → 升级或明确失败，保证"绝不永久等待"在并发边缘/崩溃遗留下依然成立）。
  4. **杀 Worker 可继续（故障注入）**：执行器新增 `onPhase` 钩子（`after-claim` / `mid-handler` / `before-complete`），注入抛错**穿透**执行器 catch（等价于进程被杀：不写终态、不释放租约）；CLI 通过 `ANCS_WORKER_CRASH_AT=<phase>` 直接 `process.exit(86)`（可用于演练与 CI）。恢复路径：租约到期 → `requeueExpiredLeases` → 重新认领 → 成功。
  5. **重复消费不产生重复副作用**：`transitionJob` 对**终态的同状态上报**返回 409（陈旧 Worker 结论被拒），已完成结果不被覆盖、事件不重复；租约持有者校验（心跳/完成仅限租约所有者）；BullMQ 侧以 `jobId:attempt` 作为任务 ID（投递幂等）+ 认领 CAS。
  6. **取消协作与传播**：执行中取消 → `CANCEL_REQUESTED`；执行器经心跳感知 → 收敛为 `CANCELLED`（`WORKER_HONORED_CANCEL`，不是 FAILED）；取消作为终态触发依赖传播（依赖方以 `DEPENDENCY_FAILED/CANCELLED` 明确终止）。
  7. **真实 Redis/BullMQ 端到端**（兑现 P03-01 交接义务）：`infra/docker-compose.dev.yml` 增补 `redis`（127.0.0.1:56379），CI workflow 增补 `redis:7-alpine` service 与 `ANCS_TEST_REDIS_URL`；`packages/providers/queue-bullmq` 装入 `bullmq@5.34.0` 并新增真实 Redis 集成测试：适配器投递 → Worker 消费（消息仅 `{jobId,queue,attempt}`）；**"Worker 未运行期间消息持久在 Redis，恢复的 Worker 仍能消费"**；**多 Worker 竞争：每条消息恰好被消费一次**。

- **验收条款对照**：
  1. **"各关键点杀 Worker 后可继续"** → 通过：三个关键阶段（认领后/执行中/完成前）分别注入崩溃 → 任务保持 RUNNING 且无终态写入（断言数据库事实）→ 租约到期回收 → 新 Worker 认领（attempts 递增）→ 执行成功；另有"真实杀进程语义"用例（不做任何状态写入即观察）与 CLI 级 `ANCS_WORKER_CRASH_AT` 退出码 86 的故障注入开关。
  2. **"重复消费不产生重复副作用"** → 通过：陈旧 Worker 上报 → 409（终态同状态迁移被拒），`result` 保持第一次写入值、`job.completed` 事件恰 1 条；BullMQ 多 Worker 竞争下每条消息恰一消费（真实 Redis 断言）；认领为 CAS（SKIP LOCKED + 状态条件）。
  3. **退避与抖动**（REQ-19-03） → 通过：公式单测（含 cap 与抖动边界 0.8×/1.2×）+ 端到端（未到期不可认领、到期自动升级、重跑不重复、人工重试立即生效）。
  4. **失败检查** → 通过：inspectJobs 运维视图 + 孤儿依赖解析（在"依赖已终态但依赖方仍等待"的人为边缘下，一次检查即收敛）。

- **本次修复的工程问题（诚实记录）**：
  1. **failJob 重构遗漏依赖解析**：把 failJob 从 `transitionJob` 拆出后（为了写退避），忘记在新事务里调用依赖解析 → P03-01 的"依赖失败传播"测试回归失败；修复为共用的 `resolveDependentsInTransaction`（单一实现，两条路径都调用）。

  3. **retryJob 返回陈旧 DTO**：清退避的 UPDATE 在 transition 之后 → 返回对象不含新值；改为清退避后重读返回。
  4. **BullMQ 键前缀不一致**：适配器默认前缀 `ancs` 与测试/Worker 的 BullMQ 默认 `bull` 不同 → 消息投递到不同键空间（表现为"投递了但无人消费"）；默认前缀改为 BullMQ 默认（可配置覆盖）。
  5. **单元/集成项目包含关系**：`*.integration.test.ts` 同时匹配 unit 的 `*.test.ts` 通配 → 集成用例被单元项目执行（无 DB/Redis 时失败）；unit 显式排除 `apps/worker/**` 与 `packages/providers/**` 的 integration 文件。
