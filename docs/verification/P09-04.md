     保留历史不占用）+ `workspaces.privacy_tier`。
  3. **领域服务** `packages/domain/src/invitations.ts`：
     - `createInvitation`：**不要求账号已存在**（账号由内部创建）；已是成员 → 409；授予 OWNER 仅限 OWNER（403）；
       **席位早期检查**（成员 + 未过期待接受邀请 + 1 ≤ 上限，超出 422 SEATS_EXCEEDED）；
     - `listInvitations` / `listMyInvitations`（按登录邮箱，未过期 PENDING，附 Workspace 名称）；
     - `revokeInvitation`（PENDING → REVOKED；非 PENDING 明确 409）；
     - `acceptInvitation`：状态/过期/邮箱匹配（403 EMAIL_MISMATCH）逐项校验 → **席位权威复查**（成员 + 1 ≤ 上限；
       超出 422，邀请保持 PENDING）→ 成员写入 + 邀请 ACCEPTED **同事务**；并发重复由成员唯一约束兜底。
  4. **降级套餐清晰超额处理**（`plans.ts`）：`getWorkspaceEntitlement` 计算 `overCommitted`（用量 > 上限；
     null = 不限；**privacyTier ≠ STANDARD 且 plan.privacyMode = false → 'privacyMode'**）。
     语义：**新增被阻止**（断言 422/403）、**存量成员/数据保留**（绝不自动移除/删除）、**档位不静默改写**——
     由界面明确提示"升级或显式调整"。
  5. **API**（`routes/workspaces.ts`）：`POST/GET /workspaces/:id/invitations`、`DELETE /workspaces/:id/invitations/:invitationId`
     （member:manage）；`GET /invitations`、`POST /invitations/:invitationId/accept`（认证用户；
     返回取得的 Workspace 与角色）；`PATCH /workspaces/:id/privacy`（workspace:update；非 STANDARD 经
     `getWorkspaceEntitlement` 门禁，无权益 → 422 PRIVACY_MODE_NOT_ALLOWED）；**直接添加成员补席位断言**
     （三处入口：添加成员/邀请创建/邀请接受）。
  6. **SDK**：`workspaces.invitations.{list,create,revoke}`、`workspaces.setPrivacyTier`、
     `client.invitations.{mine,accept}`。
  7. **Web**：`/w/[workspaceId]/team`（`TeamManagement`）——成员列表（角色变更/移除）、邀请（创建/撤销；接受条件
     说明）、**超额横幅**（维度中文标签 + "现有成员与数据保留"）、隐私档位（无权益时非 STANDARD 禁用并给
     title 提示）。
