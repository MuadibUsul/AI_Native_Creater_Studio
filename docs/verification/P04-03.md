- **验收条款对照**：
  1. **"接入真实 LLM Adapter"** → 接口与装配就位：`LlmAdapter` 在 contracts，Mock 实现同契约并接入服务与启动装配（默认 mock + 明确提示，§76-03）；**真实适配器（凭据）随 P06-01**——诚实边界已记录。
  2. **"输出口语化叙事、章节、旁白段和估计时长"** → 通过：NarrativePlan 全字段落库；估计时长按 220 字/分钟（并与"必须口语化"绑定：逐字抄袭被拒）。
  3. **"Schema 不合法时有限修复"** → 通过（有界且有记录）：可修复场景自动规整（未知字段/字符串数字/缺省/重复 id），失败时**至多 2 次 LLM 调用**后 422（附 attempts/detail/repairs）；结构性缺失（无 narrationBlocks）不瞎猜。
  4. **"锁定文字保留"** → 通过：再生成时锁定旁白逐字不变（测试断言跨版本同 id 同文本）；模型改写 → 回滚 + 修复记录；模型丢失 → 补回；锁定块文本编辑 → 409（AC-14 的"明确提示，不静默修改"）。
  5. **"事实类型保留"** → 通过：旁白只能引用已登记事实 id（未登记引用被剔除；keyClaims 全非法 → 422）；claims 表不被生成触碰（事实/分析/观点/不确定类型在 P04-02 固化）；`requiredVisualFacts` 由 keyClaims 派生（供 P04-04/05）。
- **本次修复的工程问题（诚实记录）**：
  1. **旁白块主键跨计划冲突（与内容块同类缺陷）**：Mock 输出的 `nrb_1..n` 作为主键在第二次生成时冲突（首次运行掩盖、第二次暴露）。最终采用**双 ID 设计**：行主键按计划作用域（`nbr_<planPrefix>_<n>`）、**逻辑 ID（logical_id）跨版本稳定**并对内暴露——既满足"锁定旁白身份不变"，又保证主键唯一（迁移 0020）。
  2. **锁定查询用错了 ID 维度**：加载上一版锁定旁白时误用行主键（导致身份漂移）——改为 `logicalId`（修复后测试才真正验证了"同 id 同文本"）。
  3. **错误分类污染**：初版把任何异常都映射为 422 INVALID_LLM_OUTPUT，掩盖了 DB 错误（在本轮调试中真实发生并误导）——改为 ApiFailure/未知错误原样上抛，仅 LLM 输出类错误进入 422 映射。
  4. **Mock 自身违反口语化约束**：初版"改写"直接拼接事实原文（8-gram 命中被自己的门控拒绝）——Mock 改为真正的确定性改写（只提取数字/主题词组句），并在提示词中写入 id 约定（生成块 `nrg_` 与锁定块 id 区分）。
