# N01-03｜序列、轨道、Clip 与源范围验证

日期：2026-10-08。状态：**VERIFIED**。依赖 N01-02 已 VERIFIED。

## UI 交付卡

- **用户目标 / 角色 / 空间：** 创作者需要把同一素材的不同源区间放入一个或多个序列，在多轨上重叠组合，并保持源素材、序列位置和速度映射可追溯。
- **入口 / 对象 / 范围：** 本任务建立 Project 聚合内的 Sequence、Track、Clip 规范化内核；用户可见的时间轴插入、裁剪、移动和精确操作由 N03-01—04 及 N04-07 接入。
- **主流程 / 恢复：** Clip 只引用一个 AssetVersion 或嵌套 Sequence；`sourceRange`、`sequenceRange` 与 `timeMapping` 均使用 N01-01 的有理时基。原素材不修改，同一版本可以被多次引用。N01-03 只提供创建和统一读取，Undo/Redo 与补偿由 N01-08 接入。
- **权限 / 费用 / 锁定：** 所有 domain 调用必须携带 workspaceId 与 projectId；跨租户资产统一 404。锁定轨道拒绝新 Clip。本任务不调用 Provider、不创建付费 Job。
- **设计覆盖：** UI 不适用；这是 N03 时间轴和 N04 专业控件的领域基础，没有新增临时管理页或第二套前端状态。
- **业务 / 测试：** 使用精确隔离 PostgreSQL 执行真实迁移与 domain 集成；ProjectDocument 同源读取规范化 Composition。没有 Mock Provider 或生产数据。

## 实现

- 新增 `composition.ts` 公共契约：`Sequence`、`Track`、`Clip`、四类轨道、线性 `timeMapping`、创建请求与响应类型。Clip 契约和数据库约束均强制 `assetVersionId` / `nestedSequenceId` 二选一。
- 迁移 0058 新增 `project_sequences`、`sequence_tracks`、`sequence_clips`；轨道位置在序列内唯一，Clip 保存 source/sequence ranges、time mapping、AV group、source stream 和对象父引用。
- Domain 新增创建序列、轨道、Clip 及读取整个 Project Composition。写入前检查项目、序列、轨道、资产版本与父对象均属于同一 workspace/project。
- 源范围不得越过 READY AssetVersion 的已知时长；序列范围不得越过目标序列；`timeMapping.rate` 必须与两个范围的有理时长完全一致，不用浮点近似。
- 嵌套序列在写入前遍历现有依赖图，拒绝自循环和间接循环。不同轨道的区间重叠合法，同一 AssetVersion 可用不同源范围重复引用。
- `assembleProjectDocument` 读取规范化 sequences/tracks/clips，并继续保留旧 SceneGraph 为只读兼容投影；没有建立第二套工程权威。

## 边界与回滚

- API/SDK/UI 在本任务不适用：N01-09 统一交付工程 API/SDK/事件，N03 交付真实时间轴操作与用户界面。本任务不能据此宣称编辑产品切片已经完成。
- 当前 AssetVersion 仍以既有 `durationMs` 保存媒体时长；读取时使用 N01-01 的无损毫秒适配。N02-02/03 将引入正式探测时基和源时间映射，不能静默降低精度。
- N01-03 没有实现复杂效果、字幕、关键帧和音频自动化；这些由 N01-04 继续扩展同一 Composition。
- 回滚须先停止写入新 Composition，再删除 0058 三表和相应代码；旧 projects/scenes/assets/project_versions 不受影响。没有删除或改写原媒体。
