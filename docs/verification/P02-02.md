- **验收条款对照**：
  1. **"并发更新无丢失"（AC-04）** → 通过（双层证据）：服务层——同 Scene 并发编辑 `Promise.allSettled` 恰一个成功，失败方 409 且 details 含 `currentProjectRevision` 与冲突 Scene 的当前 revision；不同 Scene 并发编辑**均可成功**且 Project revision 递增两次（无丢失更新）；HTTP/SDK 层——同一场景两个并发请求恰一个 200、一个 409 `VERSION_CONFLICT`（AncsApiError 断言 details）。
  2. **"同键重放无重复事件"（AC-03）** → 通过：同幂等键同请求体重放返回**逐字段相同**的响应（项目 revision 不变），`edit_events` 计数只增加一次（`UPDATE_SCENE` 恰 1 条）；重复提交不产生副作用。
  3. 附加锁定：结构性操作过期 base → 409 且 details 给最新 revision；Lock 场景不可 update/delete/split，显式解锁后恢复可编辑；未排期操作 501（含 plannedPhase）且**批内任一失败整批不提交**（项目 revision 与目标 Scene 均未变）。
- **本次修复的工程问题（诚实记录）**：
  1. **幂等键的传输现实**：测试中用中文幂等键触发 `Headers.set` 的 ByteString 错误（HTTP 头仅 Latin-1）——契约收紧为 ASCII 可打印字符（含契约测试），并在 SDK 侧由请求体校验先拦截。
  2. **幂等键双源**：§4.6 的幂等键位于请求信封（body），而中间件此前只认请求头——现为"请求头优先、请求体 `idempotencyKey` 兜底"，SDK 同时镜像到请求头（真实客户端不依赖 SDK 也安全）。
