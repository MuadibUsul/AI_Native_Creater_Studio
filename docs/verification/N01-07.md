# N01-07｜范围锁与间接影响计算

日期：2026-10-09。状态：**VERIFIED**。依赖 N01-06 已 VERIFIED。

## UI 交付卡

- **用户目标 / 角色 / 空间：** 创作者锁定内容、时位、时长、资产、样式或轨道后，Web 与 AI 的后续编辑都必须保护该对象及被间接影响的依赖对象；只有明确解锁才能继续。
- **入口 / 对象 / 范围：** 复用 `POST /projects/:projectId/edits` 和 SDK `projects.edit`；新增 `set_object_lock`，对象覆盖 Project、Scene、Sequence、Track、Clip、VisualObject、Caption、AudioRegion。范围锁执行内核供后续专业时间轴与提案采用复用。
- **主流程 / 恢复：** 显式加锁或解锁 → 整批候选模拟 → 计算直接影响、时间线涟漪和依赖传播 → 与六类锁求交 → Project 行锁内重算 → 锁、状态、EditEvent、Outbox 同事务提交。任一冲突整批不落库。
- **权限 / 费用 / 锁定：** 沿用 `project:write`；USER/SYSTEM 可明确解锁，AI 解锁被 403 拒绝。该能力不调用 Provider、不产生费用。
- **设计覆盖：** 本任务交付统一执行语义和公共 API/SDK 类型，不新增页面；现有编辑入口自动获得保护。专业时间轴的可视化锁控件由对应 N03/N04 用户切片实现，本任务不声称该 UI 已交付。
- **业务 / 测试：** 真实 PostgreSQL 验证持久化、跨租户目标隔离、无 `sceneId` 的重排、ripple 间接位移、同批解锁和整批回滚；HTTP/SDK 验证公共路径；全量门禁覆盖现有 Web、Director、Undo、Worker、Render。

## 实现

- 新增六个维度：`CONTENT | POSITION | DURATION | ASSET | STYLE | TRACK`；新增八类锁目标和严格契约。空维度、未知目标类型或未知维度在边界拒绝。
- 迁移 0061 新增 `project_object_locks`，以 `(project_id, object_kind, object_id)` 唯一；数据库 CHECK 限制目标类型、非空 JSON 数组和合法维度。
- `validateEditOperationCandidate` 为每个操作生成影响集：
  - update/delete/replace/restore 计算直接内容、时长、资产或样式影响；
  - insert/delete/duplicate/split 计算后续 Scene 的间接 `POSITION` 涟漪；
  - reorder 比较前后位置，因此即使操作没有 `sceneId` 也不能绕过时位锁；
  - `EditImpactDependency` 对嵌套对象按维度传递影响，可递归扩展且去重。
- 显式解锁是独立的有序操作；同批后续编辑只读取更新后的候选锁状态。AI 对 `set_object_lock(false)` 和旧 `set_scene_lock(false)` 均返回 `AI_UNLOCK_FORBIDDEN`。
- 事务外快速预检和 Project 行锁内权威复核都加载当前锁；非 Scene 目标按 workspace/project 查询，跨租户统一 404。
- 每次锁操作写 `SET_OBJECT_LOCK` EditEvent 的前后维度与原因；最终锁状态、Project revision 和 Outbox 同事务提交。锁 DTO 和事件不含凭据或外部数据。
- Director 改用规划的稳定 `sceneId` 顺序追加，避免批内后续插入移动刚创建且已锁定的 Scene；仍保持一次原子请求与幂等键。
- 既有 SDK `projects.edit` 直接消费扩展后的共享 `EditRequest`，无需新增第二个执行入口。

## 分层、限制与回滚

- Contracts、migration、domain/service、既有 API/SDK、tests、docs 已完成。UI 不适用：本任务是统一锁与影响执行内核；专业锁控件属于后续具体编辑切片。
- 当前活动操作覆盖旧 Scene 编辑、重排和时间线涟漪；全局主题与 Composition v2 的具体写操作尚未由 N01-11/N03 激活，但其依赖影响传播接口和锁目标已经契约化并通过单测。
- `set_object_lock` 的补偿模式暂标 `PLANNED`；N01-08 将把锁事件纳入完整 Undo/Redo 前后状态恢复。
- 回滚代码前应先停止新锁写入；迁移回滚需确认无锁记录后删除 `project_object_locks`。仅回退应用代码会保留无害的 0061 表。
