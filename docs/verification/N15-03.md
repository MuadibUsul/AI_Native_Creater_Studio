# N15-03 验证：运营 RBAC/ABAC 与职责分离策略

**状态：IN_PROGRESS。** 2026-10-08（Asia/Shanghai）。本记录覆盖已实施的 0053—0055 授权切片；不代表 N15-03、O0 或生产后台已验收。

## 已实施边界

- Contracts：封闭的 23 项旧 Admin `OpsAction`、`PLATFORM / WORKSPACE / OBJECT` scope、资源/金额/工单目标及固定拒绝原因。未知 action 默认拒绝。
- Migration 0053：`admin_role_scopes` 将角色 grant 限定到 workspace/对象/工单、金额和有效期；scope 增删改使 principal `grant_version` 递增。旧角色 grant 不回填 scope。支持授权要求明示受益 principal、工单和只读字段 scope。
- Migration 0054/0055：持久 `admin_permission_policy_versions` 与 `admin_emergency_grants`。每环境至多一个 ACTIVE 策略；策略版本与编译后的动作矩阵 SHA-256 不匹配即拒绝。已发布策略不可改写，只允许退休。紧急授权仅能绑定单个 workspace 的 `PAUSE_NEW_GENERATION` 或单个 ops session 的 `REVOKE_COMPROMISED_OPS_SESSION`，最长 30 分钟、设 24 小时内复核期限；scope 不可改写、证据不可删除或回退。0055 进一步阻断 INSERT 自审，并在可信同人/别名关联缺位时禁止任何记录声称“已独立复核”。迁移不自动发布任何环境策略。
- Auth/API：23 个旧 `/admin` 注册路由按规范路由映射 action；每次重查当前 principal、role grant、scope、策略版本、环境、对象、金额和时间。工单目标缺 ticket 立即拒绝；同角色多个 scope 中缺工单的 scope 不会遮蔽后续有效工单 scope。仅已完成安全投影的总览、指标、Provider 状态、限定支持摘要及 workspace 限定 Jobs 列表可在 TEST/STAGING 通过显式授权。所有旧写与其余读路由保持 403；PRODUCTION 的旧 `/admin` GET/POST 全部固定 403，独立 `/ops` 本人会话/MFA 自助不受影响。
- 紧急授权：`assessEmergencyGrant` 只评估已持久化 grant 的当前角色、具体目标、incident、有效期、策略及 `alertedAt`；退款、解锁作品、发布等动作不在封闭词表中。它**不创建授权、不发送通知、不执行止损**，因此紧急操作仍不可用。
- 支持摘要：`SUPPORT_L2` 需有效且有限期的 workspace+ticket scope，支持 grant 还需匹配当前受益 principal、workspace、ticket、`SUMMARY_READ`、ACTIVE 和未来到期时间；成功读取追加 audit log 与客户可见事件。
- 安全投影：Provider 仅返回 `PROVIDER_FAILED / RESULT_URL_EXPIRED / OTHER` 固定错误类别。Jobs 在 SQL 中先按获授权 workspace 限定、再 `LIMIT`，返回字段白名单与固定错误类别，不返回 `type/stage/input/result/error` 的自由内容。
- 安全读取切片：新增工作区限定的项目状态、存储总量和当前受益主体+工单限定的支持授权投影。项目响应不含标题/脚本，存储响应不含对象键，支持授权不含客户内容；所有 SQL 在 `LIMIT` 前按 workspace、principal、ticket 过滤，跨 scope 统一拒绝。
- SDK/UI：新增上述只读 SDK/query；`/admin` 使用独立 ops session，在提交明确 workspace/ticket 后才查询。切换 scope 立即清空上一范围数据；支持摘要需主动确认，成功读取写 audit 和客户可见 Outbox。只显示当前角色可用的读取入口，旧直写控件从本切片移除，服务端仍拒绝所有未交付写动作。`StudioShell` 仅在真实 ops session 存在时显示运营入口。
