## 样例与来源

本轮只使用 FFmpeg `lavfi` 自行生成 4 个短 MP4 与 1 个 WAV，以及本轮编写的 SVG、SRT、损坏媒体文本和长时间算术 JSON。没有扫描用户私人文件、外部下载、真人或真实市场数据。`BRIEF.md` 记录用途、预期剪辑与失败路径；`manifest.json` 记录 9 个测试输入的 SHA-256、字节数、流期望和使用边界；`generate.ps1` 记录完整的二进制生成命令。

| 输入 | `ffprobe`/文件结果 | 用途与边界 |
|---|---|---|
| `clip-a-24000-1001.mp4` | 169,837 B；H.264 320×180，CFR 24000/1001，AAC mono 48 kHz，4.000 s | 合成源片自带原声；供纯素材保留原声结构测试。 |
| `clip-b-30000-1001.mp4` | 4,588 B；H.264 320×180，CFR 30000/1001，无音轨，4.004 s | 第二段合成视频；静态 SMPTE 色条，不冒充摄影。 |
| `clip-c-60000-1001.mp4` | 42,060 B；H.264 320×180，CFR 60000/1001，无音轨，4.004 s | 第三段合成视频；可代替 **Mock** 生成产物做结构测试，不是 Provider 输出。 |
| `clip-d-synthetic-vfr.mp4` | 175,620 B；H.264 320×180，时基 1/15360、标称 30/1、平均 3600/143，119 帧，4.766667 s | 帧 PTS 差有 512 与 1024 ticks，证明此样例为可变间隔；**不是手机素材**。 |
| `independent-48k-stereo.wav` | 768,078 B；PCM s16le，48,000 Hz、双声道、4.000 s | 独立音频同步与采样时基输入。 |

纯素材、生成、混合三种模式在 `manifest.json` 有明确结构示例，后两者的 C 片只代表 Mock 输出。未运行三种模式的实际项目/编辑/导出验收，不能将样例存在等同功能交付。

## 实际命令与结果

环境：Windows PowerShell，`ffmpeg.exe` / `ffprobe.exe` 来自 `C:\ProgramData\chocolatey\bin`；FFmpeg `6.1.1-essentials_build-www.gyan.dev`。没有接触开发库或隔离测试库。

1. `Get-Command ffmpeg,ffprobe -ErrorAction SilentlyContinue`：两者存在；`ffmpeg -hide_banner -version`：6.1.1。使用 `generate.ps1` 所列的 FFmpeg 命令生成 4 个 MP4、1 个 WAV，各命令退出 0。
2. `ffprobe -v error -show_entries format=duration,size:stream=index,codec_type,codec_name,avg_frame_rate,r_frame_rate,time_base,start_pts,start_time,duration_ts,duration,sample_rate,channels -of json <file>`：上表所列流属性。对 VFR 文件额外运行 `ffprobe -v error -select_streams v:0 -show_entries frame=best_effort_timestamp -of csv=p=0 ...`，算得 `frameCount=119`、`firstPTS=512`、`lastPTS=72704`、`uniquePTSDeltas=512,1024`。
3. 对 5 个有效音视频逐一运行 `ffmpeg -nostdin -hide_banner -loglevel error -i <file> -f null NUL`：5/5 解码退出 0。
4. `ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1 packages\testing\fixtures\media-v04\invalid-container.mp4`：退出 **1**，错误含 `moov atom not found` / `Invalid data found when processing input`，符合负面期望。
5. `& .\packages\testing\fixtures\media-v04\generate.ps1 -OutputDirectory .artifacts\n00-04-repro`：全新忽略目录生成 5 个文件；逐文件 `Get-FileHash -Algorithm SHA256` 与仓库样例比较，**5/5 相同**。首次比较误把静态 `invalid-container.mp4` 也纳入生成器输出集合，因此报缺失；修正为 5 个脚本实际生成的文件后全相同。此错误属于检查命令的文件选择，不是媒体生成失败。
6. Node 读取 `manifest.json`、逐个读取 9 个测试输入并以 `crypto.createHash('sha256')` 与 `sizeBytes` 比较：`assets=9 hashAndSizeFailures=0`。`long-timeline.json` 解析后 `longSeconds=86400`。
7. PowerShell `[xml](Get-Content ...graphic-overlay.svg -Raw)` 得到 `svgRoot=svg width=320 height=180`；`ffprobe -v error -show_entries stream=codec_type,codec_name ... untrusted-caption.srt` 得到 `subrip|subtitle`、退出 0。字幕能解析为字幕流，但正文仍是不可信输入。

完整哈希见 `packages/testing/fixtures/media-v04/manifest.json`。例如 A 片为 `c86be8e7a9e1aef93adb5307a886c35a9efde7dbb1ce5be2900b52eabb3964fb`，VFR 片为 `58222257c6ac18eb3ffaeb12c01f03965731dcd51f86af0d646f5bdecff62c7c`。本轮没有运行 `pnpm verify`、数据库集成、浏览器播放、真实音画同步、上传/剪辑/Undo/Redo、Provider 或导出测试；没有 Provider 费用。

## 未满足的验收与下一动作

- **真实授权实拍：缺。** 需要明确许可、来源、授权时间与 SHA-256；不从本机私人目录擅取文件。
- **真实手机 VFR 与录屏：缺。** 合成 VFR 只证明 PTS 非均匀，不覆盖手机旋转、HDR、音频起点与设备编码；未来样本需 `ffprobe` 原始流信息。
- **合法参考视频：缺。** 本组可用合成片作自有参考结构测试，不能代表外部参考版权/获取路径。
- **真实长片：缺。** 24 小时 JSON 只覆盖整数时基，不覆盖解码、代理、缓存、播放和音画漂移。
- **用户旅程：未运行。** N00-06 的浏览器/媒体验收骨架建立后，用授权输入跑纯素材、生成、混合与恶意输入的实际正负路径；付费 Provider 无凭据时明确保留未验证。

当前仅合成样例子项有文件与探测证据，N00-04 整体保持 `IN_PROGRESS`；其依赖任务可做不受阻的准备工作，但不能据此宣称真实素材门通过。迁移/API/SDK/UI 本轮均不适用；回退只需撤销本目录新增测试文件与对应文档，不涉及数据库或业务状态。
