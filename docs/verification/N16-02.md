## 分层与实现

| 层 | 本子步 |
|---|---|
| Contracts / Migration / Domain / API / SDK | 暂不适用：尚无账号外观偏好契约及服务端读写；完整 N16-02 后续必须按该顺序补足，再接 Web。 |
| Web | `system / light / dark` 三态；系统偏好缺失回退浅色；监听系统变化；设置页可选择当前设备覆盖。覆盖按 `userId` 存储，旧无账号归属的 `ancs-qf-theme` 不继承。 |
| SSR 首屏 | 只有严格解析的 `userId.light/dark` cookie 且服务端 `/auth/session` 用户 ID 相等才采用固定外观；否则跟随系统。固定模式由 SSR body class 设置；system 模式由第一个 body 内联脚本在可见内容前设置，脚本不拼入 cookie 或本地存储文本。 |

设备覆盖 cookie 只用于 UI 外观，不含凭据。登录成功后以登录用户的本地覆盖更新 cookie；未登录或 cookie 用户与当前会话不符时首屏使用系统外观。UI 主题修改不调用作品编辑、渲染或账本接口。当前 `system` 无需在两台设备同步计算结果，实际账号偏好服务端来源仍缺失。
