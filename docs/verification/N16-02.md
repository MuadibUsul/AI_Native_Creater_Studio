## 分层实现

| 层 | 结果 |
|---|---|
| Contracts | `system / light / dark` 公共枚举、当前用户偏好 DTO 和严格 PUT 请求；客户端不能传 `userId` 替他人写入。 |
| Migration | 0052 新增 `user_appearance_preferences`，`user_id` 主键并级联关联用户，数据库 CHECK 约束三种模式。0051 是并行 N15-02 的前置迁移。 |
| Domain / API | 当前用户 GET/PUT `/api/v1/users/me/appearance`，缺行默认 `system`；Better Auth Web 会话和原生访问令牌共用认证解析。匿名 401、非法模式或越权字段 400，响应 `private, no-store`。 |
| SDK | `auth.getAppearance()`、`auth.setAppearance({mode})`，请求和响应均经公共契约校验。 |
| Web | 优先级为设备明确覆盖 → 账号偏好 → OS → 浅色。账号偏好服务端持久化，设备覆盖按 `userId` 存入 localStorage 和严格枚举 cookie；`system` 仅同步选择意图，各浏览器按自己的 OS 计算颜色。设置页区分账号默认和当前设备。偏好 API 失败时设备覆盖仍生效且可切换。 |
| SSR | 根布局用请求会话 cookie 查询当前账号偏好，只接受公共 DTO；覆盖 cookie 的用户 ID 必须与已验证账号一致。固定模式由 SSR body 设置，系统模式由可见内容前的固定脚本按 `prefers-color-scheme` 设置。脚本不拼入 cookie/localStorage 原文。匿名旧 cookie 回退系统。已登录访问 `/sign-in` 不再被 hydration 强制重置为系统。 |

主题只改 UI 语义 token/body 类，不向作品、渲染、费用或 Provider 写入主题值。Native 客户端映射归 N16-11。

### 真实会话浏览器验收

命令：指定上述**隔离 test DB**、移除当前进程 `DATABASE_URL` 后运行 `node scripts/verification/n16-02-real-session.mjs`。脚本使用真实 PostgreSQL、Fastify/Better Auth、已构建的 Next 和 Chromium；完成后关闭测试服务。复跑时生产构建的浏览器 rewrite 指向常规 API，脚本仅把浏览器 `/api/v1` 请求转发给同一隔离 Fastify 实例；SSR 由运行时 `ANCS_API_INTERNAL_URL` 直连该实例。最终运行退出 **0**：

- 同一账号两个独立浏览器上下文，OS 分别浅/深；默认 `system` 首屏分别浅/深。
- 在真实设置页把账号偏好改为 `dark`，两个会话刷新后的无 hydration JS 首屏均为深色；已登录访问 `/sign-in` 经 hydration 仍为深色。
- 一台设备设置 `light` 覆盖后，它的首屏为浅色，另一台仍为深色。
- 另一账号和未登录浏览器即使持有前账号旧 cookie，首屏仍按 `system` 为浅色；捕获 hydration 错误为 0。
- 在同一隔离库创建真实 Channel、Project 和两个各 12 秒的 Scene。主题切换前后的完整 ProjectDetail、SceneGraph、账本响应逐字段相等；导演工作台选中的第二 Scene、播放器 DOM 节点与预览模式保留。通过 Remotion 自带 `Play video` / `Pause video` 控件及直接来自 `Timeline.useTimelinePosition()` 的时间标签，实测切主题前 **2 秒**、切换后 **2 秒**、继续播放后 **3 秒**，播放位置未归零且持续前进。该控件只显示整秒，**内部逐帧 epoch 未直接读取**；项目没有 FrozenManifest，不声称验证过其 hash。

早期本地 scripted auth stub 仅用于 Web 子步；最终同步结论以上述真实会话与隔离数据库为准。未调用第三方 Provider，也未写 `ancs_dev`。Native 映射与 D0/D1 整体验收仍由后续任务完成。
