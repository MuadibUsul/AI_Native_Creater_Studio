## 实现证据

- **私有候选**（`createProposalBranch`）：候选只存**操作集 + 绑定**（`baseProjectRevision`、`selectionAnchorId` 与其指纹、`intentRevisionId`、`operationsHash = sha256(规范操作集)`），**不改工程**（不写 `edit_events`、不推进 revision）；base revision 与当前不一致 → 409 `PROPOSAL_STALE_BASE`；绑定锚点必须属于同一工程。
- **确定性试改**（`previewProposal`）：用**真实执行器**（`processEdits`）在**事务内跑完整操作集，然后无条件回滚**——不是近似动画、不是第二套模拟器；返回试改后的 revision、事件摘要与受影响片段区间，并带 `projectUntouched: true`（结构性保证：事务整体回滚）。同一操作集必得同一结果。
- **原子采用**（`adoptProposal`）：依次校验幂等键（同键重放返回原结果，不同键重放已提交候选 → 409）、候选状态（`DISCARDED`／`SUPERSEDED` 拒绝）、**操作哈希**（`PROPOSAL_HASH_MISMATCH`，防止"采用与用户看到的不一致"）、**选择指纹**（候选绑定锚点时比对创建时指纹与锚点当前指纹，`PROPOSAL_FINGERPRINT_MISMATCH`）、**base revision**（`PROPOSAL_STALE_BASE`），全部通过后经**统一编辑协议**原子执行并标记 `COMMITTED`；执行失败（如目标被锁 → `EDIT_IMPACT_LOCKED`）时候选保持 `OPEN`、**没有任何部分写入**、不返回"已采用"。
- **丢弃与取代**：`discardProposal` 幂等（已丢弃再丢弃返回同一状态，已提交不可丢）；`supersedeProposals` 把同一意图下的其他 OPEN 候选标为 `SUPERSEDED`（晚到结果不得更新新候选）。
- **API／SDK**：`POST/GET .../proposals[/:id[/preview|/adopt|/discard]]` 五个端点与对应 SDK 方法。
