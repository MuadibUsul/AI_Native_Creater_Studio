# N01-09｜工程 API、SDK 与事件契约

日期：2026-10-09。状态：**VERIFIED**。依赖 N01-08 已 VERIFIED。

## UI 交付卡

- **用户目标 / 角色 / 空间：** Web、后续 Native 客户端和自动化工具从同一后端读取完整工程、锁和正式编辑历史，并通过同一编辑入口安全写入。
- **入口 / 对象 / 范围：** 新增 `GET /projects/:projectId/state` 与 `GET /projects/:projectId/edit-events`；扩展 `POST /projects/:projectId/edits` 的 schema 协商；SDK 增加 `projects.state`、`projects.editEvents`。
- **主流程 / 恢复：** 鉴权和项目归属 → schema 版本检查 → 服务端组装 ProjectDocument／锁／事件 → 契约解析 → SDK 再解析。事件按单调 `seq` 游标增量读取。
- **权限 / 费用 / 锁定：** 读取要求 `project:read`，编辑沿用 `project:write`；跨租户按抗枚举约定返回 404。无 Provider 调用和费用。
- **设计覆盖：** UI 不适用。本任务交付公共数据边界；现有 Web 页面无需新增入口。后续 Studio/Native 使用同一 SDK，不建立前端副本权威。
- **真实业务 / 证据：** 真实 Better Auth、Fastify、PostgreSQL 和 SDK 往返覆盖成功、幂等、权限、未知 schema、旧写兼容及 OpenAPI 路径。

## 实现

- `ProjectState` 返回 `schemaVersion: 1.0`、完整 ProjectDocument、带维度 ObjectLock 和当前 EditEvent 水位线。
- `ProjectEditEventPage` 返回带 `seq`、对象引用、补偿链和完整 patch 的正式 EditEvent；`afterSeq + limit` 上限 200，使用 `limit + 1` 判定下一游标。
- `EditRequest.schemaVersion` 对旧客户端保持可省略；显式未知版本返回 409 `CAPABILITY_UNAVAILABLE`，reason 为 `PROJECT_SCHEMA_UNSUPPORTED`，并列出支持版本。
- API 先按 projectId 找 workspace，再走统一 workspace capability；Domain 查询仍同时携带 workspaceId/projectId。
- SDK 对状态和事件响应再次执行共享 Zod 契约；OpenAPI 由真实 Fastify 路由 schema 自动生成。
- 旧 `/graph`、`/scenes`、版本及编辑入口保留。实测旧 Scene 写入后规范化 Clip 和 AssetVersion 引用逐字保持。

## 限制与回滚

- EditEvent 是创作历史，不替代安全 Audit Log；事件读取只给有项目读取权限的成员。
- `schemaVersion` 当前只支持 `1.0`；未来版本必须新增显式兼容／迁移，不得静默降级。
- 回滚不涉及数据库迁移；删除两个 GET 路由、SDK 方法和可选请求字段即可，既有 `/graph` 与编辑协议仍可工作。
