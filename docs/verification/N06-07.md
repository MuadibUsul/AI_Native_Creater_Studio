## 验收路径覆盖

1. **连续三轮修改后早先认可的内容仍引用相同资产与参数**：采集"开场"片段的三轴指纹后，对**别的片段**连做三轮修改 → `checkConfirmedContent` 报 `UNCHANGED`、`intact=true`、`diffs=[]`。已测。
2. **意外移位阻止自动采用**：候选只对片段 A 做 `ripple_clip DELETE`，片段 B 会被**附带**左移；B 受保护且非本批显式目标 → 采用 409 `CONFIRMED_CONTENT_REGRESSION`（`violations` 指明 B），**工程 revision 与事件数不变**，候选保持 OPEN。已测。
3. **显式目标不算范围外**：候选显式改受保护片段 → 采用成功；核对报告如实给出该对象变化并标 `explicitTarget=true`、`outOfScope=[]`。已测。
4. **不支持的保护类型 fail-closed**：保护字幕对象 → 501 `CONTENT_PROTECTION_UNSUPPORTED_KIND`（本项仅支持 CLIP，见缺口）。已测。
5. **“其他别动”范围守卫（契约 + 单测）**：`resolveScopeGuard` 对"未声明约束/等长 → SAFE"、"变长且无等长替代 → EXPLAIN_DURATION_CHANGE"、"变长但有等长替代 → EQUAL_LENGTH_PLAN_RECOMMENDED"给出确定判定。**已测判定，未接规划器（见缺口）。**

## 关键实现要点（易错）

- 保护门必须比对 **试改后状态**（试跑在同一事务内跑完、回滚前采集的三轴指纹），**不是当前已提交状态**——附带移位发生在试改之后，用已提交状态会永远检测不到（本项开发中先踩到，已修）。
- 采用路径**只在传了 `protectionIds` 时**才多跑一次试改核对；不传则零额外开销、行为与之前一致。

## 失败与剩余缺口（为何不是 VERIFIED）

1. **"其他别动 + 总时长改变 → 先解释或改等长方案"只到契约层**：`resolveScopeGuard` 有权威判定与单测，但**尚未接到规划器**（`planRangeEdit` 产出计划时计算总时长变化并回带判定/等长替代）。属"接口存在 ≠ 功能交付"，故本项不计完成。
2. **保护范围仅 CLIP**（视频与音频片段；"声音"以音频片段承载）。**字幕/音频区域/视觉对象**的保护属后续增量（当前显式 501 fail-closed，不静默放过）。
3. 无 UI；保护记录的呈现属后续交付面。
4. 无 Provider 依赖、无费用。
