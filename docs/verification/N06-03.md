## N06-03 验收路径覆盖

1. **记录字段读写集与依赖版本**：创建候选时写入 `read_set`/`write_set`（操作注册表声明的并集）与 `write_targets`（对象 + 维度 + 来源操作下标），以及候选引用片段的源素材绑定签名。
2. **两端改不同片段可受控合并**：候选改片段 A，干预编辑改片段 B → 影响集 `conflicts=[]`、`rebaseable=true` → `rebase` 推进 base revision（`rebased=true`，`rebaseCount=1`）→ 采用成功且结果与试改一致。rebase 只改候选行，不动工程 revision/事件。
3. **改同对象同维度 409**：候选与干预编辑都 `trim_clip` 同一片段 → `conflicts` 含 `(CLIP, clipId, DURATION/POSITION/…)` → `rebase` 409 `PROPOSAL_REBASE_CONFLICT`；候选 base 保持旧 revision，`adopt` 仍 409 `PROPOSAL_STALE_BASE`；工程 revision/事件数不变。
4. **同对象不同维度可共存**：候选 `set_clip_opacity`（STYLE），干预编辑 `trim_clip`（CONTENT/POSITION/DURATION）→ 无维度相交 → `rebaseable=true` → rebase + 采用均成功。
5. **间接影响可检测（重排/涟漪）**：干预编辑对片段 A 做 `ripple_clip DELETE` → 片段 B 被整体左移（B 只是**间接**受影响）→ 事件流为 B 落 `UPDATE_CLIP` → 影响集把 B 计入 `interveningChanges` 并产生冲突、拒绝 rebase。契约层另有 `reorder_scenes` 展开为「每个 Scene × POSITION」的单测。
6. **不能以最新 revision 强覆盖**：冲突场景下 `rebase` 拒绝且不写库，`adopt` 依旧拒绝（`baseProjectRevision` 未被动过）。
7. **源素材变化触发重新审核**：直接换源（不经编辑协议、工程 revision 不变）→ `assetChanged=true`、`blockReasons=[ASSET_CHANGED]` → `rebase` 409 `PROPOSAL_REVIEW_REQUIRED`。
8. **身份变化触发重新审核**：绑定锚点保存新修订（指纹变化）→ `identityChanged=true` → `rebase` 409 `PROPOSAL_REVIEW_REQUIRED`。
9. **幂等**：已在最新 revision 时 `rebase` 为幂等空操作（`rebased=false`，不写库、不推进计数）。

> **保守性说明（有意为之）：** 从 `edit_events.patch` 无法还原改动形状时（例如涟漪位移邻居落的是 `update_clip` 但 patch 无 `changes`），影响集按**对象级全维度**计 Conflicts —— 宁可多报冲突（要求重新审核）也不漏报（否则陈旧候选会被静默 rebase）。

## 失败与剩余缺口

- 影响集在**场景（Scene）级**操作上依赖事件负载还原：`insert_scene`/`duplicate_scene` 无显式创建 id 时无法定位新对象，按对象级保守处理；本项候选实际使用片段/轨道/字幕原语，已覆盖。
- 干预改动的维度还原依赖 `edit_events.patch` 形状；涟漪位移邻居事件无 `changes` 时降级为全维度（见上）。
- rebase 之后的试片缓存按新 base revision 自然失效并清理旧行；跨实例缓存策略仍属 N06-04 未完成项。
- 无 Provider 依赖、无费用。
