- **本次修复/发现的工程问题（诚实记录）**：
  1. **时长来源**：Director 插入的 CHAPTER_TITLE（无旁白）使快照时间轴 > Narration 实际时长（本例 35.0s vs 30.8s）——spec 取较大者并**明确告警**；After-Alignment 重定时未实现（TODO：依赖编辑协议批量 update_scene）——成片尾部为场景延续，音频不被截断。
  2. **Remotion Composition 化的类型陷阱**：`calculateMetadata` 要求 props 类型可赋给 `Record<string, unknown>`——**interface 无隐式索引签名**，必须用 type alias（FinalCompositionProps 已注明）。
  3. **Node 类型剥离的导入扩展名**：Node 直跑 `.ts` 不重映射 `./x.js` → `x.ts`（CLI 首跑 ERR_MODULE_NOT_FOUND）——run-render.ts 显式 `'./executor.ts'` + tsconfig `allowImportingTsExtensions`（与 motion-worker 同一约定）。
  4. **素材同源服务**：组件不访问网络/凭据的落地方式——编排层把冻结对象落工作目录，执行器复制进 bundle 静态目录（`/assets/<fileName>`，Remotion 本地静态服务器直接服务 bundle 目录），组件仅消费相对 URL。
  5. **跨文件测试干扰（已修复）**：createRender 改为同事务入队 RENDER_FINAL 后，`results-http.integration.test.ts`（无 beforeEach 清理 + `claimJob` 未限定类型）会误认领其他文件遗留的 QUEUED 渲染任务，导致 "QUEUED → PROVIDER_QUEUED 非法迁移" 间歇失败（集成套件共享同一测试库、按文件串行）。修复：该文件补 `beforeEach` 清理（与其余集成套件同一约定）+ 认领限定 `types: [NOOP_JOB_TYPE]`；`render.integration.test.ts` 同样补 `beforeEach` 清理（其创建渲染会留下 QUEUED 任务）。修复后集成套件独立运行 **221/221 全绿**；**教训**：共享库的测试必须自清理且认领必须限定类型——历史文件依赖"库中无他人数据"是隐性耦合。
