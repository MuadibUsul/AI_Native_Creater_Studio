## 验收路径覆盖

1. **时间选择指向正确对象**：`clipsInTemporalSelection` 对 `POINT` 用半开区间 `[start,end)` 判定（边界时刻**不**命中）；对 `RANGES` 区分**完整覆盖**与**部分相交**。已测（含"3s 恰为结束边界 → 不命中"这一易错点）。
2. **多区间不合并**：显式 `[0,3s]` 与 `[5s,6s]` 两段分别判定，跨区间片段只标"部分相交"，不被合并成整段。已测。
3. **轨道作用域**：可按 `trackIds` 限定（"这里的音乐"这类意图可先按音频轨收窄）。已测。
4. **渲染与投影一致（不各算一套几何）**：jsdom 断言"投影的 `visibleClipIds` 与组件实际渲染的片段一致"、像素宽/左偏移与有理时基换算一致（1s=100px → clip_a 300px、clip_b 左 400px）。已测。
5. **窗外与脏数据如实回报**：窗外片段不进渲染但列入 `outsideViewportClipIds`（调用方可提示"还有内容"）；引用不存在轨道的片段列入 `orphanClipIds`，不静默丢弃。已测。

## 失败与剩余缺口（为何不是 VERIFIED）

1. **逐帧步进**：契约已有 `mediaTimeToFrameIndex`/`frameIndexToMediaTime` 与帧吸附，但**没有逐帧步进的 UI/键位**，也没有"分数帧率显示不丢帧"的用例（29.97/23.976 的显示与步进）。
2. **源/序列双时间码**：组件只有一个 `formatTime`；"同时显示源时间与序列时间"未做。
3. **说话句段与音乐 region 的语义指向**：投影已支持 CAPTION/AUDIO 车道，但把"这句话""这里的音乐"解析到 `CAPTION` / `AUDIO_REGION` 目标**未做**（需接字幕词条与音频区域，属 N03-07/N03-06 的既有数据 + N04-09 锚点）。
4. **空间 × 时间选择在应用层的组合**：`composeSelectionAnchor`（N04-02-s1/N04-09-s1）可用，但项目页未把"画布点选 + 时间带选段"组装并持久化。
5. **真实浏览器高 DPI 目检**（N04-01）未做。
6. 无 Provider 依赖、无费用。
