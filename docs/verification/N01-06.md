# N01-06｜操作注册表与候选状态校验

日期：2026-10-08。状态：**VERIFIED**。依赖 N01-04 已 VERIFIED。

## UI 交付卡

- **用户目标 / 角色 / 空间：** 创作者从 Web 或 AI 提交一批编辑时，系统必须先理解整批操作的真实顺序；前一步创建的对象可被后一步引用，任一步无效则整批不改变项目。
- **入口 / 对象 / 范围：** 入口仍是现有 `POST /projects/:projectId/edits`、Web Lite Timeline 和 AI 修改应用；对象为当前 14 类 EditOperation。没有新增页面或临时设置。
- **主流程 / 恢复：** 契约解析 → 注册表能力/角色/后端检查 → 候选状态顺序模拟 → revision/锁/引用的事务内复核 → 状态、EditEvent、Outbox 一次提交。失败保留原项目，无需额外恢复。
- **权限 / 费用 / 锁定：** 注册表声明 `project:write`、USER/AI/SYSTEM、读写集、锁与 revision 前置条件。现有 API 继续在执行器前强制 `project:write`。编辑本身不调用 Provider、不产生费用。
- **设计覆盖：** 沿用现有 Web/AI 编辑交互；本任务是统一执行语义，不新增用户可见控制。N04/N06 后续用同一注册表扩展交互和候选分支。
- **业务 / 测试：** Web 与 AI 都提交同一 EditRequest 并进入 `processEdits`。真实 PostgreSQL 验证批内创建后引用、失败零落库、事件与 revision；全量 Web/API/Undo/Render 回归通过。

## 实现

- `EDIT_OPERATION_REGISTRY` 对全部 14 种操作逐项声明：availability、计划阶段、权限、允许 actor、执行后端、结构性标识、read/write set、前置/后置条件、失效范围和补偿模式。
- `requireEditOperationDefinition` fail closed：未登记、未实现、actor 不允许或后端不支持均在执行前拒绝。原有三个未实现操作继续返回 501，并保留既有计划阶段兼容信息。
- `validateEditOperationCandidate` 在落库前对整批操作顺序模拟；支持创建、更新、删除、拆分、复制、解锁再编辑及重排后的候选引用。相同模拟在事务外快速执行一次，并在锁定 Project 行后对权威数据再执行一次。
- `insert_scene.createdSceneId`、`duplicate_scene.createdSceneId`、`split_scene.createdTailSceneId` 提供正式批内对象标识；与服务端补偿字段互斥。后续操作可引用这些 ID。
- 新 Scene 在候选内继续编辑时不要求不存在的旧 revision；最终只插入一次最终状态。已有 Scene 仍执行一次 expected revision 校验和条件更新。
- AI 引用校验按操作顺序维护已知 ID：创建后可引用，删除后不能再引用。Web 与 AI 的最终应用仍走同一个 `processEdits`，没有第二套执行器。
- `restore_project_version` 当前要求独占批次，因为其候选 Scene 集来自版本快照；避免在未加载快照时推测后续引用。
