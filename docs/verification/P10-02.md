- **验收条款对照**：
  1. **"未授权不提交"** → Consent（声明版本 + 文本哈希 + 主体类型 SELF/AUTHORIZED_OTHER）是提交前置硬门槛，
     且测试断言"422 时 Provider **零调用**"——不是"提交后失败"，而是**根本不发出请求**。
  2. **"训练失败可恢复"** → FAILED 带 `retryable` 标记；`retry` 仅在该状态下允许，样本与 Consent 全保留，
     重试成功 → READY（测试覆盖完整序列）。
  3. **"退休、平台解绑、Provider 删除可区分"** → `retiredAt`（本地，Provider 保留）/ `unlinkedAt`（断开关联，
     Provider 保留）/ `providerDeletedAt`（Provider 侧真实删除，不可恢复）——三个独立时间戳 + 三个状态 +
     Provider deleteVoice 调用记录；测试断言三者互不相同且 Provider 删除前零 deleteVoice 调用。
  4. **"录音/上传、音质检测、Consent、Provider 验证、Instant/Professional 状态"** → 上传经资产链路（录音/上传同一
     路径）；音质四项指标全实现（噪声=静音比/RMS、削波、时长、有效语音比）；Consent 独立表；Provider 验证 = 
     训练状态机（SUBMITTED/TRAINING/READY/FAILED）+ 绑定；两档行为差异（Instant 立即 READY；Professional 
     提交-轮询-可重试）。
  5. **§14.3 字段不得混同** → 样本（表+资产引用）/ 授权（表）/ provider_voice_id / retention policy /
     ownership metadata 各自独立列，集成测试逐列断言。
- **本次修复/发现的工程问题（诚实记录）**：
  1. **二进制解析器 1MiB 上限（真实缺陷）**：Fastify 通配解析器默认 bodyLimit 1MiB——>1MB 的 WAV 上传被误
     413（先于存储端点的按意图上限校验）。修正：存储端点 bodyLimit=本地上限（64MB）、文档导入 =
     25MB；413 由业务路由给出明确信封。
  2. 夹具教训：伪 mp3 若**声明为 audio/wav** 会在上传入口被 MIME 嗅探拒绝（先于质量检测）——修正为
     ID3 头 + `audio/mpeg` 声明，真正走到"格式不支持质量检测"的 422 分支。
