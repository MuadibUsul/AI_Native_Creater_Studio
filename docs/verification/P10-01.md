- **验收条款对照**：
  1. **"Markdown、PDF、DOCX 和 Newsletter 内容导入，保留表格与出处"** → 四类全部交付：表格 = ContentBlock
     `table{columns,rows}`（MD/DOCX/EML-HTML 均保留）；出处 = project_sources（urn+sha256+filename+snapshotKind），
     链接逐条记录 URL。
  2. **"错误文件…有明确处理"** → 损坏 PDF/DOCX → 422 DOCUMENT_PARSE_FAILED（带 parseReason）；加密 → 422
     DOCUMENT_ENCRYPTED；不支持类型 → 415；空文件 → 400；超大 → 413——**无一静默降级**。
  3. **"扫描 PDF…有明确处理"** → 无文本层 PDF → **422 SCANNED_PDF_NO_TEXT**（明确说明需 OCR，本系统不伪造）；
     部分缺页 → pagesWithoutText + 逐页警告（页号 1 基）。
  4. **"嵌入对象有明确处理"** → DOCX 图片/对象/脚注/批注/超链接、PDF 页面图片、EML 附件——逐条
     normalization.notes（≤200 字），**不静默丢弃**。
  5. **"不伪造提取成功"** → 空结果 → 422 EMPTY_CONTENT；扫描件 → 422；解析异常 → 422——成功响应必有真实抽取内容。
- **本次修复/发现的工程问题（诚实记录）**：
  1. **SDK Headers 展开陷阱（重要）**：`{ ...buildHeaders(false) }` 对 `Headers` 实例展开得到空对象——
     二进制请求将丢失会话 Cookie/x-client 头（集成测试以 401 暴露）。修正为 `headers.set(...)` 并注释原因。
  2. **EML 部件编码头读取错误**：首版从 content-type 值中解析 content-transfer-encoding（应取部件头映射中的
     独立头）——单测（quoted-printable 未解码）暴露并修正。
  3. **Markdown 内嵌 HTML 泄漏**：首版只拦截"整行单标签"，`<div>文本</div>` 会把标签带进正文——修正为
     检测行内标签 → 警告 + 去标签保留文本。
  4. **Windows/BodyInit 类型差异**：`Uint8Array` 在 DOM 与 Node 的 BodyInit 定义下不完全兼容（sdk 无 DOM lib、
     web 有）——用 `NonNullable<Parameters<typeof doFetch>[1]>['body']` 精确取型，两处 tsconfig 均通过。
