- **验收条款对照**：
  1. **"每个事实图表可追溯"** → 通过（双向断言）：Claim→Citation（**块 ID + 字符区间** + 引文）→Source（url/contentHash）链条在测试中逐环校验；Dataset→sourceIds→Source 且在图表绑定校验中**返回必须写入 Scene 的 data_source_ids**（§10.3 的图表字段要求）；引用不属于本项目的来源 → 422 SOURCE_NOT_IN_PROJECT（不得伪造来源）。
  2. **"缺数据不会自动生成虚构数列"** → 通过（四道闸门）：① 无数据集时**降级阶梯**（QUOTE/SOURCE_CARD/TEXTUAL_EXPLANATION/REQUEST_DATA，绝不生成图表数据）；② `synthetic` 数据集**永不可绑定**事实图表（422 SYNTHETIC_DATASET_NOT_BINDABLE）；③ 无来源数据集拒绝创建（422 DATASET_REQUIRES_SOURCE）；④ 空数据集拒绝创建与绑定（422 DATASET_EMPTY）。
  3. **Claim 建模（REQ-7-02）** → 通过：factuality 四类、sourceIds/structuredData、锁定标记；**fact 类必须 ≥1 来源**（手动与抽取两条路径都强制；无来源输入的 fact 自动降级 uncertain 并提示）。
  4. **表格与单位模型** → 通过：表格块（P04-01）→ 数值提及与单位归一（保留 rawUnit/raw/offset 以便复核）；时间线（年份/季度/日期）。
  5. **REQ-56-01（不得伪造来源）** → 通过：来源必须属于该项目；Claim 的来源链可解析（URL/title/publisher/author/publishedAt/contentHash 结构化保存）。
- **本次修复的工程问题（诚实记录）**：
  1. **契约严格度与"明确原因"冲突**：请求侧沿用记录侧 schema（sourceIds min(1)/points min(1)）会让"空来源/空数据"变成 400 契约错误，掩盖业务语义——请求侧放宽、服务层给出 **422 + 原因**（与 P04-01 的明确失败风格一致）。
  2. **块 ID 前缀含连字符**：`blk_<docId片段>_<digest>` 的片段来自 UUID（含 `-`），既不利于断言也不整洁——前缀清洗为十六进制。
  3. **中文短句阈值**：句子切分的最小长度 6 会丢掉"第一句。"这类 4 字中文有效句——降为 4（英文短句仍可能被过滤，属可接受启发式）。
  4. **占位代码清理**：抽取服务里误留的占位插入语句已删除（诚实记录，避免留下"看起来在做某事"的死代码）。
