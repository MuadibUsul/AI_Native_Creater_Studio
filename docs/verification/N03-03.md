## 实现证据

- **契约（5 个新规范原语）**：`packages/contracts/src/composition-edits.ts` 新增
  - `slipClipOperationSchema`（`clipId` + `sourceRange`，位置不变只滑移素材内容）；
  - `slideClipOperationSchema`（`clipId` + 非零 `offset`，总时长由左右邻居伸缩吸收）；
  - `rollClipOperationSchema`（`leftClipId`／`rightClipId` 必须不同 + 新剪辑点 `at`）；
  - `rippleClipOperationSchema`（`action = DELETE｜TRIM_HEAD｜TRIM_TAIL`，`amount` 与动作严格配对，`closeAcrossTracks` 默认 true）——**唯一**会移动其他片段的原语；
  - `splitAvCutOperationSchema`（`videoClipId`／`audioClipId`／`at`／正 `offset`／`kind = J｜L`）。
  `EDIT_OPERATION_TYPES` 25→30；v2 覆盖层 `slip_clip` 由 COMPILED_ALIAS 提升为 NATIVE，新增 `slide_clip`／`roll_clip`／`ripple_clip`／`split_av_cut`（来源操作 34→38），域编译器删掉 slip 别名死分支。
- **事务执行器**（`packages/domain/src/edits.ts`）：
  - `slip_clip`：源时长必须等于片段序列时长（`SLIP_DURATION_MISMATCH` 422）、源可用性（READY/校验和/越界）；AV 关联片段按**同一源滑移量**同步（`AV_LINK_DURATION_MISMATCH` 409、`HANDLE_UNAVAILABLE` 422）。
  - `slide_clip`：左右必须都有相邻片段（`SLIDE_REQUIRES_ADJACENT_NEIGHBORS` 422）、邻居必须 1:1 映射（`SLIDE_UNSUPPORTED_MAPPING` 422）；被滑片段只改位置，**邻居内容在时间线上保持不动**（前段源出点外扩、后段源入点前推），handle 不足即 `HANDLE_UNAVAILABLE` 422；AV 关联片段按同一位移移动，若在自身轨道重叠则 409 `CLIP_OVERLAP`。
  - `roll_clip`：两段必须同轨且相邻（`ROLL_REQUIRES_ADJACENT_CLIPS` 422）、剪辑点必须落在合成跨度内（`ROLL_POINT_OUTSIDE_SPAN` 422）、左右源入出点同步移动（handle 不足 → 422）；合成时长守恒。
  - `ripple_clip`：**显式**收缝。`DELETE` 删除片段（连同 AV 关联片段）并把起点晚于缝隙的片段左移；`TRIM_HEAD` 推进源入点、`TRIM_TAIL` 回收源出点，两者都停在原位并把后续片段左移（`RIPPLE_AMOUNT_OUT_OF_RANGE` 422）；`closeAcrossTracks=false` 且存在 AV 关联 → 409 `AV_SYNC_REQUIRES_CROSS_TRACK_RIPPLE`（不静默破坏声画同步）；每个被平移片段单独落 `UPDATE_CLIP`（patch 带 `ripple: true` 与 before/after）→ **位置变化对用户可见、可撤销**。
  - `split_av_cut`：必须 AV 关联（`CLIPS_NOT_AV_LINKED` 422）、两个切点都要在各自片段内部（`CUT_POINT_OUTSIDE_CLIP` 422）、1:1 映射；J = 音频切点早于视频、L = 晚于视频，音频**不换源**只是被切成连续两段 → 切换处原音连续。切分逻辑与 N03-02 共用新的 `splitClipRow` 助手（N03-02 的 `split_clip` 已改为调用它，无行为变化）。
- **影响面/undo-redo**：五个操作登记 `operationImpacts` 与候选模拟分支；undo/redo 按操作名事件反演（`SLIP_CLIP`／`SLIDE_CLIP`／`ROLL_CLIP`／`RIPPLE_CLIP`／`SPLIT_AV_CUT`），涟漪删除的逆操作按原 id/原范围重建片段，被平移片段由各自事件回位。

## 发现并修复的真实缺陷（本项测试抓出）

1. **涟漪 TRIM_TAIL 的源出点算成了负数**：源出点被写成 `源起点 − 收缝量`，在源起点为 0 的片段上产生空/负区间 → ZodError → HTTP 500（测试报 "Internal server error"）。修复为 `源起点 + 源时长 − 收缝量`。
2. **涟漪 TRIM_HEAD 会留下缺口并让后续片段反压**：掐头后片段自身没有左移（仍在原位起点的右侧），后续片段却已左移 → 时间线重叠。统一为"片段停在原位、时长缩短收缝量；掐头改源入点、去尾改源出点"。
3. **slide 的邻居语义写反**：后段邻居的源入点被反向平移，且出点被重算成"新入点 + 原时长"（把邻居的素材内容推着走）。修正为"内容在时间线上不动"：前段源出点外扩、后段只推进源入点（出点不变），处理性错误由测试的输出（`srcTo` 2500 vs 2000）暴露。
4. **slip 的 AV 同步量取错**：用"新源时长 − 原源起点"当滑移量，正确应为"新源入点 − 原源入点"（音频同步滑移量差了 1s）。
5. **roll 的 undo 取错锚点**：右段事件的逆操作使用了右段自己的出点（合成跨度外沿）→ 撤销时 `ROLL_POINT_OUTSIDE_SPAN`；改为按"左段用 before.end、右段用 before.start"取原剪辑点。
