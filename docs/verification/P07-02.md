- **本次修复/发现的工程问题（诚实记录）**：
  1. **类型检查的 strict 取舍**：生成代码是纯 JS（无 JSDoc），`strict` 下"参数隐式 any"会误杀一切组件 → 采 `checkJs` + `strict:false`（仍检出未定义标识符/arity/显式类型不符）；README 化于决策 0008。
  2. **Node 直跑扩展名**：`sandbox.ts` 引用 `./analysis.js` 在 vitest 下可解析、在 Node 直跑（CLI 链）下 ERR_MODULE_NOT_FOUND → 改 `./analysis.ts`（与 P07-01 的 CLI 约定一致）；该差异只在"Node 直接运行 TS"时暴露。
  3. **版本 DTO 的 projectId 来源**：版本行不含 projectId 列（经组件可达）→ 读取面由组件行传入（避免从 input JSON 猜字段）。
  4. **domain 不得 import providers**（arch R3 全量依赖生效）：domain 单测不能引用 mock-llm 的草稿常量 → 测试内联样例代码；mock 常量仅由 motion/integration 套件消费。
