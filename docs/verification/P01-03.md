- **验收条款对照**："A 租户不能读写 B 的 Project、Asset、Job 或事件"：
  1. **机制**：所有 workspace 范围请求必须经过唯一授权入口 `requireWorkspace`（认证→成员资格→能力）；不存在"按资源 id 直查后返回"的路径（REQ-31-02）。
  2. **现有点位验证**：Workspace 详情/改名/成员列表/添加成员/改角色/移除成员——跨租户访问全部 **404**（与不存在不可区分，抗枚举）；列表仅含自身参与的租户；VIEWER 写操作 403；撤销成员后立即 404。
  3. **待扩充义务（明确记录）**：Project/Asset/Job/事件（SSE）尚不存在（P02 起落地）；其跨租户用例必须按同一模式加入 `test:security`（见交接"下一项任务"与 REQ-51-06 状态）。
- **次序约定（已固化并被测试锁定）**：请求体校验先于认证（未认证 + 非法请求体 → 400，不涉及数据访问）；认证先于授权（401 先于 403/404）。
- **本次修复的工程问题（诚实记录）**：
  1. **共享数据库套件的并行干扰**：integration/security 内的多个测试文件并行运行且各自清理 user/workspace 表，导致互相删数据（表现为偶发 401/套件级失败）。修复：两个项目设 `fileParallelism: false`（按文件串行）；配置注释说明原因。
  2. **OWNER 不变量并发洞**：原实现"先计数后写入"在并发下可能双降级为零 OWNER。修复：角色变更/移除在锁定 Workspace 行的事务内重读与计数，并新增并发测试（两名 OWNER 互降：恰一个成功，租户恒有 OWNER）。
  3. **secrets:check 再次立功**：新增测试假密钥在提交前即被拦截（P01-02 的扫描修复生效），按可审计标记豁免。
