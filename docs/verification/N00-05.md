# N00-05 功能差项、发布门与开关：验证记录

## 交付内容

- `docs/requirements/v04-professional-capability-coverage.md` 按 ANCS v0.4 / Web 维护 18 个专业能力域、实现任务、限制、所需证据及 G0—G4/D0/D1 发布门。竞品官方文档只用于差项对照，不算 ANCS 能力证据。
- contracts 新增五个稳定工作区能力键、G0—G4、平台、能力等级、有效状态和固定拒绝原因；更新请求严格限制为 `{ enabled: boolean }`。
- 迁移 `0056_motionless_red_shift.sql` 新增 `workspace_feature_preferences`，每工作区、能力键唯一，仅保存用户意向和审计主体，不删除旧项目或媒体。
- domain 维护服务端能力注册表和发布门。当前五个发布门都如实为未通过：未选择为 `OFF`，用户选择但门未通过为 `READ_ONLY`，只有服务端发布门通过后才可能为 `ENABLED`。`assertWorkspaceFeatureWriteAllowed` 为后续真实写入和报价入口提供统一拒绝点。
- API 新增 `GET /workspaces/:id/features` 与 `PUT /workspaces/:id/features/:featureKey`；SDK 新增 `workspaces.features` 与 `workspaces.setFeature`。读使用 `workspace:read`，写使用 `workspace:update`，跨租户统一 404。
- Web 的工作区设置新增“新能力”入口，展示五个能力、平台、最低等级、发布门和实际状态。选中尚未开放的能力显示“等待发布门”，不会误报已经启用，也不会触发生成、费用或项目改写。

## 证据边界与回滚

- 本任务验证的是差项账本、发布门模型和工作区意向开关。五个 G 门当前仍未通过，18 个专业能力仍需由对应 N 任务提交底层执行、直接控制、预览、撤销和导出证据。
- 浏览器脚本使用受控 API fixture 验证 UI 状态；权限、持久化、跨租户和旧项目可读使用真实 API、domain 与隔离 PostgreSQL 验证。没有 Provider 调用或费用。
- 后续 v0.4 写入和报价入口必须调用 `assertWorkspaceFeatureWriteAllowed`，不能只依赖前端隐藏或读取偏好。N15-30 负责生产平台开关、审批、灰度、观察与回滚。
- 回滚时保持服务端注册表的发布门为阻塞并隐藏入口即可；迁移表和已选偏好可保留。回滚不得删除项目、媒体、版本或授权记录。
