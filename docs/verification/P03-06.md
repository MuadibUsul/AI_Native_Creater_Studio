- **implementationSummary**：

  3. **领域服务**（`results.ts`）：
     - **Webhook 验签**：HMAC-SHA256（ts.body）+ 时间窗 ±5 分钟；缺头/伪造/超窗 → 拒绝且**不写事件行、不改任务状态**（AC-08）；
     - **replay 防护**：唯一键插入失败 → 幂等 ack（DUPLICATE），不重复下载/不改账（AC-08）；
     - **迟到/乱序**：`attempt < 当前 attempt` → 事件标 STALE_ATTEMPT_IGNORED，**不回收、不改任务**（AC-05）；
     - **未知 providerJobId**：只登记事件（供人工排查），**不据回调创建任务或改任何任务**；
     - **回收链路**（`collectProviderResult`）：下载（大小上限/超时，HTTP 实现）→ **校验**（声明大小 / 魔术字节嗅探 / SHA-256）→ **写入自有存储**（§26 布局）→ 落 Asset（READY，PROVIDER_GENERATED/SYSTEM_RENDER，PROVIDER_TERMS 授权）→ 任务 SUCCEEDED → 生成记录 SUCCEEDED → **结算（settleHold）** → 发 `asset.ready` 事件；
     - **下载失败不重生成（AC-09）**：失败只 `collectAttempts+1` + lastError + `provider.result.collect_failed` 事件，状态保持 PENDING（可再回收），**submitState 不变、不产生新的付费提交**；校验类失败（大小/嗅探/校验和）标记 `retryable=false`（占位/伪造结果不反复重试）；
     - **过期预警**：`runResultExpirySweep`——临近过期（默认 15 分钟）发 `provider.result.expiring`；已过期 → 状态 EXPIRED + 任务 `needs_reconciliation=true`（**不自动重复付费**，§5.6）+ `provider.result.expired` 事件；
     - 轮询补偿/人工恢复共用入口：`registerProviderResultDescriptors` + `collectProviderResult`（与回调同一 state 行、同一状态迁移服务）。
  4. **API**：`POST /api/v1/providers/:providerId/webhooks`（公开端点，仅凭验签信任；原始体保留用于验签；验签失败 401 统一信封；重复 200 DUPLICATE）；`POST /workspaces/:id/jobs/:jobId/collect`（**generation:run**，人工恢复）；启动装配 `ANCS_WEBHOOK_SECRETS='provider:secret,…'`（无验签器的 Provider 一律拒绝，fail-closed）。

- **验收条款对照**：
  1. **"下载失败不重生成"（AC-09）** → 通过：首次下载失败 → 失败可重试标记、状态保持 PENDING、`collectAttempts=1`、任务仍 RUNNING、**attempt 与 submitState 不变**（无重新提交）；URL 恢复后**只重试回收**即成功。
  2. **"Provider URL 失效后已完成资产仍可用"（AC-10 / §75-5）** → 通过：回收成功后再把该 URL 置为不可用，资产内容仍可从**自有存储**读回（字节逐一相等）。
  3. **Webhook 验证（REQ-33-04 / AC-08）** → 通过：签名/时间窗/replay 三重防护，伪造与重放均不产生副作用；HTTP 端点级亦有断言（401 统一信封）。
  4. **结果校验** → 通过：声明大小不符 / 文本冒充 PNG（嗅探）/ 校验和不符 → 一律拒收且**不落 Asset、不落存储**（不产生"占位/伪造结果 Ready"）。
  5. **过期预警** → 通过：临近过期发事件；已过期 → EXPIRED + `needs_reconciliation`（对账语义，不自动重复付费）。
  6. **回调/轮询/人工恢复共用服务**（计划 §5.5）→ 通过：三者都经 `registerProviderResultDescriptors` + `collectProviderResult` 与同一 `transitionJob`。
- **本次修复的工程问题（诚实记录）**：
  1. **服务端写入缺失**：`ObjectStorageAdapter` 原本只有客户端直传（Signed URL）能力，回收需要**服务端写入**——接口增补 `putObject`（本地驱动实现；S3 用 PutObject），客户端上传路径不变。
  2. **可重试性分类**：初版把所有失败都视为可重试（校验和错误也标 retryable）——改为按原因分类（大小/嗅探/校验和 → 不可重试；网络/HTTP 类 → 可重试），避免对"伪造结果"无限重试。
  3. **平台级表清理**：`webhook_events` 无 workspace 外键（Provider 事件先于任务归属被记录），测试清理需显式 delete（已修正，避免跨用例串行污染）。
  4. **人工回收的语义**：初版 `collect` 直接读 state 的 results，而测试未登记描述符 → 显式提供 `registerProviderResultDescriptors`（这也是轮询补偿的正式路径）。
