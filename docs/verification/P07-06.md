- **验收条款对照**：
  1. **"将批准绑定固定 Render"** → 审批记录含 renderId + manifestHashAtApproval + projectVersionIdAtApproval + projectRevisionAtApproval（append-only）；非 READY 不可审批。
  2. **"生成受控下载入口"** → ExportPackage：四件产物逐条签名 URL（TTL 15 分钟；服务端签发，客户端不持存储凭据）；本地驱动下 URL 实际可下载（集成测试真实取回）。
  3. **"未批准不能正式导出"** → 服务端守卫（无记录/驳回/失效 → 409）；UI 在未批准时不提供导出入口。
  4. **"批准后导出与 Manifest 一致"** → 导出包 manifestHash = 批准快照 = Render 当前值（任一不符即 409）；集成测试以**下载字节哈希**对照 manifest.outputs.sha256 逐项断言。
- **本次修复/发现的工程问题（诚实记录）**：
  1. **本地签名下载端点的装配条件**：`/api/v1/storage/*` 仅在存储依赖含 local 能力时注册（`createStorageDeps`）——测试与部署必须经该工厂构建 StorageDeps，否则签名 URL 404（非对象缺失）；已在测试中修正并保留此行为（云适配器走预签名 URL，不需要该端点）。
  2. **"批准后编辑"语义**：批准绑定的是**已产出产物**（immutable）；批准后项目新编辑不影响既有批准的有效性，但导出面板明确提示"导出内容仍为已批准快照；如需包含新编辑请重新渲染并批准"——避免用户误解（"新编辑需重新审批"针对新渲染）。
