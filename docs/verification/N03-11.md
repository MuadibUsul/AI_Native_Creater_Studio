## 验收路径覆盖（逐条对照任务验收）

1. **切换后端不改变工程**：`loadDocument` 只改 `backendKind`，`snapshot` 与 `documentRevision` 原样保留；两种后端下投影与效果里的 revision 完全一致。已测。
2. **播放事件带 requestId、revision 与实际 presented 时间**：引擎**从不**把"请求的时间"当作"已呈现"——`play/seek` 命令只产生**效果**，不产生 PLAYBACK 事件；只有后端回灌 `PRESENTED` 时才产事件，且 `requestedTime` 与 `presentedTime` **分别**上报（测试里后端故意滞后 80ms / 200ms，断言两者不同且 `presentedDriftMs` 如实）。另断言 `presentedFrame` 由后端给出。已测。
3. **unknown capability 不能被展示为支持**：`negotiatePlaybackCapabilities` 只保留"显式声明支持且未被声明为不支持"的能力；**未声明的**（如 `AUDIO_CROSSFADE`）列入 `unsupported`；**未知字符串**（如 `NOT_A_REAL_FLAG`）直接丢弃。已测。
4. **dispose 可重复调用**：首次 dispose → `DISPOSED` + DISPOSE 效果 + DISPOSED 事件；**再次 dispose → 零效果零事件**；释放后其他命令一律 `ERROR(DISPOSED)`。已测。
5. **不维护第二套编辑状态**：引擎只持有 N03-08 的 `PlaybackSnapshot`（带 `documentRevision`）；**没有任何写工程的能力**（无编辑命令、无 revision 变更）。已测（后端切换前后投影逐字段相同）。
6. **先适配现有可用预览后端（端口就绪）**：`PlaybackBackendPort` 接口 + `runPlaybackEffect` 驱动器已交付，并用**假后端跑通整场会话**（load → play → step → pause → setRange → dispose，断言端口调用序列与状态迁移一致）。真实适配器见下。
7. **失败不假装成功**：后端抛错 → `FAILED` 结果（不向调用方抛异常）→ 引擎 `ERROR(BACKEND_FAILED)` 且回 `IDLE`；此后 `play` 被拒（`NOT_LOADED`）。已测。
8. **其他 fail-closed**：未加载就 `play` → `NOT_LOADED`；已播放再 `play` → `ALREADY_PLAYING`；`seek` 越出 `setRange` 范围 → `INVALID_COMMAND`；`step 0` 帧 → `INVALID_COMMAND`；空范围连命令都构造不出来（契约层 `mediaRangeSchema` 拒绝）。已测。

## 失败与剩余缺口

1. **具体后端适配器未写**：`PlaybackBackendPort` 的实现（现有 Remotion 预览后端 / HTMLMediaElement / MSE 回退）属 **N03-12 "标准 proxy 与 HTML 媒体／MSE 回退路径"**——本项交付的是"任何后端都能接"的引擎与端口，并用假后端证明流程闭合。
2. **`PRESENTED` 事件的 `action` 目前恒为 `SEEK`**：因为"播放中周期性上报"的节拍由宿主决定，尚未定义节拍策略（属 N03-13 WebAudio 主时钟与同步调度）；届时按同一回灌路径扩展枚举即可，不改引擎骨架。
3. **无真实呈现数据**：呈现时间/帧号的一切真实数值来自后端，本项只有假后端。
4. 无 Provider 依赖、无费用。
