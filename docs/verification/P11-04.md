- **implementationSummary**：
  1. 契约 `lineage.ts`：`derivationLineageSchema`——**血缘 = 派生时输入快照**（不复制内容）：`packId/packVersion`（Plugin 来源）+ `channelKey`（Recipe 来源）+ `coreInputsDigest`/`inputsSnapshot{atomCount,claimCount}`（Core/Atom 来源）+ `summary` + `projectVersionId`（**产出项目版本，approve 可选绑定**）；`derivationListItemSchema` 增 `stale` + `currentCoreInputsDigest`（读取时对照）；`approveDerivationRequestSchema` + `LINEAGE_ERROR_REASONS`（ALREADY_APPROVED / PROJECT_VERSION_NOT_FOUND）。
  2. 迁移 0037 `derivation_lineage`（项目+时间索引）；迁移 0038 增 `project_version_id`（**不做 FK**——同项目校验在 domain 层，版本行删除不牵连血缘）。
  3. domain `lineage.ts`：`recordPlanLineage`（analyze 每次运行**追加**一条 PLAN 行——只追加，历史不篡改）；`listProjectDerivations`（新→旧；`stale = 派生时 digest ≠ 当前 digest`——**提示而非撤销**，行与状态不变）；`approveDerivation`（PLAN→APPROVED 一次性；重复 409；可选绑定项目版本——**须属于同项目**，不存在/跨项目一律 404，不泄露他项目版本存在性）。
  4. 挂钩 `packs.ts/runPackAnalyze`：analyze 成功后写入血缘（插件经公开契约产出的每个 OutputPlan 自动带来源快照——**Pack 侧零改动**）。
  5. API/SDK：`GET .../derivations`、`POST .../derivations/:lineageId/approve`（可选 body `{projectVersionId}`）；`client.derivations.{list,approve}`。
  6. **审计（REQ-92-02 / LED-96-PLUGIN-02）**：Core（domain/contracts/api 非测试代码）无 `outputType ===`、无平台名（YOUTUBE/XHS/XIAOHONGSHU/TIKTOK/NEWSLETTER…）条件分支——零命中；渠道键仅两处作为**数据**出现：Recipe 种子（`atoms.ts`）与 Pack manifest 声明（`official-packs.ts defaultChannelKey`），消费方（`packs.ts`）只读 manifest 字段、不分支。
