- **验收条款对照**：
  1. **"每个组件可独立校验"** → 通过：`validateComponentDefinition` 覆盖协议全部约束（含 fixture 与 defaults 的 schema 校验），拒绝必须给出原因码；注册表注册时强制自检（坏组件不得进入）。
  2. **"每个组件可独立渲染"** → 通过：单元级（react-dom/server 标记断言）+ **渲染级（真实 Remotion/Chrome → PNG）**；渲染输入只有 `{ props, context }`（帧/时长/画幅/主题）——不读网络/凭据/时钟。
  3. **"字体和颜色可由主题控制"** → 通过：组件全部经 `useSceneTheme()` 取 tokens；单元测试断言两主题输出不同且**不含**默认主题色/字体（写死即失败）；渲染测试断言两主题 PNG 字节不同。
  4. ComponentDefinition 字段集（§11.1 type/version/inputSchema/defaults/supportedAspectRatios/min-maxDuration/previewFixture/renderer）→ 全部落地；fixture 可序列化且被协议校验（P05-02 的截图/渲染证据与 golden 依据）。
- **本次修复/发现的工程问题（诚实记录）**：
  1. **React hooks 不能在测试中直接调函数组件**：初版测试直接调用 `renderer({props, context})` 导致 `useContext` 在无 dispatcher 下为 null——改为 JSX 元素渲染（这也是真实渲染路径，测试与生产一致）。
  2. **泛型不变性**：`ComponentDefinition<TProps>` 因 inputSchema/renderer 同时出现在输入输出位置而不变（`<具体>` 不可赋给 `<unknown>`）——协议辅助函数改为泛型；注册表在存取边界显式类型擦除（注释说明 props 类型由各组件 schema 保证）。
  3. **测试隔离**：`.test.tsx` 直接 import `registry.js` 不会触发内置装配（index 的副作用不执行）——测试显式调用 `registerBuiltInComponents()`（并在 registry 测试中提供 reset + 重装辅助）。
  4. 未使用辅助函数（`key`）被 lint 拦截——删除（保持 lint 零告警）。
