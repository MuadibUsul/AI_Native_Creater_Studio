## N06-05 验收路径覆盖

1. **“再慢一点”未提前采用**：`resolveProposalDisposition('再慢一点')` → `REFINE`（绝不是 `ADOPT`）；显式 UI 动作 `ADOPT` 才覆盖文本。已测。
2. **沉默不确认**：空/空白表达 → `NONE` + `requiresConfirmation=true`（不得据此采用）。已测。
3. **多个候选“用这个”无唯一目标时消歧**：两候选且无显式目标 → `requiresDisambiguation=true`、`targetProposalId=null`、返回候选 id 列表；指向不存在的目标同样要求消歧，不默默选一个。已测。
4. **部分采用不会切断音画依赖**：候选操作集含同一 `avGroupId` 的视频/音频两半时，只勾选画面那半边 → 闭包把音频侧并入（`adoptedOperationIndexes=[0,1]`，`closureExpanded=true`），声画两侧同步落地，未勾选的无关片段不动。已测。
5. **作用范围明确可见**：响应回带 `adoptedOperationIndexes` / `remainingOperationIndexes` / `closureExpanded` / `effectiveWriteTargets`（对象 + 维度）。
6. **引用闭包**：只选“对新建对象设不透明度”的操作 → 闭包并入其创建操作（`insert_clip` 的显式 `createdClipId`）；闭包覆盖全部操作时等价完整采用（`COMMITTED`）。
7. **fail-closed 与零部分写入**：越界下标 → 422 `PROPOSAL_PARTIAL_SCOPE_INVALID`，工程 revision 与事件数不变；操作哈希不符 → 409 `PROPOSAL_HASH_MISMATCH`。
8. **防重复写入**：部分采用是一次性交付（`PARTIALLY_ADOPTED`）；再次部分采用 → 409 `PROPOSAL_NOT_OPEN`，无第二次写入。

> **保守性说明：** 闭包宁可扩大也不切断依赖；执行层另有自己的守卫（涟漪跨轨同步、对象锁等），任一步失败即由统一编辑协议**整批回滚**，零部分写入。

## 失败与剩余缺口

- “部分采用后继续采用剩余操作”被设计为**不支持**（候选在部分采用后终态；要再改须新建候选）——为避免重复写入与声画漂移，此取舍已写入 `adoptProposalPartial` 的文档与交接。
- “后面也这样”目前只**识别并回报**为 `APPLY_MORE` 语义，跨候选/跨对象的政策化应用属后续任务（N07 系列）。
- 处置解析是**确定性兜底**；真实 NLU 由语音/LLM 层给出 `uiAction`（显式动作优先）。
- 无 Provider 依赖、无费用。
