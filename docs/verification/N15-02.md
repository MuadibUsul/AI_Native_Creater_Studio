# N15-02 验证：独立运营认证、多因素与会话

**阶段：VERIFIED（N15-02 身份/MFA/会话工程范围）。** 时间：2026-10-08（Asia/Shanghai）。O0、逐动作 RBAC/ABAC、双人审批和真实生产账号启用仍属后续任务。

## 实现证据

- Contracts：普通登录响应新增 TOTP 挑战分支；`OpsEnvironment`、`OpsRole`、`OpsSession` 和 enrollment/reauth/revoke 请求契约。所有普通运营会话 DTO 不含 token、TOTP secret、恢复码。
- Migration 0051：`admin_principals`、`admin_role_grants`、`admin_sessions`、Better Auth `two_factor` 与 `user.two_factor_enabled`。运营 token 仅存 SHA-256；`admin_sessions` 绑定 Better Auth Web session、环境及 grant version。角色 grant 的 INSERT/UPDATE/DELETE 触发器递增 `grant_version`，让既有运营会话失效。
- Service：只有 Better Auth 登录二次挑战成功后才签发独立 HttpOnly `ancs_ops_session`；已登录 enrollment 确认不会升级旧普通会话。每次请求检查普通 Web session、当前 MFA 开关、当前 principal、角色、环境、grant version、空闲/绝对期限。包含 `SERVICE_ACCOUNT` 的 principal 不建立人类会话；非法角色值运行时拒绝。敏感写要求近期 TOTP 重验；连续失败有服务端锁定。撤销自身或其他本人设备会话，退出通过原会话删除级联失效。
- API：`POST /auth/verify-totp`、`GET /ops/session`、`POST /ops/mfa/enroll`、`POST /ops/reauth`、`POST /ops/sessions/revoke`；旧 `/admin/*` 读写均经过独立运营守卫。`ANCS_PLATFORM_ADMINS` 保留历史配置解析，但不再授予权限。生产环境的旧 `/admin` 全部读写路由在 N15-03/04 逐动作、逐对象授权及安全投影到位前固定返回 403；运营身份自助 `/ops` 不受此关闭规则影响。
- SDK/UI：SDK 暴露上述认证与运营会话动作；登录页识别 TOTP 挑战；运营页提供 enrollment、重验、设备撤销、环境及角色标识。生产标识取服务端运营会话，未将 TEST 身份呈现为生产启用。

## 负面路径与加密证据

- 真实 HTTP/DB 专项 6 测试覆盖：普通 Owner 404；历史白名单不可用；SERVICE_ACCOUNT 混合角色拒绝；普通旧 session 和 enrollment 确认不签发 ops cookie；Native Bearer、错误 ops cookie、空闲及绝对过期拒绝；退出、设备撤销、MFA 停用、角色新增/撤销使旧会话失效；TEST principal 在 PRODUCTION 守卫下 404；生产模拟中 PRODUCTION principal 完成 MFA 后仅可使用 `/ops/session`、重验和本人会话撤销，旧 `/admin` 的 overview、users、jobs、support-view 读取及写入均返回 403；敏感写重验过期 403，错误码 401 与服务端失败计数，正确码后继续处理。
- Better Auth 1.7.7 本机源码 `plugins/two-factor/index.mjs`：TOTP secret 经 `symmetricEncrypt`，上层默认 `backupCodeOptions.storeBackupCodes='encrypted'`；本项目也显式固定加密选项。真实 DB 断言 `two_factor.secret` 不含 URI 明文 secret、`backup_codes` 不含返回的首个恢复码且不能作为 JSON 解析。恢复码仅在 enrollment 一次性响应和页面临时内存中显示，不入普通 DTO/日志。
- 新设备异常当前以 User-Agent 的 HMAC 指纹变化识别，在 `audit_log` 追加 `ops.auth.new_device`，当前设备的 `/ops/session` 返回 `securityNotice=NEW_DEVICE` 并由 UI 展示。IP 也只保存 HMAC 指纹；**尚无外部短信/邮件/安全通知通道**，不称为生产通知实测。
- `/ops/reauth` 对 Better Auth `verifyTOTP` 异常统一映射 401 并计入服务端失败锁定；这是预期错误处理边界，不将插件原始错误或 secret 回传。现有 Better Auth 登录挑战本身有尝试限制。
