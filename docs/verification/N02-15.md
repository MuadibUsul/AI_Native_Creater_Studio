## 实现证据

- **统一读投影**：`getMediaEvidenceBundle` 让 Director、选区解析与参考分析共用同一 MediaIndex 读取路径（`listUnifiedMediaIndex`），不产生第二套索引查询；上下文只含显式消费者枚举（DIRECTOR / SELECTION / REFERENCE_ANALYSIS）与已授权数据面。
- **缓存 key 组合**：`sha256(workspaceId, sourceAssetVersionId, consumer, kind, 源范围(含有理时基), analysisConfigHash, indexFingerprint, permissionContextHash)`。`indexFingerprint` 由当前索引 run（processorVersion/analysisConfigHash/indexVersion/status）、转写 run 与用户标签集派生——索引或来源数据变化即自然失效，旧缓存行保留（**仅相关记录失效，不是全量清空**）。
- **权限上下文隔离**：key 含服务端生成的 `permissionContextHash`（workspace+userId+role+capability），不同成员/角色命中不同缓存行；跨租户读取 404 反枚举；响应固定 `Cache-Control: private, no-store` 与 `Vary: authorization, cookie`。
- **用量记录**：每次调用记录 `hitCount`/`analysisReadCount`/`rangeReadCount`（命中即自增 hit 并更新 lastAccessedAt），落库可查。
- **导演接入**：`planDirector` 在同一次规划中按素材读取证据包（consumer=DIRECTOR），结果只投影 `recordIds` 前 100 条与 `cacheStatus`，不把整包证据塞进计划。
- **UI 接入**：片段检索结果新增"带到编辑器"（写 `sessionStorage: ancs-media-selection:<ws>:<prj>`）；编辑器读取后显示"已选择真实片段 + 源范围"，明确"项目尚未自动修改"，可取消；**空分镜（新项目）同样显示**（见下"发现并修复的真实缺陷"）。

## 发现并修复的真实缺陷（浏览器 E2E 抓出，jsdom 未覆盖）

首次真实浏览器运行时，选区 banner 在编辑器中**不可见**：`workflow-director.tsx` 的**空分镜早退分支**（`qf-director-empty`，第 243–248 行）在渲染前 return，绕过了含 banner 的主分支（`qf-director-workspace`）——也就是说：**在"新项目空分镜 → 把检索命中带到编辑器"这个最需要该信息的场景下，提示恰好不出现**。逐层排查（存储读取探针证明 effect 已按正确 key 读到值且条件为真；DOM 检查证明根节点为 `qf-director-empty`）后确认根因，修复方式：把 banner 提取为 `mediaSelectionNotice` 并同时接入空分镜分支与主分支；并补充 jsdom 回归用例锁死（见上表）。
