## 实现证据

- **契约**：`trackSchema`／`createTrackRequestSchema` 增加 `solo`／`syncLocked`（预览与导出共用同一状态面）；`packages/contracts/src/composition-edits.ts` 新增五个规范原语——`create_track`（含 `restoreTrackId` 精确复原）、`move_track`、`delete_track`（`nonEmptyPolicy = REJECT｜MOVE_CLIPS` 与目标轨成对）、`update_track`（`changes` 至少一项：name／position／locked／muted／hidden／solo／syncLocked）、`set_av_link`（`linked` 时恰两条不同片段）。`EDIT_OPERATION_TYPES` 30→35；v2 覆盖层把 `create_track`／`move_track`／`delete_track` 由 PLANNED 翻为 NATIVE，新增 `update_track`／`set_av_link`（来源操作 38→40），`clips`/`tracks` 投影同步带上新字段（`toTrack`、旧版迁移投影均补默认值）。
- **执行器**（`packages/domain/src/edits.ts`）：
  - `create_track`：位置被占用时把该位置及其后的轨道整体后移（**两阶段写入**），插入新轨并逐段落事件。
  - `move_track`／`update_track.position`：按目标位置重排全轨顺序（`commitTrackOrder` 两阶段：先 +10000 偏移再落位），保证 `(sequence_id, position)` 唯一索引不产生瞬时冲突。
  - `delete_track`：默认 `REJECT` 非空轨（409 `TRACK_NOT_EMPTY` + `clipCount`）；`MOVE_CLIPS` 要求目标轨同类且不同（422 `TRACK_KIND_MISMATCH`），片段迁走不丢；删除后剩余轨道重排连续。
  - `update_track`：只改**这一条**轨道自身的状态（静音/独奏/隐藏/锁定/同步锁/名称），不触碰其他轨道与其片段。
  - `set_av_link`：链接需同序列、一视频一音频（422 `AV_LINK_INVALID`）、时长相等（422 `AV_LINK_DURATION_MISMATCH`），分配同一 `avGroupId`；解链清空 `avGroupId`，其后各自编辑不再联动。
  - **同步锁参与涟漪**：`ripple_clip` 的收缝范围改为"显式 `closeAcrossTracks=true` → 全部轨道；否则 → 本轨 + 打开 `syncLocked` 的轨道"，若 AV 关联片段所在轨不在范围内 → 409 `AV_SYNC_REQUIRES_CROSS_TRACK_RIPPLE`（不静默破坏声画同步）。
- **undo/redo**：`CREATE_TRACK`／`MOVE_TRACK`／`DELETE_TRACK`／`UPDATE_TRACK`（恢复到 before 的轨道状态）／`SET_AV_LINK`（恢复原 `avGroupId`，含"解链后再撤销"回到关联状态）逐条登记。

## 发现并修复的真实缺陷

**轨道重排触发唯一索引冲突（HTTP 500）**：`create_track` 让位与 `move_track` 重排都用"逐条直接写目标 position"的方式，在 `sequence_tracks_sequence_position_uq` 上产生瞬时重复键（例如把 A1 从 1 挪到 0 时 V1 还在 0），真实数据库直接抛 `duplicate key value violates unique constraint`。修复：抽出 `commitTrackOrder` 做**两阶段落位**（先把所有要动的轨道挪到 +10000，再写入最终位置），并在 `create_track` 中"先偏移 → 插入新轨 → 再落位"。该缺陷是本次用真实 PostgreSQL 跑 HTTP 用例时被服务端日志（临时开启 logger）定位的。
