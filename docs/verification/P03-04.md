- **验收条款对照**：
  1. **"KMS"** → 通过（本地实现）：AES-256-GCM envelope encryption，密钥版本化 + 轮换语义 + fail-closed；云 KMS 适配器按同一 `CredentialCipher` 接口替换（真实凭据阶段，§13.5 第 8 条）。
  2. **"连接测试"** → 通过：离线校验（可解密）恒执行；注入 Provider Test Hook 时执行真实连接测试并记录模式 LIVE；失败置 INVALID。
  3. **"轮换、撤销"** → 通过：轮换写新密文/新版本（旧密文仍可解密），撤销记录 revoked_at 且**立即**从路由候选中消失（测试：撤销后决策 501 且原因为 BYOK_SELECTED_BUT_CONNECTION_MISSING）。
  4. **"Managed/BYOK 选择"** → 通过：§17.2 决策树实现（AUTOMATIC 优先 BYOK → 平台；显式 BYOK 无连接拒绝；显式 Managed 无平台凭据拒绝）；Workspace 级按类别覆盖（workspace_provider_settings）；身份级覆盖位已预留（P06-02）。
  5. **"密钥不进入前端及日志"** → 通过（强断言）：所有端点响应与**错误信封**逐条断言不含 Secret、`ciphertext`、`authTag`、`nonce`、`encryptedSecret`；连接 DTO 只有掩码；平台凭据仅经服务端 `resolve` 使用；secrets:check 亦拦截仓库侧泄漏。
  6. **"跨租户连接不可使用"** → 通过：非成员对连接与设置的读/写/测试/轮换/撤销一律 404（不泄漏资源 id）；攻击者自身 workspace 路由决策不会引用他人连接（501，details 无他人 connectionId）。
  7. **REQ-51-06（§51 四要素）** → **4/4 收尾**：跨 workspace 读/写拒绝（P01-03 起持续）、Signed URL scope（P02-04）、**Provider 凭据隔离（本任务）**。
- **本次修复的工程问题（诚实记录）**：
  1. **`PlatformCredentialRegistry` 需要 resolve**：Router 只需 `has()`，但执行链路要拿明文 → 接口补可选 `resolve`（在 contracts 中明确"仅服务端"）。
  2. **SDK 不支持 PUT**：新增请求方法 PUT（幂等头照常）。
  3. **凭据端点对 VIEWER 的可见性**：考虑过用 workspace:read 让 VIEWER 看掩码列表，最终收紧为 **provider:manage**（凭据是高权限资源，§17.3"只在后端使用"），并补 403 断言。
  4. **BYOK 优先不等于"总能回落"**：显式 BYOK 设置缺连接时**必须拒绝**（否则用户以为在用自有 Key，实际在消耗平台额度——成本与合规风险）；测试锁定该行为。
