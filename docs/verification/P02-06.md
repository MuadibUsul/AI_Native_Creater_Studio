- **验收条款对照**：
  1. **"断线重连能恢复状态"** → 通过（两条独立证据）：① REST 原语——首次 `cursor=0` 拉取 → 断开期间两次编辑 → 带最后 seq 重拉，恰收到 2 条新事件、与首次批次零重复、顺序正确、追平后再拉为空；② SSE——首次连接读到一个事件后断开 → 断线期间两次编辑 → 带 `Last-Event-ID` 重连，**补齐两条（seq 连续）且不重**；连接中产生的新编辑经已建立（或新建带游标）的流实时送达。
  2. **"越权游标按协议处理"** → 通过：非成员访问游标/列表/SSE 一律 404（抗枚举）；`cursor` 超出 head → 409 `PRECONDITION_FAILED`（details.reason=CURSOR_AHEAD、headSeq），SSE 场景在建立流之前即以该状态拒绝。
  3. **"过期游标"** → 本系统的事件日志不做 TTL 清理（Outbox 是权威账本的一部分），因此不存在"过期游标"；语义上等价情形（超出 head）已按协议 409 处理。**已记录为与规范措辞的差异**（见剩余风险 1）。
  4. **REQ-61-01（通知）** → 通过：通知持久化（服务端表）而非 Web toast；in-app 列表/未读计数/标记已读；Job 失败与 Render 完成类型为预留位（随 P03/P07 的事件产生方接入）。
  5. **REQ-29-06（不每秒轮询）** → 通过：客户端经 SSE 接收推送；REST 轮询仅在断线恢复时使用（且带游标，非全量）。
- **本次修复的工程问题（诚实记录）**：

  2. **测试状态跟踪**：`expectedSceneRevisions` 需要 Scene revision 而非项目 revision（初版测试混用导致 409）——改为显式 `EditState`（项目/场景双 revision 跟踪）。

- **remainingRisks**：
