# 二十八、详尽运营后台：业务运营、制作运行与安全治理

**需求来源：[U02] 用户本轮追加“还需要有一个详尽的运营后台”。** 本章将这一目标细化为产品与工程要求。具体模块、权限、流程与阈值规则是本版设计，不声称现有仓库已经具备；不得用一页仪表盘或几个后台按钮代替本章验收。

后台的目标是让运营人员能够回答并处理：**谁在使用、制作卡在哪里、钱怎么收和花、模型与策略是否可靠、用户为何流失、哪些内容或数据需要治理，以及故障发生后如何安全恢复。** 它应有操作能力，但不能形成绕过作品状态、租户权限和财务账本的超级后门。

## 28.1 三个工作空间与边界

| 空间 | 使用者 | 能做什么 | 默认不能做什么 |
|---|---|---|---|
| 创作 Studio | 创作者、剪辑者、审阅人 | 看、指、说、试改、确认、交付 | 看到平台其他客户、平台成本或密钥 |
| Workspace 管理 | 客户 Owner／Admin／Billing Manager | 本工作区成员、角色、套餐、用量、身份、素材与集成策略 | 获得平台运营权限，跨租户搜索或修改供应商全局目录 |
| Platform Ops 运营台 | 平台运营、客服、财务、内容审核、可靠性与安全人员 | 按职责诊断、配置、处置和治理 | 任意打开私密视频、冒充用户确认、直接改余额或数据库 |

建议逻辑入口为平台 `/ops`、客户 `/w/:workspaceId/settings`；已有 `/admin` 先盘点再兼容迁移。路径和是否独立应用由现有工程决定，不因命名新建第二套后端。平台令牌使用独立权限域／audience和更严格会话策略，不能仅靠隐藏菜单或一个`isAdmin`字段隔离。

平台后台可以信息密集、支持表格与钻取；它与Studio共用§29黑白设计语言，但不套用创作画布“只能少量按钮”的交互限制。导航按职责展示：**经营、客户、制作、AI与内容、治理、系统**。普通创作者不需要在 Studio 看见这些模块。

## 28.3 运营台统一交互规范

每个模块采用“列表 → 详情 → 影响预检 → 授权动作 → 执行结果”的一致流程。列表支持服务端分页、可保存视图、多维过滤、排序、字段权限、列设置、时间区间、时区和数据更新时间；大数据不一次拉到浏览器。详情支持时间线、相互链接的对象、已遮罩诊断和相关审批／工单。

全局搜索允许按用户／Workspace／Project／Job／Provider Job／订单／动作ID精确定位；模糊联系方式需专门权限与限频。搜索先按操作者权限过滤，再聚合，不能在“无权查看”的搜索结果里泄露其他客户名称或数量。

金额保留币种、单位、估算／实际状态；日期同时可查UTC和所选显示时区。列表区分空、未采集、部分数据、延迟、失败、无权限；不能把缺失数据渲染成零或100%成功。页面状态以黑白层级、图标和文字呈现；必要专业颜色例外不作为唯一告警。详见§29。

批量操作必须：筛选快照→锁定目标ID集合／数量→逐项可操作性预检→影响和费用预估→授权→排队→逐项结果。不能点击“全选”后让新进入筛选范围的用户也被隐式执行；支持批次暂停与未执行项取消，不承诺回滚已经发生的外部退款或删除。

敏感导出是异步、有权限、有用途、有到期和下载审计的任务。行列权限与页面一致，不能通过导出绕过；CSV／表格导出对公式前缀注入做安全处理。后台错误不暴露完整prompt、密钥、签名URL或原始音视频。

## 28.4 管理员身份、角色和职责分离

角色是权限集合模板，实际授权还需环境、租户范围、资源种类、金额阈值、时间、工单、风险和审批条件。默认拒绝，前端展示不是授权边界。

| 角色模板 | 允许的主要范围 | 硬性限制 |
|---|---|---|
| PLATFORM_OWNER | 人员委派、平台配置治理与审批安排 | 不是自动可读全部素材／明文Key／篡改账本的root |
| SUPPORT_L1 | 脱敏客户、订单／任务状态、工单和服务通知 | 不看私密媒体，不退款，不编辑作品，不切Provider |
| SUPPORT_L2 | 深入脱敏诊断、申请限时支持访问、恢复方案 | 临时授权只读为默认；不能冒充客户接受试改或发布 |
| PRODUCTION_OPERATOR | 队列、恢复、取消请求、Provider状态、成本止损 | 重试受预算／模式约束；无财务退款或内容批准权 |
| PROVIDER_MANAGER | 目录、限流、路由草案和健康 | 凭据只看指纹／状态，不读原Key；价格／区域变更需审批 |
| BILLING_OPERATOR | 订单、用量、对账、退款与补偿申请 | 不直接改余额；不能审批自己发起的敏感财务动作 |
| BILLING_APPROVER | 审批范围内财务动作、差异复核 | 申请人与审批人不得是同一身份或其别名 |
| CONTENT_REVIEWER / REVIEW_LEAD | 按案件访问证据、审核／复核／申诉 | 无权无限浏览私密作品；不改变原件，重大恢复需复核 |
| AI_QUALITY / STRATEGY_CURATOR | 评测、策略／组件／prompt候选和发布申请 | 不自动升级全部客户项目，不绕过版权／sandbox审核 |
| GROWTH_ANALYST | 聚合指标、允许分群、实验分析 | 默认无原始媒体、支付细节或身份训练样本 |
| PRIVACY_OFFICER / SECURITY_ADMIN | 数据请求、限时访问审批、权限和审计 | 隐私删除按工作流；不可删除审计证明来掩盖访问 |
| AUDITOR | 明确范围内的只读证据和审计 | 无业务变更、无无限量导出 |
| SERVICE_ACCOUNT | 单用途自动任务 | 非交互式、最小scope、有限期、不具备人类确认资格 |

平台管理员登录必须多因素验证，敏感动作重新验证；设置会话空闲／绝对时限、设备撤销、异常登录提醒和角色变更即时失效。具体分钟数在配置与验收中定稿，不硬编码历史示例。生产与测试身份／密钥／动作入口区分，生产页面持续显示环境。

至少对真实货币退款、批量额度调整、删除私密原件、授予高权限、批量媒体导出、全局路由／价格策略和生产恢复实行风险分级审批。高风险双人原则必须由两个独立操作者满足；一人创业阶段可自助执行预先限定的低风险动作，但不能通过注册第二身份自批高风险操作。未具备双人条件时保持该高风险路径禁用或接入已批准的外部复核流程。

紧急break-glass只允许预先列明的止损权限，例如暂停新生成和撤销失窃会话；短期、逐次原因、告警、事后复核。不提供“无限提权查看全部素材／无限退款／强行发布”的万能开关。

## 28.5 所有有副作用操作进入 AdminAction

后台不直连可写数据库、不绕过领域校验、不为运营提供任意SQL／shell面板。统一命令服务位于现有API与domain，客户端只发类型化请求。

```text
AdminAction
  id / schemaVersion / environment / actionType
  requesterPrincipalId / requesterRoleSnapshot / ticketId? / reason
  targetType / targetIdsSnapshot / workspaceScope / scopeHash
  expectedRevisions / policyVersion / dryRunId / impactHash
  riskLevel / requiredApprovals / approverPrincipals[] / approvalExpiry
  financialImpact / privacyImpact / estimatedCost / authorizedCeiling
  idempotencyKey / expiresAt / executionJobId? / providerReferences[]
  state / itemResults[] / beforeSummaryHash / afterSummaryHash
  evidenceRefs[] / compensationActionId? / createdAt / completedAt?
```

主状态：`DRAFT → PRECHECKED → AWAITING_APPROVAL → APPROVED → QUEUED → RUNNING → SUCCEEDED / PARTIAL / FAILED`；执行前可`REJECTED / EXPIRED / CANCELLED`。执行中的取消仅请求未开始步骤停止，外部结果未知进入`RECONCILING`，**不得先标失败后盲目重试付费操作**。部分批次按item保存状态，不能用一个成功标志盖住部分失败。

执行顺序为：身份与scope→policy与revision→生成只读dry-run→计算影响与预算→按风险审批→执行前再次核对revision／授权／scope→幂等领域命令→事务或外部工作流→核对实际结果→审计／通知。权限、目标、价格或scope变化使原审批失效，不允许修改审批内容后沿用签名。

dry-run要展示受影响用户／项目／资产／任务数、保护项、费用、可能不可逆项及补偿策略；它不是实际修改。执行错误要返回已完成步骤与可恢复路径。回滚依动作性质定义：配置恢复旧版本、编辑用补偿事件、账本用冲正／退款、删除只在保留期可恢复；不能承诺任意动作都能“撤销”。

## 28.6 经营指标、用量与质量口径

设独立`MetricDefinition`与版本，不在各页分别计算不同“收入”。每项记录公式、事实来源、分母、去重键、事件时间／处理时间、时区、币种、更新延迟、测试账号排除、晚到修订与责任人。

| 指标 | 产品定义要求 | 不能混淆 |
|---|---|---|
| 有效活跃Workspace／用户 | 以已定义的真实创作事件计算；登录活动另列 | 登录次数不能直接当创作使用 |
| 首次价值转化 | 注册／创建Workspace→导入→首次有效试改→首次采用→首次通过QA导出 | 草稿生成／点击导出不等于合格成片 |
| 成功率 | 同类操作、固定时间窗、去重逻辑任务；首次成功和最终成功分别算 | 重试成功不能抹去首次失败；排除取消要注明 |
| MRR／ARR | 明确可经常性订阅项、周期归一、折扣、欠费与取消口径 | 一次性充值、税款、实收、递延收入不能统称MRR |
| 实收／退款／净收 | 按支付／退款实际确认事件和币种分别报告 | pending付款、未确认退款不计为成功现金流 |
| Credits | 已购／赠送／补偿／预留／已用／释放／到期／冲正按桶展示 | Credits不是现金余额；赠送不计销售收入 |
| 成本与贡献 | Provider实际／估计、失败和试改损耗、渲染、存储、带宽、分摊口径 | 缺失成本不能填零；管理分析不冒充法定会计毛利 |
| 留存／付费续订／流失 | cohort按用户或Workspace固定，期初基数、周期、暂停与到期分类 | 月续订和任意回访不互换 |
| AI制作质量 | 采用率、范围外误改、纠正轮次、首次可用时间、用户评分和审核样本 | 较高生成次数不代表作品质量更好 |
| 单位经济性 | 每分钟合格成片／每次被采用修改的全成本与分摊 | 只计算成功生成API价格会漏掉规划、失败和预览 |

多币种保留原币账，不直接相加；管理报表折算要记录汇率来源、日期和快照，并可回溯重算。数值使用货币最小单位或已定义decimal，禁止浮点累积财务余额。收入／成本指标与财务报表之间有明确责任边界；上线会计、税务和合同口径另行核验，不由AI猜定。

平台经营看板只看必要汇总。单租户小样本数据不得泄露到外部对标；按内容类型汇总默认不用私人视频全文或身份训练数据训练增长模型。

## 28.7 用户、工作区和客服操作闭环

用户详情聚合身份状态、注册来源、合规同意、Workspace关系、近期关键事件、套餐、工单与通知；敏感字段按角色遮罩。账号状态与订阅、单能力限制、内容案件分开：`ACTIVE / RESTRICTED / SUSPENDED / DELETION_PENDING / DELETED`不代表立刻删除资产或取消账单。

暂停账号必须标注具体原因、限制范围、生效时间、复查、通知与申诉入口。风险降低时恢复同一身份与资产，不能新建空用户替代。Workspace转移须验证现Owner与新Owner及企业政策，不能由客服改一列归属；最后Owner移除有保护。席位／套餐变更预演影响和费用，新规则不静默夺走已约定权益或改坏历史冻结版本。

工单状态至少：`OPEN / TRIAGED / WAITING_USER / WAITING_INTERNAL / RESOLVED / CLOSED / REOPENED`。工单可关联项目、任务、费用、数据请求和事故；内部备注与客户回复严格分开。优先级与响应目标由策略配置，显示工作时区和超时原因，不伪装已有24小时人工支持。

客服首先看到脱敏技术信息，不默认看到视频和对话全文。确有需要时创建`SupportAccessGrant`：用途／工单、允许的Workspace／项目／资产／时间范围、可做动作、批准者、到期、客户同意或其他经审核有效依据、撤销。默认只读；使用时显示操作者身份，不共用用户cookie，不以用户身份产生采用／发布／克隆同意。

支持期间修复作品只能提出可审阅候选；按已授权恢复策略恢复技术状态与批准艺术内容分开。客户随时可撤销支持访问；撤销后服务端和已缓存播放权限都失效，未获允许的下载和导出仍被阻止。

## 28.8 任务中心、恢复与制作成本止损

任务详情显示任务DAG、每阶段、租户、优先级、公平配额、queued／running时长、lease／heartbeat、attempt、实际Provider Job、result fetch、取消、超时、回调和用量事件。**停派发、取消执行、停止采用、停止说话、退款是五件不同的事。**

| 运营动作 | 执行条件 | 必须保护 |
|---|---|---|
| 查询外部结果／补拉输出 | Provider Job存在、凭据scope允许、输出仍可取 | 先查后重试；回收后验hash／QA；不能自动绑定过期提案 |
| 恢复阶段／重试 | 原任务状态可恢复、无已成功副作用、预算和模式仍允许 | 逻辑任务与attempt分开；只重试失败阶段，不重跑整片 |
| 取消请求 | 能力支持；展示不能取消的已提交外部步骤 | 不承诺未收费，晚到结果隔离，不覆盖确认版 |
| 调整优先级 | 在批准范围、公平队列和账户上限内 | 不无限插队、不剥夺其他租户资源 |
| 暂停Workspace／Provider新任务 | 安全／成本异常有明确scope | 默认保留运行中和已完成成果，独立处理必要中止 |
| 死信重放 | 已分类错误、依赖恢复、幂等检查通过 | 不复制付款、发布、资产和EditEvent；单批限额 |
| 受控批量恢复 | 固定目标快照、dry-run、数量／预算上限、逐项结果 | 停止未执行部分，已执行副作用有追账和补偿 |

成本紧急止损支持平台／Provider／账户／Workspace／项目维度；暂停昂贵新任务不应使纯素材剪辑或已确认成片下载无理由停摆。预算事件延迟可使用保守预留，但未知实际成本仍待对账。供应商缺少幂等接口时，网络结果不明必须查询／人工对账，不能保证外部exactly-once。

运维恢复不能强制解除用户锁、改变`FOOTAGE_EDIT`政策、替换已批准身份或覆盖FrozenManifest。让用户选择替代素材时走普通提案流程。

## 28.9 供应商、模型和密钥运营

供应商目录将“官方声明”“账户实测”“线上观测”分开。每项能力记录模型／版本、支持输入输出、限制、取消／Webhook、实际账户／地区、成本公式、数据处理政策、核验时间、测试证据和稳定性；不因为竞品宣称支持就开放能力。

Provider价格、并发、路由、隐私地域改变先做配置diff和受影响项目／报价预演，冻结版本不变；新生成按已授权政策决定，报价越界重新授权。切换供应商不能把用户BYOK失败静默切到平台付费，更不能把保密素材转给另一区域服务。

凭据只保存后端加密引用；运营台只显示拥有者、指纹、用途、最后成功、失败类型、到期／轮换／撤销状态。新增与轮换为write-only输入，测试不回显Secret；客服不能下载BYOK Key。平台托管和客户BYOK作用域严格分开，连接修复默认让客户走授权流程，不索取密码。

健康探测默认用非敏感合成fixture；测试调用要声明可能费用并符合额度。自动降级只允许到已批准的合法候选；无候选就暂停相关能力并告诉用户缺口。

## 28.10 商品、订单、订阅、Credits与退款

商品模型拆为`PlanVersion`、`PriceVersion`、`EntitlementSnapshot`、计算Credit桶、存储与席位、Pack权益、试用／赠送／补偿规则。一个订阅开通不自动等于Provider无限预算；权益与计算用量继续分离。

Plan变更必须说明对新客户、存量客户、下个续费周期及已签合同的作用；支持预定生效、停售与保留老方案。优惠码／试用需有适用对象、次数、有效期和总成本上限，限制滥用但不偷偷收集不必要身份信息。后台按钮不得直接改用户可变余额。

订单、订阅、发票／付款凭证、支付、退款、拒付与权益是独立事实，通过事件关联。只有经过签名校验并去重的支付事件或明确的对账确认才授予适用权益；处理乱序Webhook、重复扣费、付款成功但权益未生效、退款成功但账本未冲正等情况。

Credits采用追加式ledger：`PURCHASE / GRANT / RESERVE / CAPTURE / RELEASE / REFUND / EXPIRE / ADJUSTMENT`是示意类型，实际需复用现存账本映射。预留与扣款区分；赠送、购买和补偿余额桶分别追踪。手工补偿必须有原因、金额上限、审批与反向记录，不能更新历史DEBIT为0。

退款流程：工单／订单选择→检查可退金额及历史退款／拒付→计算权益影响→申请与审批→调用支付提供商→持久外部退款ID→查询／Webhook对账→账本补偿→客户通知。重复点击返回同一退款；超额拒绝；结果未知进入对账队列；取消生成、拒绝样片、撤销编辑不等于自动退款。

冻结／暂停账号不能阻止查看依法或合同要求保留的账单和请求处理渠道；具体市场要求在商业上线审核。后台不保存完整支付卡信息或读取安全码，退款优先引用原支付对象并按提供商实际能力执行。

## 28.11 成本、预算、对账与盈利分析

每笔用量按Workspace／项目／提案／阶段／逻辑任务／attempt／Provider账号归因。保留原始计量事件、报价快照、预留、实际结算、账单对照与差异状态。AI规划、ASR、语音会话、索引、试片、失败、修复、合成、存储／带宽不得从运营账本消失。

差异案件包括：外部收费但内部无记录、内部扣额度但外部失败、账单延迟、币种／税费差、重复事件、取消晚到、预留未释放、价格版本错误。每案有证据、责任人、动作、金额与关闭依据；未知不可强行标`MATCHED`。

预算阈值、单操作／日／月上限、试用总补贴、Provider日封顶、异常烧钱告警由版本化策略管理。提高上限需要权限与理由；降低上限说明进行中任务如何处理。所有报表能从聚合钻到允许范围的事件，不从可变balance倒推出历史。

运营贡献报告可拆软件订阅、计算收入、赠送额度成本、失败浪费、试片采用损耗和基础设施分摊。真实利润、税费和会计收入并非这些简单汇总自动证明；报表标明估计与覆盖率。

## 28.12 素材、索引、身份与隐私生命周期

资产中心展示原件、代理、波形、索引、向量、遮罩、试片、生成输出和冻结引用；不默认提供全平台内容墙。缩略图与播放也属于内容访问，需与原片一致授权，不能只有下载受控。

删除分成：移除项目引用、清缓存、删除孤立派生物、用户申请删除个人数据、Provider删除请求、备份自然到期。各自有预演、责任、记录与期限配置。原件／批准资产仍有引用时，不用TTL误删；用户有效隐私删除也不能因“需要以后重渲染”被无限拒绝。

`PrivacyRequest`包含请求人验证、类型、scope、法律／合同保留例外（由获授权人员确认）、目标清单、执行进度、下游状态、证明和未能删除的明确说明。数据导出有权限复核、限时URL、下载记录；数据删除有依赖检查和必要不可恢复确认。备份恢复后必须重放有效删除标记，不能复活已删身份样本和索引。

声音／数字人后台保存授权与验证元数据，原训练材料严格最小化。退休身份可禁止新生成，历史已批准产物按许可与删除政策处理；“本平台移除引用”“Provider已确认删除”“备份到期”不得混为一个绿色完成标签。

内容审核、支持访问和质检采样分别请求scope与用途；不把用户使用产品等同允许员工随意观看或拿去训练模型。使用私人素材做质量集要有明确允许范围及撤销处理。

## 28.13 内容审核、投诉与申诉

审核记录可由用户举报、身份滥用、权限争议、内容规则或异常行为触发；模型只提供辅助分类和证据，重大处罚有人工复核。状态至少：`OPEN / TRIAGED / UNDER_REVIEW / ACTIONED / APPEALED / REINSTATED / CLOSED`。

处置粒度包括某项生成能力、某个资产／输出、公开发布、账户或Workspace；不得一个资产争议就静默删除全部用户项目。隔离与原件删除不同，处置应保存理由、版本、操作者和申诉期限策略。

审核访问仅限案件范围；查看敏感媒体、导出证据和身份训练素材需要更高权限。客户可见理由与内部风控信息分离，避免泄露其他举报者和安全规则细节；撤销错误处置时恢复相应权限而不改历史证据。

公开发布需另有用户授权；运营审核通过不等于用户授权发布。视频真实性、人物授权和合成标识规则以产品政策与市场核验为准，不在本规范中宣称任何法域的绝对合法性。

## 28.14 策略、组件、Pack与AI质量运营

策略后台不是模板文件上传页。每份策略展示参考权限、分析覆盖、观测／推断规则、蓝图、DNA、Recipe、语法schema、支持视频类型、测试素材、三内容迁移结果、费用／延迟、已知限制、版本和部署范围。

策略／组件状态可为`DRAFT → VALIDATING → IN_REVIEW → APPROVED → CANARY → PUBLISHED → DEPRECATED / SUSPENDED / REVOKED`。代码组件和第三方Pack须经过sandbox、依赖、签名、权限及资源检查。审核不通过保留原因与新版本入口，不能修改已发布版本的内容而复用旧hash。

“下架”默认停止新推荐和新安装，不重写历史FrozenManifest；安全或权利撤销可能阻止未来执行，此时给出受影响项目清单和迁移／替代提案，不能擅自生成替换内容。策略市场分账、开发者入驻和定价可与已有企业／商城任务衔接，不先造一套独立结算系统。

Agent模型、prompt、工具schema、策略、路由和组件版本一起进入`ModelRelease`。上线前运行真实确定性回归与允许的Provider smoke；人工盲评与模型评分分开。灰度守护指标至少包含锁违反、范围外误改、隐私／费用越界、失败率、延迟、采用率和单位成本；重大安全违反应能停止新调用。

客户正在审阅的提案锁定其关键执行版本，灰度升级不悄悄改变候选效果。紧急回滚保留已发生的费用和输出，配置版本回退不能伪造业务撤销。普通客服无权改全局prompt来修某个客户项目。

## 28.15 增长、通知与分群

增长后台围绕已定义的价值事件建立漏斗与cohort，不只统计PV。维度包括入口、创作者类型、制作模式、视频类型、渠道、设备、产品／模型版本、套餐与地区策略；敏感内容文本不作为默认维度。

实验保存假设、分组单位、稳定分配、范围、指标、停止规则、开始结束、数据延迟和分析版本；Workspace内成员尽量同组，避免协作行为相互冲突。运行前登记成功标准，不看结果后挑指标。量不足返回证据不足，不宣称统计显著。营销实验不得放宽安全、隐私、生成禁令和财务权限。

通知分事务、服务和营销。模板有语言、变量schema、版本、预览、审批、渠道、频控、受众快照、去重键和退订／抑制策略。事务通知来自后台事件，营销按有效同意与渠道规则，不把收到渲染完成通知等同订阅广告。

群发先测试与小范围发送，显示数量与成本，支持取消尚未发出的部分；重试不向成功用户重复发送。后台可管理邮件／站内／推送／企业消息集成，但仅实际已接入并有授权的渠道标为支持；未接入渠道不能报告发送成功。

## 28.16 发布、CMS、Webhook和开发者接入

继承P1/P2/P3/P4发布分级；连接详情显示已授权scope、期限、remote account与状态，Secret不可读。错误分类区分需要用户重新授权、限额、内容失败、政策拒绝、超时未知和供应商故障。

Webhook保存已验签事实、去重键、原始摘要hash、事件版本、处理状态和重试；运营重放仍必须经过同样验证和领域幂等，不允许编辑payload注入任意状态。原始敏感payload采用受控保留与脱敏展示。

发布结果未知先查询remote ID／幂等记录；不直接再发一条。CMS回写、内容导入和通知失败分别处理，不因回写失败重新生成付费视频。客户API访问按版本、scope、限额与账本管理；API Key只能创建时按受控流程展示或用客户端安全交付，后续只显示指纹／轮换入口。

后台运维动作不能替代用户的最终发布授权，不能通过客户cookie模拟登录绕过官方能力限制。无可靠接口则明确导出包／手工交接。

## 28.17 告警、事故、成本止损与恢复

告警定义包括指标、窗口、阈值、数据延迟、去重键、严重度、受影响范围、责任角色、升级路径和runbook。示例：费用速度异常、失败率／排队时间升高、Provider输出即将过期未回收、存储满、索引失败、Webhook积压、账本对账异常、异常内容访问、权限修改。

事故对象关联告警与用户工单，维护开始／发现／确认／缓解／恢复时间、影响、负责人、动作、客户通知与复盘。告警聚合抑制重复，但不能静默吞掉新的高风险事件；“已读”不等于“已恢复”。

紧急操作优先停止新增风险：停派昂贵生成、撤销泄露凭据、冻结敏感导出、限范围隔离问题版本。恢复要验证Provider／预算／队列／版本与权限，分批恢复并观察；不能一个“全部重试”按钮烧掉预算。

备份面板展示最近成功、校验、RPO／RTO目标、演练证据和失败；这些数值是待定运营目标，不是现成承诺。恢复先在隔离环境验证，按环境与风险审批；媒体对象、数据库、账本、删除标记和密钥引用需要一致恢复。生产管理员不能直接从网页触发无预检的整库回退。

## 28.18 审计、隐私与操作证据

管理动作、内容访问、导出、权限变更、审批、密钥轮换和失败尝试都写追加式审计。至少包含actor、有效角色、环境、scope、原因／工单、授权依据、request ID、目标revision、前后摘要hash、费用、结果、审批与证据引用。

审计数据与普通运营备注分离；管理员不能删除自己的行为记录。可采用独立写入权限、定期签名／hash校验和符合成本的不可改写存储加强防篡改，但不得在未实现时宣称不可篡改。完整私密prompt、原件URL、训练样本和Secret不应写进不可删审计；只保存最小必要引用与摘要。

敏感证据本体按保留／删除政策管理；审计留“发生何事”的必要事实，不能利用审计无限复制个人内容。审计导出自身也产生审计，支持按案件／日期／主体限定范围与下载期限。

## 28.19 数据模型与API增量

先盘点复用现存users、workspaces、projects、jobs、provider_generations、credit_ledger、subscriptions、publications、audit等实体。下表仅是逻辑对象，不要求同时创建所有空表。

| 逻辑对象 | 关键关系与一致性要求 |
|---|---|
| AdminPrincipal／RoleGrant／Session | 与客户身份授权域分离，角色变更使对应会话／权限失效 |
| AdminAction／Approval／ActionItem | 固定目标集合、revision、审批与作用域hash，执行幂等、逐项结果 |
| SupportTicket／SupportAccessGrant | 关联客户／项目／动作；限时scope、用途与撤销 |
| MetricDefinition／MetricSnapshot | 定义版本、数据watermark、事实来源与估算覆盖 |
| PlanVersion／EntitlementSnapshot | 订单／订阅引用不可变版本，不改旧订单历史 |
| ReconciliationCase／RefundRequest | 关联外部支付、账本与审批；状态未知须持续核对 |
| PrivacyRequest／DeletionItem／RetentionException | 标记原件、派生、向量、Provider与备份处理；保留例外经审批 |
| ModerationCase／Appeal | 证据scope、规则版本、处置范围和复核身份 |
| StrategyRelease／ModelRelease／ConfigChange | 回归证据、灰度范围、版本、回滚及影响清单 |
| NotificationCampaign／AudienceSnapshot | 用户同意、受众版本、逐渠道去重、退订 |
| Incident／Alert／RecoveryRun | 影响范围、runbook、执行与恢复证据 |
| DataExportJob | 目标行列权限、授权快照、有效期、下载审计 |

API采用现有版本前缀，例如下列**拟新增语义能力**；路径先检查现存路由，等价接口不重复建设。

```text
GET  /api/v1/ops/overview                 # 受控汇总与指标watermark
GET  /api/v1/ops/search                   # 先scope过滤再返回
GET  /api/v1/ops/users/:id                # 脱敏客户视图
GET  /api/v1/ops/workspaces/:id           # 元数据、权益、用量
GET  /api/v1/ops/projects/:id/diagnostics # 默认无私密内容
GET  /api/v1/ops/jobs/:id                 # DAG、attempt、账本引用
POST /api/v1/ops/actions/dry-run         # 风险、diff、作用域与预算预检
POST /api/v1/ops/actions                 # 创建批准请求／低风险动作
POST /api/v1/ops/actions/:id/approvals   # 复核人员独立批准／拒绝
POST /api/v1/ops/actions/:id/execute     # 服务器重查权限与revision
GET  /api/v1/ops/actions/:id              # 状态／逐项结果／费用
POST /api/v1/ops/support-access          # 最小scope／期限／依据
POST /api/v1/ops/privacy-requests        # 数据请求，不直接删资产
POST /api/v1/ops/exports                 # 受控异步导出
GET  /api/v1/ops/audit                    # 特许只读、分页与范围
```

模块专用写接口可以编译为AdminAction，但不得另开无审批的修改路径。所有读写检查环境／角色／对象与Workspace；全平台汇总由明确平台权限读取，不能为了统计暂时禁用租户隔离。账本与退款的副作用使用现有领域服务和Outbox；跨外部系统采用可恢复工作流，不假设数据库事务覆盖第三方API。

后台读模型可缓存／聚合，但标注时效和来源；写后查询状态可能短暂延迟，不能把展示延迟当业务失败重试。功能flag不等同授权校验。CI包含路由权限覆盖和危险写接口归入AdminAction的结构检查。

## 28.20 O0／O1／O2交付顺序与硬门

| 门 | 交付内容 | 对应任务 | 放行条件 |
|---|---|---|---|
| O0 最小安全运营台 | 独立运营认证／角色、AdminAction、审计、客户与项目脱敏诊断、任务恢复、Provider状态、账本／预算查看、资产保护、止损告警、受控支持访问 | N15-01—08、10、12—18、21、24、33、37（以N15-37依赖表为准） | 内部真实制作有人可诊断和止损；关键越权／重复收费／原件保护负面测试通过 |
| O1 对外收费运营台 | 商品／权益、订单订阅、退款对账、客服、账号／团队、隐私导出删除、内容与身份治理、事务通知、发布／Webhook、恢复、敏感导出、生产门 | N15-11、19—27、30—36、38及其依赖 | 不用改数据库解决续费、退款、故障和删除；支付／身份等真实路径按实际启用能力验收 |
| O2 完整运营与AI质量台 | 全价值漏斗／留存、单位成本分析、策略／组件治理、AI质量和评测、配置实验／灰度、营销触达、完整跨角色演练 | N15-09、23、28—31、39—40及其依赖 | 24模块全部有读／写／失败／审计证据；策略／模型的发布治理必须在对应功能上线前提前通过 |

N15不排在N14桌面端之后。它是横切工作流：核心领域契约可用时并行做后台对应模块，避免初期运维依赖SQL。O0不强制完整多机位／GPU内核先完成；O1不要求先有商城或所有客户端。新增模型、身份、公开策略或发布渠道，即使未进入O2，也必须先通过对应操作与审核门。

G0内部真实使用同时要求O0；对外收费G4至少O1及适用隐私／身份／真实Provider门。O2是“详尽运营后台完成”的门，不能用O0已通过对外宣布后台全部实现。运营管理界面分阶段交付，但需求不从账本删除。

## 28.21 端到端运营验收场景

| 编号 | 真实业务场景 | 必须验证的结果 |
|---|---|---|
| O-E01 | 客服收到“视频卡住”工单 | 通过Job ID查DAG和脱敏错误，无需先看用户私片；恢复只重试失败步骤 |
| O-E02 | 重试请求超时并再次点击 | 同逻辑任务不重复付费／发布；未知外部结果进入对账 |
| O-E03 | 客服直接调用退款API | 权限拒绝；申请人不能审批自己；记录拒绝审计 |
| O-E04 | 已获批退款的金额／目标被篡改 | scope／impact hash不匹配，旧批准无效；无外部退款 |
| O-E05 | Provider故障切路由 | 遵守BYOK、隐私地区和生成政策；冻结片不变；新报价越界需确认 |
| O-E06 | 客户“只剪原素材”且支持人员尝试修复生成 | 后端同样拦截；后台无模式绕过按钮 |
| O-E07 | 取得限时只读媒体支持授权 | 只读范围有效；到期或客户撤销后播放／导出与缓存访问失败 |
| O-E08 | 退款Webhook重复／乱序到达 | ledger与权益不重复变更；金额可核对，不超可退余额 |
| O-E09 | 隐私删除涉及原件、向量、Provider和备份 | 状态逐项，无法立即删除明确说明；恢复备份不复活删除内容 |
| O-E10 | 素材GC命中冻结依赖 | 被保护并给出引用，不能因TTL或后台强制回收误删 |
| O-E11 | 新prompt降低成本但误改已锁定片段 | 回归／灰度守护阻止发布或停新调用，旧版本可用且证据完整 |
| O-E12 | 策略下架／权限撤销 | 停止新推荐；历史冻结版本不被改写，后续不可执行需明确报告 |
| O-E13 | 批量提升试用额度和营销触达 | 固定受众、额度总上限、审批、同意／退订、逐项结果、不重复执行 |
| O-E14 | 生产页面错误拿测试凭据执行动作 | 环境及凭据scope拒绝；测试结果不进入生产经营报表 |
| O-E15 | 收入表部分成本未回传 | 显示估算覆盖和差异，不能填零宣称利润上升 |
| O-E16 | 非法跨租户搜索、CSV导出或图片预览 | 读端点／缓存／导出统一拒绝，无敏感结果片段泄露 |
| O-E17 | 员工离职／角色撤销 | 活动会话和审批能力失效；先前授权动作执行前重查 |
| O-E18 | 成本异常紧急止损与恢复 | 仅停止批准scope内新风险；纯剪辑／已交付产物保留；恢复分批有审计 |
| O-E19 | 错误封禁客户并申诉成立 | 恢复对应范围，不丢工程与账单；理由和复核人员可追踪 |
| O-E20 | 事故期间isolated restore演练 | DB／媒体／账本／删除标记一致，实际恢复证据，不凭“有备份”通过 |

以上场景使用至少两个租户、两个不同审批人、多种角色与有权限的真实测试媒体；财务与外部事件先沙箱，生产真实验证只在授权范围。界面按钮、mock全绿或文档状态不能代替实际领域／API／浏览器E2E与外部对账证据。

## 28.22 运营台完成定义与配置决策

每个模块都必须交付：数据模型／API／角色矩阵、列表与详情、作用域搜索、适用操作的dry-run／审批／执行／恢复、错误与空状态、审计、通知、至少一条正常流程和一条负面流程、迁移和runbook。只读模块明确标明没有写动作及原因；不要为了凑功能添加危险操作。

高风险金额阈值、SLA、保留期限、角色委派、部署地区、付款提供商及退款政策、生产RPO/RTO、支持访问期限、营销渠道和语言，全部作为待配置决策登记。缺少真实配置时使用明确测试策略，不在生产默设无限额度、无限保存或自动批准。

“后台详尽”最终以N15-40和O2证据判定：运营人员不用改数据库、不泄露私密内容、不重生成整片，就能处理用户、任务、费用、质量、治理与恢复；客户作品与确认权仍由客户控制。

## 28.23 与黑白设计系统共用组件

本后台服从§29：中性侧栏、清楚文字、合适密度的表格与详情抽屉。24模块不使用彩色KPI卡或装饰渐变，不用全屏大空白降低运营效率。用户/工单/任务/账单/审批/审计等交互走相同控件状态；生产环境、scope和高风险动作必须有明确文字。O门验收功能与安全，D门验收外观与可访问性，不互相冒充通过。
