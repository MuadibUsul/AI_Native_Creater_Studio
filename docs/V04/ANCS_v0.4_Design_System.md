本文件是总规范§29的完整摘录，关联N16-01—12、Design Tokens JSON/CSS参考。不是已实现前端或高保真界面图；UI不改变作品内容主题。

# 二十九、全站设计语言：苹果式极简黑白

**需求来源：[U03] 用户明确要求采用苹果式极简白、黑，不喜欢花哨设计。** 本章将这一偏好落实为ANCS自己的跨端设计规范。参考Apple Human Interface Guidelines的明暗适配与可读性原则，但不是复制苹果页面、商标或专有资源，也不声称得到Apple认证。下面的颜色、字号、间距、动效和布局数值都是**ANCS项目默认值**，不是苹果官方像素规范。[D01][D02]

**一句话：白色、黑色和中性灰承载界面；清楚的排版和空间建立层级；作品本身保留色彩。** 同一套规范覆盖Studio、项目列表、身份设置、Workspace管理、Platform Ops、身份／付款／错误状态、后续桌面和手机。不能只把首页换成白底，内部仍沿用彩色管理模板。

## 29.1 视觉原则与明确禁用项

| 原则 | 应当做 | 不应当做 |
|---|---|---|
| 内容优先 | 最大空间给视频，信息按当前任务出现 | 大型装饰背景、AI吉祥物、抢画面的品牌动画 |
| 单色层级 | 依靠字重、尺寸、间距、边界与明度 | 依靠蓝紫渐变、彩色卡片或霓虹分区 |
| 操作明确 | 一个上下文内有清楚的主操作，其余弱化 | 所有按钮都黑底、所有小动作都做大卡片 |
| 表面克制 | 大部分表面实色，细分隔线，少量必要阴影 | 大面积毛玻璃、流动光晕、拟物浮雕和多重投影 |
| 密度适配 | Studio宽松，Ops表格紧凑但清晰 | 把运营后台做成巨大留白的营销页，或把Studio做成控制台 |
| 可访问 | 焦点、麦克风、错误和危险操作始终可辨识 | 为了干净隐藏取消／错误／键盘焦点，把文字降到看不清 |
| 连贯 | 同组件在各页面使用相同状态和语义 | 每个页面自行设计圆角、颜色和按钮行为 |

禁用装饰性渐变、彩色网格背景、霓虹／发光边框、彩虹AI波形、持续漂浮、循环呼吸光、大面积背景模糊、彩色KPI卡、伪3D图标和装饰性图表。素材内容、必要的色彩工具和操作系统提供的无障碍呈现不受这项禁令误伤。

不默认采用任何特定一代苹果材料效果。用户要的是克制、秩序与精致；不因“苹果风”就引入大面积玻璃或追求最新视觉特效。

## 29.2 浅色、深色与主题行为

提供`system / light / dark`三种外观选择。**首次使用默认跟随操作系统**；未取得系统偏好时回退浅色。用户可以在外观设置中固定白色或深色，不要求首次创作先选主题。

主题优先级为：当前设备明确覆盖 → 已同步的用户偏好 → 操作系统 → 浅色回退。`system`只同步“跟随系统”这个意图，不把一台设备计算出的黑色外观强制同步给另一台设备。偏好加载和服务端首屏需要避免先白后黑的闪烁及hydration冲突；具体实现复用现有前端架构。

浅色以纯白内容面和极浅中性灰分区；深色以近黑底、略浅表面和高可读文字构成，不做整页反相。主题切换不暂停播放、不重建项目、不丢选区、不重提付费任务，也不改视频主题、素材、字幕样式或FrozenManifest。

Apple文档要求分别检查两种外观的可读性，并使用随外观适配的语义颜色；ANCS据此设计两套有明确语义的token。Web提供手动固定外观是本项目选择，不描述成Apple要求。[D01]

## 29.3 颜色Token与对比度

禁止业务组件散落硬编码颜色。使用`ui.*`语义token；UI主题与作品的`contentTheme/brandTokens`分开。原有Tailwind或CSS系统映射到同一token，不新建两份可冲突主题。

| Token | 浅色 | 深色 | 使用约束 |
|---|---|---|---|
| `ui.bg.canvas` | `#FFFFFF` | `#0A0A0A` | 工作区背景 |
| `ui.bg.subtle` | `#F5F5F5` | `#111111` | 轻分区、列表底层 |
| `ui.bg.elevated` | `#FFFFFF` | `#171717` | 弹层／抽屉／局部浮层 |
| `ui.bg.hover` | `#EFEFEF` | `#222222` | hover，不作为唯一可点击提示 |
| `ui.fg.primary` | `#171717` | `#EDEDED` | 主文字、图标 |
| `ui.fg.secondary` | `#595959` | `#B3B3B3` | 说明、次级文字，不能另叠opacity减弱 |
| `ui.fg.muted` | `#666666` | `#A3A3A3` | 有意义的辅助文字；仍需对比度验证 |
| `ui.border.subtle` | `#E5E5E5` | `#262626` | 仅装饰分隔，不独自承担输入框／焦点边界 |
| `ui.border.control` | `#737373` | `#8C8C8C` | 必需辨认的边界／控件 |
| `ui.action.primary.bg` | `#171717` | `#EDEDED` | 主操作实色底 |
| `ui.action.primary.fg` | `#FFFFFF` | `#171717` | 主操作文字 |
| `ui.action.primary.hover` | `#383838` | `#FFFFFF` | 主操作悬停底（2026-10-14 界面精修新增） |
| `ui.selection.bg` | `#E8E8E8` | `#2A2A2A` | 列表选中底，另加线条／勾选／文字 |
| `ui.focus.ring` | `#171717` | `#EDEDED` | 焦点边界；相邻颜色不足时使用双层环 |
| `ui.media.matte` | `#0A0A0A` | `#0A0A0A` | 看片区域外垫底，不改变视频像素 |

> 2026-10-14 界面精修：深色层级加深（subtle/elevated/hover/border/selection），新增主操作悬停、阴影层级、缓动与等宽字体 token；取值以 `ANCS_v0.4_Design_Tokens.json` 为准，说明见 `docs/design/ui-refresh-2026-10.md`。

普通有意义文字对实际相邻背景的对比度至少4.5:1；关键操作、控件辨识和必要图形边界按适用规则至少3:1；重要正文优先更高对比。不能把`border.subtle`当成唯一输入框边界。WCAG关于文字、非文字和不单独依赖颜色的要求分别见[D03]—[D05]。实际控件还需浏览器检查，token计算通过不等于整个产品已达无障碍标准。

禁用组件可以使用专门的低强调外观，但禁用原因仍用可读文字提供；不可仅让用户猜为什么按钮无效。深浅模式、hover、selected、focus、error和loading都要检查实际组合，而不是只测白底正文。

## 29.4 字体、中文排版与数字

UI默认采用合法可用的系统字体栈：

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
  "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif;
```

该栈只引用用户设备可用字体，不下载、打包或分发Apple字体文件。Apple字体有特定许可，不因“苹果风”假定可作为Windows/Web项目字体嵌入；采用第三方字体或图标前逐项记录许可。[D02] 输出视频使用何种字体是独立的作品资源与授权问题，UI的系统字体不能被隐式当成云渲染已有字体。

| 文本角色 | 默认尺寸／行高 | 字重 | 场景 |
|---|---|---|---|
| 页面标题 | 28/36px；小屏24/32px | 600 | 项目列表／后台模块标题 |
| 区域标题 | 18/26px | 600 | 抽屉／表格分组 |
| 主正文／对话 | 16/24px | 400 | 用户说明、AI简短回应 |
| UI正文／表格 | 14/22px | 400或500 | 控件、后台列表 |
| 辅助标签 | 12/18px | 400或500 | 时间、元数据；不承载长段正文 |
| 重要金额／指标 | 24/32px | 600 | 少量必要统计，不铺满超大数字 |

以`rem`实现可缩放排版；中文不默认负字距、不用超细字重。主要控件不低于14px，12px仅限非主任务短标签。金额、时码、进度、版本使用tabular numbers；代码／技术ID只在需要时用等宽字体。长文件名可截断，但完整值有可访问查看方式；币种、负号和小数不能截掉。中文／英文／数字混排、长译文和字体回退都要测试。

## 29.5 间距、形状、密度与图标

基础间距尺度：4、8、12、16、24、32、48、64px。页面常规边距24px，小屏16px；宽屏工作区可32px。通过合理分组与对齐形成层级，不为每块文字加边框卡片。

圆角建议：小控件8px，常规控件10px，抽屉／模态16px；pill只用于有需要的紧凑状态／组合控制，不把所有表面做成胶囊。作品画布尊重实际宽高比，圆角或窗口装饰不得裁掉可见边缘，更不能进入视频导出。

默认按钮视觉高度40px；桌面密集工具可32px，触控点击区域至少44×44px，且不得与邻近动作重叠。范围拖柄有更大不可见命中区和数值替代入口，不能要求每个人都准确点击1px线。上述尺寸是产品基准，并非声称所有尺寸来自Apple或WCAG。

图标使用统一stroke、光学尺寸和圆角，16/20/24px为主要尺度。沿用已许可图标库或自有SVG；不从苹果软件抓取图标，不把SF Symbols当成无条件跨平台可分发资源。危险／不熟悉操作需文字，hover tooltip不能作为唯一说明。

阴影只服务浮层层级；静态卡片默认无阴影。无层级必要不使用模糊，未支持透明或用户要求降低透明时保持清晰实色。

## 29.6 控件与状态：黑白不等于没有反馈

统一组件至少涵盖Button、IconButton、Input、Textarea、Select、Switch、Checkbox、SegmentedControl、Tabs、Popover、Dialog、Drawer、Toast、StatusBadge、Progress、DataTable、CommandPalette和EmptyState。复用现有UI实现，按组件的所有状态迁移，不另建不可互操作组件库。

主按钮浅色黑底白字，深色浅底深字；次按钮为清晰边界或轻底，文字操作保持可辨认。链接使用下划线、位置和上下文，不用蓝色作为必要标志。可点击性不能完全依赖hover。

| 状态 | 黑白表达 | 行为约束 |
|---|---|---|
| 保存中／生成中 | 静态文案＋细进度／小型旋转标记 | 真进度才显示百分比，未知时间不造倒计时 |
| 麦克风监听 | 明确麦克风图标＋“正在聆听”＋停止入口 | 不能藏在仅一条呼吸动画中，关闭后立即停止采集 |
| 已保存／已采用 | 勾形符号＋明确文字，必要短暂出现 | 不抢焦点，不重复播报 |
| 失败／警告 | 警示符号、标题、原因、可恢复动作 | 不仅靠红色，也不自动消失关键错误 |
| 已选中 | 对比边界／勾选／标签／填充之一组合 | 与hover区分，键盘可识别 |
| 无权限／禁用 | 锁／不可用符号＋原因 | UI隐藏不替代后端权限 |
| 危险操作 | 独立区域＋具体动词＋影响摘要＋确认 | 黑白主题不能削弱退款、删除或发布的审批 |

不使用红／绿／黄状态卡作为默认风格。错误和告警用明确文字、图标、边界和层级区分；系统高对比模式或关键专业色彩编码可以按语义保留。任何必要色彩例外都不得以颜色作为唯一信息通道。[D05]

输入错误要在字段旁说明，不能只改变边框颜色。键盘焦点至少有清晰2px轮廓；遇到黑色主按钮／复杂视频背景时加对比色间隔或黑白双线，确保焦点与对象位置仍清楚。

## 29.7 Studio共看片室应用

初始画面只有作品区域、轻量顶栏和底部交流／播放区。作品名、保存状态、交付入口有稳定位置；不用大标语、大统计卡或多栏默认布局。

空项目是干净的拖放与表达入口：“放入素材，或说说你想做什么。”声音、数字人、封面、规格已配置时静默继承；没有身份也能直接剪辑。必要说明逐步出现，不塞进首次表单。

视频显示原色。选中对象时显示黑白双描边、细定位线和简短标签；选框是交互层，不能烧进输出。框选、暂停、点选和语音状态不以闪光/放大背景庆祝。AI提问就近放在不遮关键画面的浮层，完整对话和笔记按需展开。

底部语音入口使用简洁麦克风和文字，允许有克制的单色音量反馈；不显示彩虹能量球。试改采用／拒绝只围绕当前方案，通常一个主操作。全片审阅时制作工具退场，但暂停、停止监听、标记和退出始终可达。

## 29.8 专业时间轴与Inspector应用

收起时只显示播放头与所选时间范围；展开后完整提供多轨、音频波形、字幕、关键帧、曲线、蒙版和精确数值，不通过简化设计删字段。

轨道和片段默认用中性明度、名称、类型图标、线型和选中边界区分。素材缩略图保持原色；用户明确设置的Clip颜色标记可作为可选工作工具保留，不变成全站彩色皮肤。密集时间轴不堆阴影、玻璃面或持续动效。

Inspector按对象分组；数值与单位对齐，拖动与直接输入同一操作，重置／继承状态清楚。控制曲线与其名称不能靠颜色区分，键盘和数值入口等价。双线选区和命中变换在暗片、亮片、透明素材上测试。

## 29.9 运营后台、设置与身份录入应用

运营台使用中性侧栏、标题、简洁过滤区、清楚表格和详情抽屉。信息架构仍按§28的六组／24模块，不因为“极简”隐藏财务对账、失败恢复、审批、审计等关键能力。

后台提供Comfortable／Compact两种密度，建议行高48px／36px；触控使用较舒适密度。少量重要指标直接排版，默认不使用彩色KPI卡、渐变图表或过多圆角卡片嵌套。表头、冻结列、选中行、排序、分页和批量范围都要明确；金额等宽对齐，估算／实际／缺数值有文字。

生产环境、操作者角色、当前租户scope、支持访问期限采用持续可见的中性标签和明确文本。测试／生产不只用颜色区分。退款／删除／重试抽屉保留完整对象、金额、币种、范围、风险、审批与进度，不为减少文字而省去安全信息。

Workspace设置采用有层级的表单与简短说明。声音／数字人录入可以逐步引导、试听和确认，授权／上传／验证错误完整呈现；不得为了空白感把必需信息隐藏在tooltip。付款页面沿用同样风格，清楚显示软件费、计算费、续费与取消规则。

## 29.10 数据图表、作品内容与主题隔离

运营图表默认黑白灰，以实线／虚线、点形、填充纹理、直接标签和工具提示区分系列；同图过多系列时用筛选、小多图或数据表，不使用难区分的十种浅灰。数据含义、币种和时间窗必须明确。重要曲线和点对背景达到适用图形对比要求。[D04]

作品预览、封面、用户品牌、素材缩略、色轮、LUT效果、视频示波器等有色彩含义的内容保留其必要颜色。财务涨跌可用正负号／箭头／“增加/减少”，不强制红绿。

**禁止给`body`、Studio根节点、播放器父节点或后台内容区添加全局`grayscale()`、`invert()`、`brightness()`来实现主题。** 不因深色界面而压暗原片，不自动修改图表数据色彩。需要调色预览时作为明确专业视图记录，不把临时监看变换混入正式导出。

UI换主题只改变`ui.*`及界面表面，不改变ProjectDocument内容hash、生成参数、资产checksum、已批准画面或费用。允许透明图像查看器调整棋盘格背景，但必须清楚区分背景和内容本身。

## 29.11 动效、反馈与性能

建议默认：hover/focus反馈100—150ms，popover／小浮层120—180ms，抽屉180—220ms；使用简单opacity／transform过渡，不默认弹簧回弹、长距离滑动、计数滚动和连续背景动画。以上都是ANCS默认值，可按实测调整但不能牺牲可访问性。

响应`prefers-reduced-motion`：移除非必要位移、缩放、弹簧和自动动画，保留即时状态与可读文字。界面动画不得阻塞用户暂停、停止语音、撤销或取消任务。切主题默认即时或极短颜色切换，不做整屏闪烁。

画布内的作品动画是创作内容，不受UI禁动效规则直接改写；播放控制和用户低动效设置应有清楚边界。长任务仍提供真实状态，不能用精美loading遮住错误。

主题与布局改变不得重建解码管线或大量GPU纹理；抽屉开关不触发整片重新渲染或Provider调用。继续满足§20性能目标，记录UI、媒体和云生成分别耗时。

## 29.12 工程落地与兼容

设计token是唯一视觉常量来源，组件使用语义引用。优先复用现存`globals.css`、Tailwind配置和UI组件。可在需要时新增`design-tokens`逻辑模块，但不为“设计系统”重复创建整个前端。

token分为primitive中性尺度、semantic语义、component组件引用。浅深主题键集合一致；所有例外有用途与审查记录。媒体／内容主题命名空间隔离，颜色校验不得把用户合法内容颜色当UI违规。

包内`ANCS_v0.4_Design_Tokens.json`与`.css`是实现参考，已检查语义值和指定色对的静态对比；**尚未集成进仓库，也未通过浏览器组件验收**。SSR外观初始化、系统主题监听、forced-colors、键盘焦点与Native适配由任务实施。

旧界面逐模块替换，复用业务事件和SDK。不要一次性删掉旧表单导致功能丢失。每个组件完成light/dark、各状态、键盘、触控、长中文、200%缩放等验证后再替换旧入口。原始v0.3任务编号不变，N16为横切设计工作流，不在商城／所有App之后才开始。

## 29.13 设计验收门与样例

| 门 | 要求 | 对应任务 |
|---|---|---|
| D0 视觉地基 | token、合法字体／图标、主题逻辑、基础控件、清晰状态与内容隔离 | N16-01—05、N16-10；基础实现随新UI同步 |
| D1 Web设计完成 | Studio、专业面板、Workspace和运营后台全部使用共享规范，功能／权限完整 | N16-06—12；对外Web设计声明前通过 |
| Native设计适配 | 复用语义规范，适配系统控件、触控、可访问和播放能力 | N14对应任务＋N16规范，不把Web截图等同App验收 |

N16任务号不代表排在N15完整后台之后。基础token／主题和共享组件先做；专业面板和后台具体模块随各自能力上线验收，完整D1最后汇总。避免等待整个UI全改完才验证核心素材剪辑，也不能等产品做完再全站换皮。

| 编号 | 验收场景 | 通过条件 |
|---|---|---|
| D-E01 | 浅／深／系统主题、刷新、不同设备 | 无错误闪屏；系统模式随设备，用户覆盖有效 |
| D-E02 | 有意义正文、标签、输入与焦点 | 静态色对＋实际组件可读，键盘焦点不被裁切 |
| D-E03 | 黑片／白片／彩色视频中框选对象 | 黑白双线仍清楚，范围绑定正确，视频像素不变 |
| D-E04 | 对话、录音、长任务、取消和失败 | 黑白状态清楚且可操作，无虚假进度 |
| D-E05 | Ops退款／删除／批量重试 | 权限、范围、金额和危险后果完整；无彩色依赖 |
| D-E06 | 十条指标系列和缺失数据 | 线型／标签／分图／表格可读；缺失不填零 |
| D-E07 | 长中文、长文件名、混排、200%缩放 | 不截断关键内容；必要横向时间轴不影响表单可用 |
| D-E08 | Reduced motion／高对比／纯键盘／触控 | 无不可达功能，不禁止系统高对比覆盖 |
| D-E09 | 切主题／开抽屉／切租户 | 播放、选区和提案保留；不重生成、不漏旧租户内容 |
| D-E10 | 原片、生成片、图表、封面与调色工具 | UI单色不改变素材色彩或输出；各内容主题独立 |
| D-E11 | Windows／macOS浏览器与字体回退 | 无Apple字体下载或打包依赖；布局可读，不要求像素完全相同 |
| D-E12 | 已有24后台模块与专业能力页面巡检 | 共用组件，未出现彩色模板残留；旧能力不因改版丢失 |

不能仅凭一张设计稿或静态截图宣称设计系统完成。验收需要组件所有状态、真实浏览器、媒体播放、交互、可访问性和业务回归。对比度脚本通过只代表所测token组合，不代表整站符合WCAG。

## 29.14 设计依据与可交付边界

[D01] Apple HIG / Dark Mode：`https://developer.apple.com/design/human-interface-guidelines/dark-mode`。本轮读取；用于两种外观分别设计、语义颜色与可读性，不用于推出“苹果只用黑白”的事实主张。

[D02] Apple Fonts：`https://developer.apple.com/fonts/`。本轮读取；Apple字体许可有使用范围。本项目选择系统字体回退，不随文档或代码分发字体文件。

[D03] W3C WCAG 2.2 / Contrast Minimum：`https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html`。本轮读取；普通文字4.5:1、大字适用3:1等具体条件按原规范，ANCS有意义小字继续采用4.5:1。

[D04] W3C WCAG 2.2 / Non-text Contrast：`https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html`。本轮读取；必要控件和图形辨识按适用3:1规则验证。

[D05] W3C WCAG 2.2 / Use of Color：`https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html`。本轮读取；信息不可仅由颜色传达。
