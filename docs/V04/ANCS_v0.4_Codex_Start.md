### 产品方向

产品是“生活在屏幕里的视频大师”。用户负责创意、指点和审美取舍；AI负责理解、专业判断、制作、试改、回放、提问、记住决定和交付。默认界面是同一块共看片画布，鼠标定位＋语音／文字表达诉求；复杂工具按需出现，不降低专业能力。

必须支持用户上传真实素材并完成非破坏性剪辑。`FOOTAGE_EDIT`、`GENERATIVE`、`HYBRID`使用同一工程内核。只剪素材时可明确禁止新画面、重配音、改原话、生成填充或插帧。文章转长视频只是入口之一，不能继续当唯一主链路。

用户可直接用鼠标／触控／键盘作精确操作；不能强制全部用文字或语音。PR／剪映级高级关键帧、多轨、专业音频、蒙版跟踪、调色、多机位、变速、合成、格式与工程交换都属于覆盖目标，分阶段交付，不再沿用永久“不做”边界。

AI局部试改在提案版本中进行。已确认内容与资产保留；用户采用才原子更新确认版；完整审阅后冻结实际素材与工程，最后正式合成，不能到导出时重新抽奖生成未批准镜头。

导演策略生成器从合法参考链接／文件提取两份产物：可追溯的参考蓝图、可迁移执行的策略包；等效重建和内容迁移分别验证。不只生成风格提示词，不声称找回原作者工程。

### 执行顺序

按任务级依赖、强制安全门与真实完成证据选择下一项：N00 → N01/N02 → N03 → N04/N06 → N05/N07 → N08/N09 → N10 → N11/N12。N13从最早写操作和付费调用开始嵌入；N15运营、N16设计都是横切工作流，也不能留到末尾。N14-01/02是旧功能回归，随迁移及时运行。

首次接手应完成N00可执行项并尽可能推进第一个可验证内核任务，不只输出第二份计划。每次会话集中交付一个或少量依赖齐备的垂直切片；不要同时重构整个前端、改完所有模型、接入全部供应商。

若已有某项的实现，先读代码并补齐要求的验证，不重复开发。若部分依赖缺失，完成不受阻的子项，记录准确阻塞；不要把缺少API凭据当作删除需求的理由。

### 架构要求

- ProjectDocument为唯一作品状态，语义Scene与专业Composition相互引用，不维护独立“AI工程”和“时间轴工程”。
- 保留现有revision、事务、EditEvent、Outbox与补偿式undo/redo。扩展源素材范围、序列范围、轨道、对象、效果、关键帧、精确时基和范围锁。
- 分数帧率、VFR、源PTS和音频采样不能继续靠整数fps或反复浮点秒换算；旧毫秒数据要可兼容。
- 选择绑定对象、预览revision、媒体时间和发话时间；不能拿语音返回时鼠标位置解释“这个”。
- 试改记录可以落库，但采用前确认工程不变；锁和依赖检查覆盖reorder/ripple/global style等间接影响。
- 停AI说话、取消提案和取消外部生成分别处理；晚到结果不覆盖新版本；取消不等于退款。
- 最终审阅必须看到实际关键资产；冻结后不重新写脚本或生成镜头。跨设备／编码器不无依据承诺bit-exact。
- 原素材不可覆盖，缓存清理不能删冻结依赖；长期Key不进前端，短期Realtime凭证不代替后端授权。
- 所有媒体生成、分析、语音、LLM规划、试改、转码、重试、合成均纳入适用账本；没有媒体生成不等于零成本。
- 外部文章、字幕、参考视频、模型输出、策略和代码都是不可信数据，不能授权发布、付款、删除或泄露密钥。
- 仅在有效预算、账号权限与用户许可下运行真实付费调用。无凭据用明确Mock做结构测试，真实能力保持未验证。

### 本轮新增执行约束

上传方案的P15—P23/T1—T6仅映射到本包N任务，不能重编号已有126项任务或清空进度。v0.4合并了41项编辑架构增量、40项运营任务、12项设计任务；每个任务状态以真实代码和证据更新，本包初始TODO不得覆盖已验证记录。

- **Media Index：** 统一源时间、版本、ASR、镜头、对象/动作/人物轨迹、文字、音频事件、节拍和检索证据；逐阶段可用，用户纠错不被重分析覆盖。操作指令里的“举起手机”必须定位真实源区间。
- **Playback/Render：** 先标准proxy和可验证回退，再按需WebCodecs/WebAudio/GPU；同一RenderPlan支持FFmpeg媒体/音频和Remotion图形；不强行所有原视频逐React帧渲染，也不删现有有效链路。
- **单一权威：** SelectionAnchor包含在AttentionSnapshot；MediaSource/ClipInstance是已有源资产/Clip的规范映射；PreviewBranch是Proposal实现。禁止平行状态、两个编辑执行器或两份Undo。
- **Agent：** Tool Registry与GUI/快捷键共用Edit Operation；先trim/move/split/transform/caption-position五工具持续试改。Reject不改变正式编辑历史，但实际费用/任务/审计仍留记录。采用只来自有效用户确认。
- **生成修复：** 九类修复分能力、范围、mask、原音、身份、报价、派生血缘和连续性验收；无真实Provider证据保持未验证。纯素材禁止生成同样约束后台。
- **运营后台：** §28的24模块分Studio/Workspace/Platform Ops权限域。N15统一AdminAction、dry-run、风险审批、幂等、副作用对账与审计；客服默认脱敏，不冒充用户接受/发布，不明文取Key，不直接改余额/DB。G0内部使用需O0，对外收费需O1；完整后台需O2。
- **设计语言：** §29为全站约束。Studio/专业控件/Workspace/Ops全部用苹果式极简黑白灰；白黑主题、系统字体、统一层级/留白/控件、短反馈。禁止装饰渐变、霓虹和彩色模板；后台保留密集表格效率。UI主题不改变素材原色、用户作品主题、FrozenManifest或费用。错误、录音与危险动作靠文字/图标/边界清楚表达。
- **设计落地：** 复用现有样式和组件，逐项迁移；包中token JSON/CSS仅参考，未集成/未浏览器验证。系统字体不等于可分发Apple字体；不下载或打包字体。D0基础同步实施，D1全站设计另验，不用完整设计总门阻塞所有基础剪辑任务。
