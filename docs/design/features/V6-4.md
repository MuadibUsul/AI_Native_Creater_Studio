# V6-4 UI 交付卡｜批注式审片（手机网页优先）

**归属：** V6-4 批注式审片 + 统一局部重渲（`docs/V06/milestones/V6-4.md`）；V6 §5.4。
**状态：** IN_PROGRESS —— 界面与服务端闭环已在真实浏览器（手机 390×844 触屏 + 桌面 1440×900）+ 真实 FFmpeg 上验证；讨论与执行中的 AI 是**脚本导演（SCRIPTED）**，真实 Claude 的方案与修改质量未验证；语音批注随 V6-2。

## 用户目标与角色

- 创作者（OWNER/ADMIN/EDITOR）在手机或电脑上看完一条视频：逐处标记问题（位置 + 一句话，可框出画面里的位置）→ 逐条问 AI 怎么改并确定方案（或交给 AI 决定、或不改）→ 全部执行，一次改完 → 看试改，"就这样"或"不要了"。
- 只读成员可以看、播放、看批注与讨论；不能标记、讨论、执行或采用（服务端拒绝为准，界面给出只读说明）。

## 真实入口

- `/w/:workspaceId/review/:projectId`（单屏，自带顶栏；不套用侧栏）。
- 共看片室顶栏"审片"进入；手机上可"添加到主屏幕"（`/manifest.webmanifest`，独立窗口；不做离线缓存——审片读写的是服务端当前状态）。

## 主流程 / 锁定 / 恢复

1. 播放当前版本（服务端 540p 预览；原生控件，手机上可拖动——依赖存储端点的字节范围）。
2. "在这里标记"：默认这一刻前后各 1 秒，可前后各挪 1 秒；可在画面上拖出一个框；写一句话 → "添加批注"。批注指向这一刻画面上的片段。
3. 每条批注："问 AI 怎么改"（AI 只给方案，不改作品）→ "就按这个改"（把 AI 最近的方案定为方案）/"交给 AI 决定"/"不改了"/"重新打开"/删除。
4. "全部执行（n 条）"：只包含已确定的批注；未确定的给出提示。执行期间与试改待采用期间批注锁定（服务端 409，界面说明原因）。
5. 改好了：播放器回到视野，播放试改（明确标记"按批注修改后的试改 · 还没采用"），显示"只重渲了改动的部分（复用 x/y 段）"；"就这样"按看过的操作哈希采用，"不要了"撤回（批注保留，可调整后再执行），也可以去共看片室继续微调这份试改。
6. 采用后：批注标为"已改"，说明新版本号；再标记会在新版本上开始新一轮。

## 状态矩阵

| 状态 | 表现 |
|---|---|
| 加载 / 加载失败 | 状态行；失败给重试与回共看片室 |
| 视频没有内容 | 播放区说明先去共看片室剪第一版；不能标记 |
| 预览渲染中 / 失败 | 播放区说明 |
| 没有批注 | 说明 + 使用方法 |
| 标记中 | 表单（位置、前后挪动、框选、文字）；框选时画面上出现拖框层，原生控件暂时隐藏 |
| 讨论中 | "AI 正在想…"；同一会话同一时刻只处理一件事（忙时说明） |
| 已确定 / 不改了 / 已改 | 状态标签；方案行（AI 回应已以"方案："开头时不重复前缀） |
| 执行中 | 底栏进度说明；批注锁定 |
| 试改待采用 | 试改标记、复用分段说明、就这样 / 不要了 / 去共看片室继续微调 |
| 上次执行没成功 | 原因：失败 / 被停止 / AI 没做改动（附 AI 的说明）/ 上次的修改没有采用 |
| 已采用 | 新版本说明；新标记开新一轮 |
| 只读 | 说明，无写操作 |

## 中英与可访问性

- 全部文案在 `apps/web/src/i18n/messages.ts` 的 `review`（中英同结构，类型检查保证不缺键）。
- 时间标签按钮有可读名称（"跳到 00:03.5–00:05.5"）；拖框层是 `role="application"` 并有名称；输入框 16px（避免 iOS 缩放）；底栏留出安全区。
