# N02-11 UI 交付卡｜媒体分析阶段与局部恢复

1. **用户目标、角色和空间**：创作者在工作区素材库确认一段媒体何时可播放、何时可做确定性剪辑，以及哪些增强分析失败或尚未启用；失败时只恢复受影响阶段。
2. **入口与范围**：沿用 `/w/:workspaceId/assets` 与项目素材页。用户打开素材详情后，在媒体能力和播放器附近查看“渐进分析”；没有新增独立页面。
3. **主流程与状态**：11 个固定阶段显示未请求、排队、处理中、部分完成、就绪、无结果、失败、未启用、等待重建、取消中和已取消。运行阶段可取消；失败、失效或取消的已支持阶段可单独重试。探测完成后，即使 ASR 或深度检测失败，素材仍明确标为“可剪辑”。
4. **权限、费用和恢复**：读取要求 `workspace:read`，重建和取消要求 `asset:manage`；domain 再次按 workspace 过滤。未知预算保持未知，不显示伪造的零费用或进度。配置变化只失效所选阶段及下游，已完成的无关阶段继续复用。
5. **设计覆盖**：**扩展**现有素材详情的 panel、badge、text button 和错误提示；窄屏沿单列排布。没有建立后台式分析页面。浅色、深色、390 px 窄屏和低动效均沿现有 Token。
6. **业务与验收证据**：真实 PostgreSQL、真实 FFmpeg probe、真实 Worker 失败路径、API/SDK、崩溃租约恢复、跨租户和 Playwright 浏览器链路；详见 [`docs/verification/N02-11.md`](../../verification/N02-11.md)。

## 单一状态与恢复边界

- `media_analysis_stages` 是现有 probe/proxy/index/transcript 运行记录的阶段投影和检查点，不复制媒体事实或检测结果。
- `PROBE/PROXY/WAVEFORM/ASR/SHOT` 连接现有真实处理链；尚未接入的 Sampling、Vision、OCR、Audio、Embeddings 和 Search Index 明确显示 `DISABLED`。
- Media Index 物理处理崩溃后复用同一 run 和稳定记录 ID，按 `(run, kind, ordinal)` 幂等补写；租约恢复不会重复生成逻辑记录。
- WAVEFORM 与 SHOT 当前由同一个本地 FFmpeg index 处理器完成，但阶段状态、依赖、配置 hash、检查点和下游失效均分别投影；N02-12/13 接入新检测器时沿此 DAG 扩展。
