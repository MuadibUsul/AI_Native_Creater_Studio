# N02-13 UI 交付卡｜音频事件、节拍与声画时间关联

1. **用户目标与角色**：Workspace 创作者按拍手、环境声或音乐节拍查找真实素材区间，回放原始声画，并把确认结果保存为人工片段标签。
2. **入口与作用范围**：沿用 `/w/:workspaceId/assets` 与 `/w/:workspaceId/p/:projectId/assets` 的“搜索真实片段”、素材播放器和详情；记录绑定具体素材版本、音频流和源 PTS。
3. **主流程与恢复**：上传视频 → Probe 后异步执行 Audio analysis → 搜索“拍手” → 查看机器推测与精确源范围 → 播放实际声画区间 → 添加人工确认标签。音频分析失败时原件和已完成分析保持可用，可在“渐进分析”中单独重试音频阶段。
4. **权限与边界**：沿用 `workspace:read`/`workspace:update`；分析只读源媒体，不改写或归一化原音。机器事件和节拍只作为检索证据，不自动改变剪辑、项目版本或人工确认状态。
5. **设计覆盖**：**沿用**素材库、片段搜索、播放器、标签和阶段抽屉；**扩展**音频事件阶段、AUDIO 搜索结果和声画关联证据；没有新增页面或第二套媒体状态。
6. **状态与交互**：覆盖排队、运行、READY、EMPTY、FAILED、DISABLED；非音乐允许零节拍，tempo 变化逐 beat 保存，独立音轨保留 stream/timebase；搜索空态、失败与重试沿用现有恢复路径。
7. **业务与验收证据**：真实 PostgreSQL、用户 MP4、FFmpeg Probe、Worker 音频 Adapter seam、统一 Media Index、搜索/源范围播放/人工确认及 Playwright 浅色桌面和深色窄屏；详见 [`docs/verification/N02-13.md`](../../verification/N02-13.md)。Scripted Adapter 只证明 I/O seam 与产品链路，不作为第三方音频模型实测。

## 复用组件

- `DeliveryAssets`：音频搜索结果、实际声画播放、人工范围标签和阶段恢复。
- `media_analysis_stages`：Audio 阶段的权威状态和局部重试。
- 统一 Media Index：音频事件、beat/downbeat、分段 tempo 与视觉记录共用权限、证据、读取和搜索投影。

## 视觉判断

- 音频候选沿用中性“声音 / 机器推测”语义，不增加波形装饰或彩色 AI 元素。
- 精确范围继续使用毫秒显示；播放器保留视频原色和原始音轨。
- 手机窄屏依次显示人工确认与机器候选，搜索、播放和证据不横向溢出。
