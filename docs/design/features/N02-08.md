# N02-08 UI 交付卡｜缺失媒体、重新链接与外部回绑

## 用户目标与入口

1. **用户与空间**：Workspace 内拥有素材管理权限的创作者，需要让已离线的原件重新可用，同时保留既有剪辑和来源关系。
2. **入口与对象**：`/w/:workspaceId/p/:projectId/assets` 的素材详情；对象是一个逻辑 Asset、其不可变 AssetVersion，以及用户已上传并完成探测的候选素材。
3. **主流程与恢复**：打开离线素材 → 选择缺失版本与候选素材 → 校验内容、时长和轨道 → 精确原件直接恢复，或对不同文件输入“确认替换”后建立新版本。取消时关闭详情或停止操作，原离线引用不变。
4. **权限与条件**：读取要求 `workspace:read`；执行要求 `asset:manage`。候选必须属于同一 Workspace、可读取且已完成媒体探测。跨租户资源统一不可枚举。
5. **设计覆盖**：**扩展**现有素材详情，复用 Panel、Badge、Field、Select、Button 和确认输入；没有新增页面。桌面并列比较在窄屏收为单列，媒体本身保持原色。
6. **真实依赖与证据**：PostgreSQL、Fastify、SDK、LocalSignedStorage、FFmpeg、production Next、Chromium，以及用户提供的真实 MP4。该切片不依赖第三方 Provider。

## 状态与行为

- `ONLINE`：所有保留版本可读，无需重新链接。
- `MISSING`：至少一个保留版本的对象不存在；继续显示缺失版本、活动引用和既有派生关系。
- `EXACT_RESTORE`：候选实际 SHA-256 与缺失版本一致。把候选内容复制回原不可变版本的存储位置，旧 `assetVersionId`、Clip 源范围和代理关系均保持不变。
- `REPLACEMENT`：校验和不同。UI 显示校验和、时长和音视频轨道差异，要求输入“确认替换”；服务端建立新的 AssetVersion，保留旧离线版本和引用，并把相关 Scene 标记为需要审阅。
- 文件名只用于识别，不能触发自动替换。候选在预检和应用时都重新读取实际对象并计算校验和，避免过期预检静默覆盖。
- 应用结果写入只增不改的 `asset_relinks` 审计行；公开 DTO 不返回存储键或签名 URL。

## 复用组件与契约

- `AssetRelinkPanel`：缺失版本、候选、差异和明确确认。
- `AssetRelinkState / AssetRelinkPreflight / AssetRelinkResult`：客户端和服务端共享的状态、预检与结果契约。
- SDK：`relinkState`、`preflightRelink`、`applyRelink`；上传意图可携带 `relinkTargetVersionId`，使缺失原件的同 hash 候选可以进入隔离版本。
- `ObjectStorageAdapter.copyObject`：受控存储内部复制 seam；本地实现使用临时文件和原子重命名。
- 迁移 0070：`asset_relinks` 审计、候选/目标版本、校验事实、实际动作、新版本、保留引用和审阅状态。
