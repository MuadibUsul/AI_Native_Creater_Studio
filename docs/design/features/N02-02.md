# N02-02｜媒体探测与格式能力状态

日期：2026-10-09。覆盖类型：**扩展**。

## UI 交付卡

1. **用户目标、角色与空间**：创作者或编辑者上传音视频后，能够知道原件是否可解码、可直接预览或需要代理，并在失败时保留原件和可执行的恢复路径。
2. **入口、对象与范围**：`/w/:workspaceId/p/:projectId/assets` 的素材列表与素材详情；对象是当前工作区、当前项目内不可变的 SourceAssetVersion。
3. **主流程与恢复**：上传确认 → 系统媒体探测 → 素材进入可用或需要处理状态 → 详情显示上传、解码、预览、导出四类能力。探测失败不会删除原件；用户可以下载原文件检查、转换后重新上传。需要代理时明确展示原因，代理生成由 N02-03 承接。
4. **权限、费用与限制**：上传仍要求 `asset:manage`；探测是系统 Job，不触发 Provider 费用。工作区、项目、素材和版本查询全部携带 workspace scope。系统不因扩展名宣称格式可用，也不把工具路径或原始 stderr 暴露给用户。
5. **设计覆盖**：沿用素材页、现有 Modal、Button 和语义 Token；扩展素材状态与详情能力区。没有新增页面；窄屏采用两列能力网格，播放器仅在探测确认可直接预览时出现。
6. **业务依赖与验收**：真实 PostgreSQL、Fastify、LocalSignedStorage、生产 Next、Chromium 和本机 FFmpeg/ffprobe；浏览器使用真实 MP4 与损坏样例完成处理中、成功、失败及原件恢复验证。

## 状态与交互

| 状态 | 呈现 | 合法操作 |
|---|---|---|
| `PENDING` / `PROCESSING` | “正在分析”，不虚构进度 | 查看、等待；原件已确认后可下载 |
| `READY` | 显示流、编码、时基、帧率／VFR、旋转、色彩和声道；按能力决定是否显示播放器 | 播放可用代理或原件、下载原件 |
| `FAILED` | 稳定的失败原因和下一步，不显示内部工具输出 | 下载原件、转换后重新上传 |
| `PROXY_REQUIRED` | 明确说明直接预览不可用 | 保留原件，等待 N02-03 代理生成 |

能力区分别显示 Upload、Decode、Preview、Export，未知能力保留 `UNKNOWN`，不伪造“可用”。视频和音频缩略、播放器内容保持原色；浅色、深色及窄屏均沿用全局黑白语义层。

## 组件与契约映射

- `DeliveryAssets`：本地化素材状态、探测详情、失败恢复与受能力约束的播放器。
- `SourceMediaProbe`：worker 的隔离媒体探测 seam；默认实现通过子进程执行 ffprobe 和完整解码检查。
- `MEDIA_PROBE` Job：上传确认事务内创建的系统任务，不受付费任务并发限制。
- `AssetVersion.mediaProbe`：保存源流事实和能力摘要；原素材对象与 checksum 保持不变。
- `StorageProvider.materializeObject`：以流式方式将原件提供给探测进程，避免整文件进入内存。

证据见 [`N02-02 verification`](../../verification/N02-02.md)。
