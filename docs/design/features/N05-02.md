# N05-02 UI 交付卡｜语音采集、转写与时间对齐

**归属任务：** N05-02（语音采集、转写与时间对齐）。
**来源需求：** `docs/V04/ANCS_v04_Mouse_Voice_Incremental_Design_20261010.md` §5.1、§6、§8.4；`docs/design/mouse-voice-gap-map.md`。
**状态：** IN_PROGRESS（采集开关与状态、能力协商、时间对齐协议与确定性夹具已交付；**真实 VAD/流式 ASR 未接**，`UNVERIFIED_CREDENTIALS_REQUIRED`）。

## 用户目标与角色/空间

- 用户显式开启麦克风后能看到"正在聆听"、电平与随时停止；被拒/不支持/错误都能看到原因；离开会话立即停止采集。
- 系统只在供应商提供**可验证的音频/词级位置**时才把词语精确绑到序列时间；否则用发话快照，并如实显示精度。

## 真实入口

- 采集控件 `VoiceCaptureControl`（含本地电平、可见监听状态、错误提示）已作为可复用组件交付；挂载到共看片室对话栏属 N04-01/N16-06（尚未挂载，故不宣称 UI 验收）。

## 对象与范围

- 能力协商：按适配器**声明能力**裁决，请求未声明支持的能力 → 501（未知一律不支持）。
- 时间对齐：`audioRange × VOICE_CLOCK 采样 × 播放锚点` → 序列区间；精度 `WORD_EXACT / AUDIO_RANGE / UTTERANCE_SNAPSHOT / UNAVAILABLE`，并给出漂移诊断（不用于改写锚点）。
- 采集：`IDLE/REQUESTING_PERMISSION/CAPTURING/DENIED/UNAVAILABLE/ERROR`，`listening/visible` 可见，卸载即停止。

## 主流程 / 取消 / 恢复

1. 点击"开始聆听" → 请求麦克风权限（可见"等待授权"）。
2. 授权 → "采集中/正在聆听" + 本地电平；再次点击或卸载 → 释放音轨并回到"未开启"。
3. 被拒/不支持 → 明确原因，不静默失败、不假装已通。
4. 对齐算法只做确定性纯计算；无音频位置时退回发话快照点。

## 权限 / 费用 / 锁定

- 采集需用户显式授权；不触发 Provider、无费用、不写工程；音频只做本地反馈（最小保留）。

## 设计覆盖

- **新增**：无对应高保真稿，按 v0.4 黑白语义 Token 补齐（复用 `panel/inset/button/status/mutedText`）。

## 业务依赖与浏览器证据

- 依赖：`@ancs/contracts` 的 `voice-alignment.ts`（对齐/协商/采集状态）与 `@ancs/domain` 的 `voice-alignment.ts`（服务层）。
- 浏览器证据：组件在 jsdom 下以 mock 的 `getUserMedia` 验证授权成功/被拒/不支持/卸载停止；**真实麦克风与真实流式 ASR 未验证**（无凭据）。
