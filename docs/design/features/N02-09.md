# N02-09 UI 交付卡｜素材输入真实端到端验收

## 用户切片

1. **用户目标与角色**：Workspace 创作者从素材库批量导入真实横屏/竖屏视频，在网络中断后继续上传，并确认素材可以探测、代理、索引、检索、播放和重新链接。
2. **入口与对象**：`/w/:workspaceId/assets`；对象是批量上传队列、逻辑 Asset、原始 AssetVersion、媒体代理、源媒体索引、转写检索证据和重新链接状态。
3. **流程与恢复**：批量选择 → 断网失败 → 继续未确认分片 → 等待分析 → 查看代理/索引并播放 → 搜索源范围 → 原件丢失后重传并精确恢复。损坏文件保留失败原因和重新上传建议。
4. **权限与边界**：Owner 可管理素材；非成员访问同一 Workspace 的素材 API 返回 404。所有 Provider 结果必须区分真实工具、脚本 seam 和未验证第三方能力。
5. **设计覆盖**：**沿用** N02-01—08 已交付的素材库、上传队列、素材详情、媒体能力、代理、索引、检索和重新链接组件；本任务是联合验收门，不新增产品 UI。
6. **真实依赖与证据**：PostgreSQL、Fastify、SDK、LocalSignedStorage、FFmpeg/ffprobe、production Next、Chromium，以及用户提供的两段真实 MP4。ASR 使用明确命名的 scripted test seam，只验证契约与检索闭环。

## 必要状态

- 三文件批次包含两段真实授权媒体和一个故意损坏的 MP4；上传队列显示每项独立状态。
- 一次真实请求以 `internetdisconnected` 中止；用户点击“继续”后复用原 UploadIntent，最终所有四次意图（含回链候选）均为 `COMPLETED`。
- 两段真实媒体均完成 probe、proxy、index；浏览器实际播放索引范围。
- 损坏文件 fail closed：解码、预览、导出不可用，原错误原因和下一步可见。
- 原件对象删除后显示缺失；同 hash 重传恢复旧版本和 storage checksum。
- 未加入 Workspace 的已登录用户读取素材列表得到 404，不能枚举租户。
- 第三方 ASR/视觉 Provider 无凭据，状态为 `UNVERIFIED_CREDENTIALS_REQUIRED`，不计作本次真实 Provider 通过。

证据见 [`N02-09 verification`](../../verification/N02-09.md)。
