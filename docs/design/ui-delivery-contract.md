# ANCS 用户可见功能 UI 交付规约

本规约承接用户 2026-10-08 的增量开发要求，适用于今后每个用户可见功能。任务仍按 `docs/V04/ANCS_AI_Native_v0.4.md` 和 N 任务清单推进；此文件规定同一功能切片中的交互、视觉和真实验收。后续 UI 任务必须完整阅读本文和相关设计源，不能只凭 `AGENTS.md` 的链接推断内容。

## 1. 开工与权威

先核对分支、HEAD、未提交修改、路由、共享组件、样式、SDK、测试配置、适用 `AGENTS.md` 与最新交接。按任务读取 v0.4 总规范、设计系统、运营专项、启动指令、任务与追踪；定位高保真源文件、原型、Token、截图和相关组件，**实际打开视觉参考**。缺失则记录缺失，不宣称已看过。

冲突优先级：用户最新明确要求 → 当前有效需求规范 → 当前设计系统 → 已确认且不冲突的高保真 → 现存实现。旧高保真不是新增功能的上限；模型生成图不自动等于用户批准。保留现有工程、有效测试和未提交修改，不重置历史或重建数据库。

## 2. 编码前的 UI 交付卡

在 `docs/design/features/<taskId>.md` 简记用户目标和角色/空间、真实入口、对象与范围、主流程和取消/恢复/撤销、权限/费用/锁定/审批、设计覆盖和复用组件、业务依赖与浏览器证据。设计覆盖逐项标记：**沿用**（现有设计符合）、**扩展**（增加能力或状态）、**新增**（按设计系统补齐）、**替代**（说明旧交互冲突与迁移）。先设计用户完成目标的过程，再决定是否需要页面或控件。

纯后端、媒体内核或迁移项可写“UI 不适用”，但必须解释原因及关联用户切片；不得据此宣布产品功能交付。简单改动不必生成多份无用文档，现有文件可直接更新。

## 3. 自主补设计与交互中心

无设计稿时，先判断结果、当前画面/选区的上下文、用户必须决定的内容、就近完成的机会、专业工具展开和修改/恢复路径。优先用对象附近操作、轻浮层、按需 Inspector/抽屉、可展开专业时间轴；复杂运营流程使用专用工作区，不硬塞小弹窗。需要新组件时做最小可复用组件及必要状态。默认给出基于现行风格的方案，不把收费、隐私、身份授权或破坏性决定擅自当作视觉选择。

默认 Studio 仍为共看片室：作品画布、轻顶栏、播放/范围控制、语音/文字入口。保留真实素材的非破坏性剪辑、纯素材/纯生成/混合制作、鼠标/触控/键盘定位、AI 局部试改与采用/拒绝、原素材/已确认片段/版本保护，以及按需多轨/关键帧/蒙版/调色/音频/多机位。布局改动不能改变选区或时间映射。停 AI 说话、取消试改、取消外部任务、撤销编辑各有不同语义；保存、播放结束或关闭抽屉不能代替采用。

## 4. 视觉与组件

全站沿 `docs/V04/ANCS_v0.4_Design_System.md` 的语义 Token 和共享组件：白、近黑、中性灰，靠排版、间距、对齐、细分隔与层级组织；浅/深/系统主题完整。Studio 宽松，专业工具与运营表格高效。中文、长文件名、混排、数字/单位、焦点、录音、错误、禁用和危险状态都须可辨。主次操作有层级，采用合法系统字体与已许可图标。不得用蓝紫渐变、霓虹、彩色 KPI、大面积玻璃、伪 3D、装饰动画或默认后台模板。只调整本轮受影响区域，不擅自重做已确认且无冲突的界面。

UI 主题不改视频、封面、缩略图、色轮或品牌原色；禁用全局 `grayscale`、`invert`、`brightness`。主题与抽屉切换不丢选区、不重建项目、不重提费用任务；切换租户时清理前一租户敏感可见状态。产品名和 Logo 沿当前有效配置，不擅自启用候选名。

## 5. 同一切片内完成业务与状态

顺序：需求和状态覆盖 → 必要设计补全 → 适用 contracts/migration/domain/API/SDK → 页面与组件 → 正常/异常联调 → 浏览器和截图复测 → 任务、设计与证据。前端错误、权限、状态语义在契约阶段确定。GUI、快捷键与 AI 共用类型化编辑操作、revision 与 Undo；不得维护第二套项目状态、权限或账本。fixture/mock 可用于开发，不能冒充真实业务；不写硬编码成功、假进度、假任务、静态封面播放器或装饰数据。

按功能覆盖相关的空、加载、排队、处理中、成功、失败、部分成功、无权限、只读、锁定、额度不足、待授权、素材缺失、上传中断、外部故障、版本冲突、试改待审/采用/拒绝/取消请求等状态。异常应说明原因和合法下一步；未知成本不填零，取消请求不等于完成取消，失败时保留输入与已确认作品。

运营台沿 AdminAction：列表/详情 → 影响预检 → 必要授权与审批 → 执行 → 逐项结果、对账和审计。环境、角色、租户范围、对象、金额与不可逆影响持续可见。只读切片明确不提供写动作及原因；前端隐藏按钮不能替代后端拒绝。

## 6. 真实浏览器与视觉回归

实际打开应用，执行本轮可用的点击、输入、拖动、播放、选区、采用、撤销、取消与恢复。至少检查常规/小桌面、浅/深、相关窄屏/触控、长中文和文件名、必要的原生 200% 缩放、键盘焦点、降低动效、正常与关键异常。1440×900 和 1280×800 是建议起点；其余宽度按适用范围增加，不因测了视口便宣称对应终端完整支持。

截图必须人工查看层级、对齐、留白、裁切、重叠、焦点、图标、可点击性、密度与跨页一致性。媒体另做真实播放、同步、局部回放、选区和版本测试；静帧不证明行为。截图固定环境、数据与媒体时间；不得遮盖本轮对象来制造稳定。旧基线变化要解释并检查差异，不批量更新消除失败。新技术基线不等于用户视觉批准。没有服务、浏览器或截图查看能力时写“未验证”。

## 7. 记录与完成

在 `docs/design/ui-coverage.md` 关联任务/需求、入口、设计来源、组件、状态、实现与浏览器/真实服务证据；单项 `docs/verification/<taskId>.md` 和 `docs/handoffs/<taskId>.md` 记录命令、结果、截图/录屏/trace、Mock 与真实边界、未完成和回退。只有用户能发现入口并完成目标，真实业务/前端一致，设计和关键状态完整，浏览器与截图已检查，适用媒体行为正确且无关界面未回归时，用户可见功能才可整体标 `VERIFIED`。基础设施可单项验收，但不能代替关联产品功能。不要虚构费用、提交、部署或用户批准。
