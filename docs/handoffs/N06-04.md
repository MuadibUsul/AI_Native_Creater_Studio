## 接手要点

1. **依赖键是权威失效机制**：`sha256(baseProjectRevision + operationsHash + selectionFingerprint + intentRevisionId + assetVersionSignature)`。任一变化 → 新键 → 不会命中陈旧试片。新增依赖维度时必须并入（例如渲染器版本、输出规格）。
2. **缓存不是第二份工程状态**：只存只读 `ProposalTrial`；采用仍走统一编辑协议并做全部服务端重验（基版本/哈希/指纹/锁/预算）。
3. **HTTP 幂等 vs 服务端缓存**：SDK `previewProposal` 默认固定幂等键，HTTP 幂等会先返回同一响应。要观察 `cached=true` 必须使用不同 HTTP 幂等键（测试已如此）。
4. **素材版本签名**：读取 `sequence_clips` 的 `(id, asset_version_id)` 排序后哈希；片段换源即变键。
5. **清理**：采用/丢弃后按 `proposalId` 删缓存行；素材版本变化等可调 `invalidateProposalTrials`（键失效已保证正确，清理是容量与归属）。
6. **迁移工具**：`db:generate` 因 0080/0081 快照 `id`/`prevId` 相同而失败；新迁移按既有做法手工写 SQL + 同步 `meta/_journal.json`，并让 `runMigrations` 应用。
