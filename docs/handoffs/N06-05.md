## 接手要点

1. **处置解析是纯函数**：`resolveProposalDisposition({ utterance, uiAction, explicitTargetId, candidates })`。顺序为 **显式 UI 动作 → 拒绝 → 后面也这样 → 继续微调 → 采用**；**沉默/无法识别 = NONE + 需确认**，多候选无唯一目标 = 需消歧。新增表达标记时注意顺序（"不要"必须先于"再"）。
2. **闭包规则两条**：① 引用闭包（消费 `createdClipId` 等 → 并入生产它的操作）；② 音画配对（同一 `avGroupId` 的片段，其操作必须同进）。两条互相可能触发 → **迭代到不动点**。新增会产生/消费 id 的操作原语时，必须同步 `PRODUCED_ID_FIELDS` / `CONSUMED_ID_FIELDS`。
3. **音画查询要点**：必须对**全部候选 CLIP 目标**解析 `avGroupId`（只查已选中的一侧会导致查不到配对）。
4. **一次性交付**：部分采用后候选为 `PARTIALLY_ADOPTED`（未采用的操作不能再落地，因为 revision 已推进）；闭包覆盖全部时置 `COMMITTED`。不要改成"允许重复部分采用"，否则会重复写入/声画漂移。
5. **执行层是最终守卫**：闭包只是"保守扩张"，真正的失败由统一编辑协议整批回滚；不要用放宽闭包来"绕过"执行层 409。
