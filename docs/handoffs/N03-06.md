# N03-06 交接｜基础混音与原声保护

**状态：** `VERIFIED`（2026-10-09）　**验证：** [`docs/verification/N03-06.md`](../verification/N03-06.md)

**依赖满足：** N03-04（多轨、轨道静音/独奏/同步锁）✅。

## 本项交付

等功率 crossfade 规范原语 `apply_audio_crossfade`（v2 NATIVE）、混音判据纯函数（`equalPowerFadeGains`／`sampleEqualPowerCurve`／dB 换算）、片段级混音计划 `planClipAudioMix`（含**无削波**与**无意外静音**两道 fail-closed 门），以及**原声保护**守卫（`preserveOriginalSpeech` 下禁止触碰源时钟的音频编辑）。

## 接手要点（下一项 N03-07 需要知道的）

1. **原声保护语义**：`preserveOriginalSpeech=true` 时，`update_audio_region` 允许增益/淡入淡出/声像/声道映射/参数，**拒绝** `sourceStreamId`／`localRange`／`timeBinding` 改动（409 `ORIGINAL_SPEECH_PROTECTED`）。新增音频原语时请同样判定"是否改变语言内容（源时钟/源流）"，不要只在 UI 层隐藏按钮。
2. **混音计划是只读读面**：`planClipAudioMix` 不写数据、不改源素材；削波判据依赖 `region.parameters.values.sourcePeakDb`（缺省 −1 dBFS 保守参考）。要更精确的判定，先把分析链路的峰值写进这个字段，而不是放宽门槛。
3. **两道 fail-closed 门**：`MIX_CLIPPING_DETECTED`（422）与 `MIX_EMPTY_OUTPUT`（409）——"能出声音"和"不削波"是硬约束；遇到误报应先修 `sourcePeakDb` 数据，不要改判据。
4. **crossfade 的约束**：两区域必须**严格相邻**（`leftSequenceRange.end === rightSequenceRange.start`）、时长同时放得进两侧；写的是 `fadeOut`（左）/`fadeIn`（右），等功率曲线由消费方按 `equalPowerFadeGains` 采样，不要用线性淡入淡出替代。
5. **撤销**：`APPLY_AUDIO_CROSSFADE` 每侧一条事件，逆操作用 `update_audio_region` 恢复原淡入淡出值；按事件粒度撤销（一次 crossfade = 两次 undo）。
6. **测试夹具注意**：`projects.production_policy` 是 strict 完整对象——写部分字段会让文档投影 500。夹具从 `defaultProductionPolicy(mode)` 出发覆盖字段。
7. **补偿不受限**：原声保护守卫只在**非补偿**请求上生效。undo/redo 是把工程恢复到此前已被接受的状态，绝不能因为守卫而撤不回去（本项首轮 verify 正是被这一点抓出）。新增任何策略类守卫时都要给 `input.compensation !== undefined` 留出通道。
8. **已知缺口**：ducking／BGM 包络与真实响度归一化属 N09-09—11；混音面板 UI 属 N03-08。
