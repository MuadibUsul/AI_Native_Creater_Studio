# V5-M3 交接｜配置统一 + Provider 种类与生产守卫 + Deepgram 正式路径 + 凭证校验 + 能力覆盖账本

**状态：** 完成（工作流引擎与 Gateway 路由/预算随首个使用者移至 M4，见裁决）　**验证：** [`docs/verification/V5-M3.md`](../verification/V5-M3.md)　**裁决：** [`0014`](../decisions/0014-config-provider-gateway-and-capability-ledger.md)

## 完成了什么

- 配置只在入口读取校验后注入：领域层不读 `process.env`（arch-check R12）；部署策略注入；空白值视为未配置；Worker 数值带上下界；清理 CLI 与 API/Worker 同一套存储签名规则。
- 生产必须显式配置存储签名密钥与（Worker 的）凭据密钥；修正从未生效的 `PLATFORM_PROVIDER_KEYS`。
- Worker 子进程（渲染、Motion 验证、媒体探测、FFmpeg）不再继承连接串与密钥。
- Provider 实现种类 `REAL/MOCK/SCRIPTED`：生产装配 Mock 需显式许可，否则启动失败；`/capabilities` 报告装配清单。
- Deepgram 作为 `ANCS_ASR_DRIVER=deepgram` 进入 Worker 正式装配（缺密钥启动失败；付费调用不自动重试）。
- 语音会话短期凭证在新的流式端点上真正被校验（伪造/串用 401，撤销/过期 409）。
- 编辑能力覆盖账本由 `pnpm capabilities:generate` 生成、`pnpm capabilities:check` 在 verify 中强制；补齐两个 NATIVE 操作缺失的内核单测。
- 入口装配守卫有真实启动测试（`apps/worker/src/startup-guards.integration.test.ts`，启动 dist 产物）。

## 接手要点

1. **新增配置项**：先加到 `packages/contracts/src/env.ts` 的 schema（必要时加交叉校验与单测），由入口读取后注入；业务包里写 `process.env` 会被 R12 拦下。
2. **新增外部能力驱动**：在入口的 `providerInventory` 里登记实现种类；Mock 必须标为 `MOCK`，否则生产守卫失效。
3. **新增子进程**：用 `childProcessEnv(process.env, …)` 并只放行确实需要的键；运行未受信代码的子进程（沙箱）仍走 `sandboxEnv()`。
4. **改了编辑操作注册表或测试**：运行 `pnpm capabilities:generate` 并提交生成物，否则 verify 失败。声明 NATIVE 前先有内核实现、内核单测与集成测试。
5. **本地跑渲染测试**：`REMOTION_BROWSER_EXECUTABLE` 必须指向 `chrome-headless-shell`（新版 Chrome 已移除旧 Headless 模式）；指向完整 Chrome 会让 `render-execution`/`render-qa` 失败。

## 没完成什么

- 工作流引擎、Provider Gateway 的路由/预算/计量 → M4（与 FinalRender 一起）。
- `defineCapability` 单一源与 Agent 工具清单生成 → M5（与 Agent 运行时一起）。
- Web 端 Mock 标识、产物级 `providerKind` 字段。
- 首个 `VERIFIED_REAL`（ASR）：需真实 Deepgram Key 经 Worker 正式路径跑通真实媒体。

## 回滚

无数据库迁移。`git revert` 即可；注意回滚后生产环境的新必填项（`ANCS_STORAGE_SECRET`、Worker `ANCS_CREDENTIAL_KEYS`、`ANCS_ALLOW_MOCK_PROVIDERS`）不再被要求，但保留配置无害。
