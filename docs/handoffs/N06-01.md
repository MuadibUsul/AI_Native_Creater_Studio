## 接手要点

1. **试改 = 真跑 + 回滚**：`previewProposal` 在 `deps.db.transaction` 内调用 `processEdits`（内层 savepoint），随后抛 sentinel 强制回滚；若事务未回滚会 500 fail-closed（不许"试改漏写"）。新增"预览"能力时请复用这条路径，不要另写模拟器。
2. **采用四道绑定**：幂等键 → 状态 → 操作哈希 → 选择指纹 → base revision；顺序与错误 reason 已固定，UI 应按 reason 区分"重新生成候选"还是"提示用户重新审阅"。
3. **失败不显示已采用**：编辑协议抛错时候选保持 `OPEN`、事务整体回滚；不要在前端乐观标记。
4. **幂等键语义**：`adoptionIdempotencyKey` 是唯一索引；同键重放返回同一 `projectRevision`，不同键对已提交候选 409。
5. **与意图链衔接**：语音封存（N05-01 `sealUtterance`）→ `planRangeEdit`（N03-09）→ `createProposalBranch(intentRevisionId)` → `preview` → `adopt`，这条链就是垂直切片的"私有试改 + 原子采用"；不要为语音另建采用接口。
6. **测试夹具**：`createProposal` 的 zod default 字段（`selectionAnchorId`／`intentRevisionId`）在 SDK 入参类型上是必填，调用时显式传 `null`。
