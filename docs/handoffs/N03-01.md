# N03-01 交接｜素材到序列的插入／覆盖／追加

**状态：** `VERIFIED`（2026-10-09）　**验证：** [`docs/verification/N03-01.md`](../verification/N03-01.md)

**依赖满足：** N01-09（ProjectDocument v2 合成模型 + `update_clip`）✅、N02-03（标准编辑代理/播放地址）✅。

## 本项交付

`insert_clip`（INSERT／OVERWRITE／APPEND）与 `delete_clip` 两个**规范编辑原语**，从契约到事务执行器、影响面、undo/redo 全链路贯通；`insert_clip` 在 v2 覆盖层由 `PLANNED` 翻为 `NATIVE`。素材可以直接落轨，**不需要任何 Article／NarrativePlan**。

## 接手要点（下一项 N03-02 需要知道的）

1. **入口**：`client.projects.edit(projectId, { baseProjectRevision, expectedSceneRevisions: {}, operations, idempotencyKey })`。`insert_clip` 必填 `sequenceId`／`trackId`／`sourceRange`；`assetVersionId` 与 `nestedSequenceId` 恰一；`mode` 默认 `INSERT`；APPEND 禁 `sequenceStart`；`linkAudio` 默认 `true`（源含音频流时按 `avGroupId` 建关联音频片段，无 AUDIO 轨则自动建一条）。
2. **测试范式**：`apps/api/src/clip-edits.integration.test.ts` 是 G0 时间线原语的模板——用 domain 的 `createProject`／`createSequence`／`createTrack`／`createClip` 铺初始时间线，用 SDK 走 HTTP 提交编辑，用 `projects.state(...).document.composition` 断言用户可见投影。**注意**：`projects.create` 的 SDK 入参面尚未暴露 `mode`（纯素材工程要经 domain `createProject` 建），这属 N04 工程入口范围。
3. **源素材夹具**：`seedSource` + `probeFixture` 按 `sourceMediaProbeResultSchema` 构造 `mediaProbe`（`status`/`streams`/`capabilities.preview=AVAILABLE`）——**不要**再自造 `{success,data}` 形状，播放地址与 AV 关联都依赖这个形状。
4. **时间表示**：片段落位与涟漪全部走 `exactTicks(timeFraction(...), sequenceTimebase)`，不可精确表示即 422 `TIME_NOT_REPRESENTABLE`；不要退回整数毫秒。
5. **fail-closed 边界（不要顺手放宽）**：结果超出序列时长 → 422 `SEQUENCE_RANGE_OUT_OF_BOUNDS`（长度扩展属 N03-04）；非 1:1 前向映射的片段需要裁切/切分 → 422 `OVERWRITE_TRIM_UNSUPPORTED_MAPPING` / `INSERT_SPLIT_UNSUPPORTED_MAPPING`；源缺校验和 → 409 `SOURCE_CHECKSUM_MISSING`。
6. **锁的两层**：轨道级锁由**统一影响面门**先拒（409 `EDIT_IMPACT_LOCKED`，因为 `insert_clip` 声明了 TRACK 的 POSITION/DURATION 影响）；被覆盖片段的对象锁由执行器拒（409 `CLIP_LOCKED` + `clipId`）。新增原语时必须同步登记 `operationImpacts`，否则锁保护形同虚设。
7. **事件粒度**：一次插入可能产生多条事件（涟漪 UPDATE_CLIP + N 条 INSERT_CLIP），undo/redo 是**按事件**反演——UI 的"撤销"按钮需要按事件步进，或由后续任务引入批次语义。
8. **已知缺口**：自动创建的音频轨在 undo 后保留为空轨（无删除轨道原语），已留 `TODO(N03-04)`。时间线拖拽 UI 未交付（N03-02/N03-08）。
