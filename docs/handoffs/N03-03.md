# N03-03 交接｜ripple、roll、slip、slide 与 J/L cut

**状态：** `VERIFIED`（2026-10-09）　**验证：** [`docs/verification/N03-03.md`](../verification/N03-03.md)

**依赖满足：** N03-02（拆分/裁剪/移动原语与 AV 同步）✅、N01-07（对象锁与影响面）✅。

## 本项交付

五个精剪规范原语：`slip_clip`（滑移素材内容）、`slide_clip`（滑动，邻居伸缩吸收位移）、`roll_clip`（卷动剪辑点）、`ripple_clip`（**显式**涟漪：删除/掐头/去尾收缝）、`split_av_cut`（J/L cut，音频切点错开且原音连续）。契约 → v2 覆盖层 → 执行器 → 影响面 → undo/redo 全链路；`slip_clip` 由别名提升为原生，来源操作 34→38。

## 接手要点（下一项 N03-04 需要知道的）

1. **"其他别动"是硬约束**：除 `ripple_clip` 外，所有原语都**不得**移动其他片段（trim/move/split/roll/slide 都只动声明对象；越界/重叠一律 fail-closed）。新增原语时先想清楚是否会隐式移动邻居。
2. **slide 的邻居语义**：被滑片段只改位置；邻居的**内容在时间线上保持不动** —— 前段源出点外扩、后段只推进源入点（出点不变、时长自然缩短）。写反会导致素材被"推着走"。
3. **roll 的 undo 锚点**：左右两段各落一条 `ROLL_CLIP` 事件，逆操作要用"左段 before.end / 右段 before.start"取原剪辑点（不能用该事件自身的片段边界）。
4. **涟漪收缝统一规则**：片段停在原位、时长缩短收缝量；`TRIM_HEAD` 推进源入点、`TRIM_TAIL` 回收源出点（源出点 = 源起点 + 源时长 − 收缝量，写成"源起点 − 收缝量"会产生空区间 → 500）。起点晚于缝隙的片段逐条左移并各落 `UPDATE_CLIP`（patch 含 `ripple: true` 与 before/after），这就是"位置变化向用户报告"的机制。
5. **AV 同步**：slip/slide/roll/ripple/split_av_cut 都同步 AV 关联片段；单轨收缝遇到 AV 关联必须 409（`AV_SYNC_REQUIRES_CROSS_TRACK_RIPPLE`），不得静默破坏同步。
6. **可复用助手**：`splitClipRow`（切分单条片段：左段留 id、右段新建为子片段并落事件）已被 `split_clip` 与 `split_av_cut` 共用；有新的切分需求请复用它，不要复制数学。
7. **事件命名**：精剪各落操作名事件（`SLIP_CLIP`／`SLIDE_CLIP`／`ROLL_CLIP`／`RIPPLE_CLIP`／`SPLIT_AV_CUT`），副作用的邻居/关联片段落 `UPDATE_CLIP`／`INSERT_CLIP`。undo/redo 仍按事件粒度。
8. **已知缺口**：转场对象与 handles 建模、音频区域重算（N03-06）、字幕/关键帧（N03-07/05）、序列长度扩展（N03-04）、精剪 UI（N03-08）。
