## 已交付

- 契约：`targetBindingBaselineSchema` + `OrderedTargetRef.bindingBaseline`（保存时目标的序列/源区间，**不参与指纹**、可选/可空以兼容旧锚点）；`SELECTION_RECOVERY_TRIGGERS`、`recoverSelectionAnchorRequestSchema`、`selectionRecoveryResultSchema`；`addMediaTime`/`subtractMediaTime`。
- Domain：`recoverSelectionAnchor`（幂等、`expectedRevision` 并发保护、`FOLLOW_OBJECT` 位移跟随、`FOLLOW_SOURCE` 源映射重投影、嵌套父序列失效检测）；`saveSelectionAnchor` 把并发主键冲突映射为 409。
- API/SDK：`POST .../selection-anchors/:anchorId/recover`（`project:write`）与 `client.projects.recoverSelectionAnchor`。

## 接手要点

1. **幂等是硬要求**：刷新恢复若工程未变，必须 `changed=false` 且不追加修订，否则每次刷新都新增审计噪音。判定依据 = 解析状态 + 证据变化 + 时间选择是否重投影 + 基线是否更新。
2. **并发保护两层**：先比 `expectedRevision`；即使同时读到同一修订，DB 主键 `(workspace,project,id,revision)` 冲突也会被映射成 409，绝不静默覆盖。
3. **跟随语义来自 `timeBindingPolicy`**：只有 `FOLLOW_OBJECT`/`FOLLOW_SOURCE` 且存在 `bindingBaseline` 时才重投影；`SEQUENCE_FIXED` 不跟随。缺少基线时不要猜（保持固定）。
4. **`FOLLOW_SOURCE` 用既有映射纯函数**：`sequenceTimeToSourcePts` → `sourcePtsToSequenceTime`；映射越界/坍缩返回 null → 标 `STALE`，不近似。
5. **基线不进指纹**：`selectionFingerprintInput` 不包含 `bindingBaseline`，避免改变既有锚点指纹。
6. **jsonb 列在类型层是 unknown**：读取片段 `sequenceRange`/`sourceRange` 必须 `mediaRangeSchema.parse` 后再用。
7. **嵌套**：只检测父序列是否存在（`project_sequences.parent_sequence_id` 无外键，可被指向缺失 id）；父序列自身时序对嵌套内容的影响未覆盖。
