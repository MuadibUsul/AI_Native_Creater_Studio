# N03-02 交接｜拆分、裁剪、移动、替换与子片段

**状态：** `VERIFIED`（2026-10-09）　**验证：** [`docs/verification/N03-02.md`](../verification/N03-02.md)

**依赖满足：** N03-01（插入/覆盖/追加原语与 AV 关联）✅。

## 本项交付

五个时间线规范原语：`split_clip`（切分，右段为子片段）、`trim_clip`（入出点裁剪）、`move_clip`（重定位/跨轨）、`duplicate_clip`（复制引用，不复制原件）、`replace_clip_source`（换源）。契约 → v2 覆盖层 → 事务执行器 → 影响面 → undo/redo 全链路贯通；v2 中 `move_clip`／`trim_clip` 由别名提升为原生，`split_clip`／`duplicate_clip`／`delete_clip` 由 PLANNED 翻为 NATIVE，并新增来源操作 `replace_clip_source`。

## 接手要点（下一项 N03-03 需要知道的）

1. **事件命名**：每个 N03-02 操作落一条以操作名命名的事件（`SPLIT_CLIP`／`TRIM_CLIP`／`MOVE_CLIP`／`DUPLICATE_CLIP`／`REPLACE_CLIP_SOURCE`），附带的副作用行（右段、AV 关联片段、绑定区域）各落自己的 `INSERT_CLIP`／`UPDATE_CLIP`／`UPDATE_AUDIO_REGION` 事件。**undo/redo 仍按事件粒度**：一次切分需多次撤销。
2. **AV 同步是执行器职责**：同一 `avGroupId` 的片段在 split/trim/move/duplicate/replace 中都会同步；新增原语时必须复用 `avSiblingsOf` 并同步落事件，否则声画会悄悄错位。
3. **复用工具**（`packages/domain/src/edits.ts` 模块级）：`loadEditableClip`、`loadTrack`（含轨道自身 locked 检查）、`loadSequenceTimebase`、`avSiblingsOf`、`clipBoundAudioRegions`、`assertSourceRangeUsable`、`assertNoTrackOverlap`、`assertObjectLockAllows`、`ticksInRange`、`compareFraction`。**不要**再写第三套时间换算：秒分数直接交给 `exactTicks(fraction, timebase)`（N03-02 抓到的 1000 倍放大 bug 就是重复乘了时基系数）。
4. **锁的两层**：影响面门（`operationImpacts`，静态声明）先拒，执行器 `assertObjectLockAllows` 兜底。新增原语**必须同时**登记影响面；`move_clip` 在给出 `trackId` 时声明目标轨。
5. **fail-closed 清单（不要顺手放宽）**：切分点越界 422、非 1:1 映射 422、裁剪时长不等 422、移动改变长度 422、轨类型不符 422、重叠 409、绑定音频区域无法保真 409、结果超序列时长 422。
6. **v2 编译**：NATIVE 操作在 `compileEditOperationsV2` 里按 `editOperationSchema` 透传；只有 COMPILED_ALIAS 才进别名 switch（别在 switch 里为 NATIVE 操作留分支——已成为死代码）。
7. **子片段语义**：切分右段与复制的片段都写 `parentClipId` 指向来源片段；后续"子片段/嵌套编辑"可据此递归。
8. **已知缺口**：轨道生命周期（含自动创建音频轨的回收）→ N03-04；音频区域级时钟重算 → N03-06；字幕 → N03-07；关键帧重排 → N03-05；时间线拖拽 UI → N03-08。
