## 一、需要你现在决定（4 项）

### 1. 仓库的许可证（LICENSE）
**现状：** 代码托管在**公开**仓库上，但项目里标注的是"未授权"（`UNLICENSED`），并且**没有** LICENSE 文件。
**含义（白话）：** 按法律默认，**任何人都没有使用、复制、修改你代码的权利**——包括你自己的合作者和未来的你（换台机器、换人接手、公司主体变更时都可能被卡）。同时，公开仓库却没有许可证，会让外部人不敢用、也不敢贡献。
**你要选一个：**
- (a) 加一个**开源许可证**：最常用是 MIT（最宽松，别人可自由用，只要保留你的版权声明）或 Apache-2.0（多一条专利授权，企业更放心）；
- (b) 明确**保持"保留所有权利"**（那就应把仓库转为**私有**，否则等于公开了却不许人用，容易被误用）；
- (c) 先不定——那就由我把这件事标成风险项，**不再推进**（不影响当前开发）。

### 2. 陈旧分支是否删除
**现状：** 有一个并行分支 `codex/quiet-frame-rebuild`，比主分支多 3 个提交、从未合并，看起来已被后来的 Quiet Frame 工作取代。
**含义：** 它是"以前的分叉成果"，放着不会坏，但会让人误以为有两条主线。
**要你确认：** 那 3 个提交是否确实不要了？确认后我删本地与**远端**分支。**远端删除不可逆**——所以我不会先斩后奏。

### 3. 历史密钥扫描：要不要加，扫出东西怎么办
**现状：** 现在的自动检查只扫描"**将要提交的内容**"，**不扫描历史**。仓库是公开的，如果以前不小心提交过密钥又删掉了，历史记录里仍能翻出来。
**含义：** 这是公开仓库里最常见的"不可逆泄露"——删除文件不等于从历史里删除。
**要你决定：**
- 要不要我给 CI 加一条**全历史扫描**（gitleaks / trufflehog）？
- **如果扫出东西**（这是你要拍板的）：要不要把这些密钥**作废并重新签发**？要不要**改写公开历史**（改写 = 强制推送 + 不可逆，所有协作者都要重新克隆）？
（我建议：加扫描；扫出东西先单独报给你，不擅自改写历史。）

### 4. 真实 AI 供应商与月度预算
**现状：** 目前所有"AI"能力（语音识别、大模型、视觉理解）都是**模拟的**。项目纪律明确：模拟通过 ≠ 真实通过，所以这些任务的完成状态只能算"模拟验证"。
**含义：** 产品的核心承诺（"说一句话就把片子剪出来""AI 看着画面和你一起剪"）**至今没有任何真实 AI 证据**。接真实服务后才能拿到真实延迟、成本、失败模式——这些数据决定架构对不对。
**要你提供（不要在聊天里发凭据）：**
- 语音识别（ASR）/ 语音活动检测（VAD）/ 大模型 / 视觉分析，**每类选 1 个主用 + 1 个备用**；
- **每月花费上限**（建议先小额试，比如几十到几百元量级）；
- 服务地区与数据留存要求（是否允许把用户素材发给第三方处理）。
**不决定的后果：** G0 交付门过不了；所有"已验证"都停留在模拟层，无法对外声称。

### 6. G0 的"多真"裁决
**要你决定：** 是否接受 **以 FFmpeg 为主的真实导出**（剪切/拼接/转码，必要时叠加层交给 Remotion），而不是"整片 Remotion 渲染"？

**要你确认：** 这些图标是否由你制作、或你拥有商用权利？**若不确认，我会改用自绘或明确开源许可的图标**（不影响主线进度）。
