## 完成了什么

- `project_op_log`：组合状态的权威记录。每个被接受的写批次一行（位置连续、编辑 revision 唯一），首行为惰性补齐的 `BASELINE`；折叠日志 = 投影表。
- `composition-projector.ts`：组合表、对象锁、日志、引用边的唯一写入方；全部写路径（内核持久化、动画、对象锁、版本恢复、直接创建、旧项目迁移）已改走投影器；arch-check **R11** 强制。
- `verifyCompositionProjection` / `rebuildCompositionProjection`：只读校验与按日志修复。
- `reference_edges`：片段 → 素材版本的当前与历史引用；资产清理据此保护"仍可通过撤销/恢复重新生效"的素材。
- `edit-trial.ts`：内核内存试改（零写入、不取行锁），非内核批次退回事务回滚；提案试改、rebase、内容保护、A/B 对照共用，等价性有集成测试守护。
- 修复：已迁移项目全部编辑被拒；`delete_track` 级联静默删除字幕/音频/视觉对象；A/B 对照把服务端故障包装成 422；事务连接上的并发查询。

## 接手要点

1. **不要直接写组合表**：用 `CompositionProjector`（编辑事务里已有一个实例；构造型 API 用 `writeCompositionDirect`）。R11 会拦下 `.insert(sequenceClips)` 之类的写法与原生 SQL。
2. **每个写批次必须 `commit`**：编辑路径在 revision +1 之后调用；直接写入用 `commitDirect`（自带 revision +1）。漏掉 commit 会让 `verifyCompositionProjection` 报差异。
3. **不要依赖外键级联删除组合对象**：级联删除不进日志，也不可撤销。内核需要的话先显式删除/迁移（参见 `deleteTrack`）。
4. **新增内核操作自动获得内存试改**：只要在 `KERNEL_TIMELINE_OPERATIONS` 中注册；在 `edit-trial.integration.test.ts` 的批次表加一行即可得到等价性覆盖。
5. **引用图扩展**：新的引用类型在投影器 `referenceTargetsOf` 增加映射，并在迁移中回填既有数据。
6. **测试夹具**：集成测试里直接 `handle.db.insert(sequenceClips)` 的行不在日志中，这类项目不要断言日志一致性（R11 只扫描非测试源码）。
