# N03-08 交接｜多轨媒体预览与真实合成

**状态：** `VERIFIED`（2026-10-09）　**验证：** [`docs/verification/N03-08.md`](../verification/N03-08.md)

**依赖满足：** N03-03／04／05／06／07 ✅（精剪、多轨、变换、混音、字幕全部就位）。

## 本项交付

**播放快照**（一份工程文档 → 视频段/音频段/字幕/能力/排除项，回带 `documentRevision`）与**服务端合成计划**（同源、同帧数学、带 revision），以及按后端显式声明能力的 `PLAYBACK_BACKEND_CAPABILITIES`；真实 FFmpeg 探测驱动的验收测试（源区间/时长/音轨与真实解码结果对照）。

## 接手要点（下一项 N03-09／N03-11 需要知道的）

1. **一份文档，两个消费者**：`buildPlaybackSnapshot` 与 `buildServerSynthesisPlan` 是同源投影，任何"播放器自己的临时状态"都要被拒绝；快照必须回带 `documentRevision`，写回工程时用它做冲突检测。
2. **能力显式**：`playbackSupports` 对未列出的能力一律 false；新增能力请同时更新 `PLAYBACK_BACKEND_CAPABILITIES` 的 `supported`/`unsupported` 两侧，**不要**用默认 true。
3. **baseline 后端不做逐帧组件渲染**（v0.4 硬要求）：图形对象在 baseline 上 501 `UNSUPPORTED_CAPABILITY`；这不是缺陷而是契约——需要图形就走 `SERVER_PRECOMPOSED`（G0 baseline/受控预渲染）。**不得**用静态截图冒充连续播放。
4. **隐藏轨不产出播放内容**（本项实测修复）：视频段循环必须同时判定 `kind` 与 `hidden`，隐藏轨只出现在 `excludedTrackIds`/`warnings`。
5. **音频可听性归一化**：`muted` + `solo` 归一化后的结果写在段上（`audible`），播放器不得自行再判一次；混音计划（N03-06 `planClipAudioMix`）与快照的判定必须一致。
6. **帧数学共用**：时间→帧用 `playbackFrameAt`（内部走 `mediaTimeToFrameIndex`），帧→时间用 `frameIndexToMediaTime`；预览 seek 与服务端合成计划都用这对函数，任何一处自己实现帧取整都会导致"预览与合成对不上"。
7. **测试夹具**：真实媒体在 `packages/testing/fixtures/media-v04/`；探测用 worker 的 `createFfmpegSourceMediaProbe`；工程夹具经 domain 的 `createChannel`（通道样式版本随通道就位，直接裸插 channels 会让 `createProject` 失败）。
8. **已知缺口**：PlaybackEngine 生命周期与事件（N03-11）、proxy/MSE（N03-12）、WebAudio 主时钟（N03-13）、WebCodecs/GPU（N03-14/15）、正式混合后端（N09-09—11）、播放器 UI 接线。
