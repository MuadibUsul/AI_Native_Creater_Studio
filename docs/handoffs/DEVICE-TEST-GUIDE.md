# 手机真机测试指南（安卓 + 苹果）

> 用途：让**真实手机**成为验收证据来源。评审与规范都要求"每个门禁至少一次 Safari 真机"——播放同步、麦克风采集这类问题**只在真机/真浏览器**暴露，模拟环境测不出来。
> 前提：你的电脑和手机在同一 Wi-Fi；电脑上已装好本仓库依赖。

---

## 一、为什么必须真机

- **Safari（iPhone）** 的媒体播放、音频时钟、麦克风权限与桌面 Chrome 差异大；播放同步问题八成出在这里。
- **Android** 上各家浏览器对音频时钟与自动播放策略也不同。
- 规范明确：**不能把"能上传"当作"能按原质量导出"**，也不能把"桌面能播"当作"手机能播"。真机证据必须来自真机。

---

## 二、现在就能做的（约 5 分钟）：界面与时间带真机检查

这一项对应我的待办 **N04-01（真实浏览器 + 高 DPI 目检）**，现在就能验，不需要等新功能。

1. **电脑上启动数据库与缓存**（只需一次）：
   ```
   docker compose -f infra/docker-compose.dev.yml up -d
   ```
2. **电脑上启动 Web 服务，并允许局域网访问**：
   ```
   pnpm --filter @ancs/web dev -- --hostname 0.0.0.0
   ```
   （默认端口 3000）
3. **找到电脑的局域网地址**：Windows 上执行 `ipconfig`，记下 IPv4 地址，形如 `192.168.x.x`。
4. **手机浏览器打开**：`http://<那个地址>:3000`
   - 若打不开：检查 Windows 防火墙是否拦了 3000 端口（首次启动通常会弹窗，选"允许专用网络"）。
5. **请你看这几件事**（有任何一条不对就告诉我）：
   - 页面**排版有没有错位/重叠**，文字有没有被截断；
   - 时间带（横向那条）的**刻度与片段块**是否对齐、清晰（高 DPI 屏上是否发虚）；
   - **拖动标尺**时播放头是否跟手；**点击片段**是否有反应；
   - 页面滚动是否顺畅（有没有明显卡顿）。
6. **反馈给我**：手机型号 + 系统版本 + 浏览器（Safari / Chrome）；哪一步不对；**截图或录屏最好**。

> 说明：现有界面是"初始设置"，不追求好看，我只需要知道**有没有功能性错位**。

## 三、之后要做的（等功能就绪后我给你逐条清单）

### A. 麦克风相关（语音采集）
**关键限制：** 浏览器只在 **HTTPS** 或 `localhost` 下允许用麦克风。手机通过 `http://192.168.x.x` 访问时**麦克风会被浏览器直接拒绝**，这不是 bug。

届时有两条路，任选（我会在那之前准备好配置）：
- **内网自签名 HTTPS**：`pnpm --filter @ancs/web dev -- --hostname 0.0.0.0 --experimental-https`，手机会提示证书不受信任 → 选择"继续访问"；
- **临时隧道**：用 cloudflared/ngrok 之类把本机 3000 端口映射成一个 https 地址，手机直接打开。
  ⚠️ 隧道会把你本机服务暴露到公网，**只在你知情且用完立刻关闭**的前提下用；不要用真实敏感素材。

### B. 播放同步（N03-16，G0 的硬前置）
这一项**现在还不存在**（N03-16 未做），所以现在还测不了。等它做完，我会给你一份**逐条清单**，大意是：
- 播放/暂停/拖动进度后，**画面对不对得上时间码**（有没有越来越偏）；
- 拖动到中间再播，**声音和画面还同步吗**；
- 长时间连续播放（比如 2–3 分钟）后是否**累计漂移**；
- 分数帧率素材（如 29.97）下**帧号显示是否丢帧**；
- 切后台/锁屏再回来，恢复是否正常。

### C. 我需要的回报格式
每次测试请给：**设备与系统版本**、**浏览器**、**做了什么**、**看到了什么**、**截图/录屏**；如果崩了，把浏览器控制台报错一并截图（Safari 需在设置里开启"网页开发者"菜单）。
