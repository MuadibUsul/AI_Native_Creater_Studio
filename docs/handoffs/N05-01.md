## 接手要点

1. **凭证纪律**：`{ session, credential }` 只在创建时返回；读取/关闭/撤销**不带凭证**。绝不会出现 Provider 长期 Key——签名密钥缺失就是 501，不许回退。
2. **partial 只读是结构性保证**：`appendVoiceEvent` 只写 `voice_sessions.transcriptDraft`，不触碰任何工程表；新增流式事件类型时不要顺手改工程。
3. **四道门顺序**：状态（REVOKED→CLOSED→EXPIRED）→ 代际 → 时钟纪元 → 序号。晚到/重复事件必须被拒绝，不能"最后写入者获胜"。
4. **封存需要锚点**：`sealUtterance` 要求会话绑定 `selectionAnchorId`（无锚点 422 `VOICE_ANCHOR_MISMATCH`）；未解析指代 422；被新修订取代的修订 409。封存产物直接送 `planRangeEdit`（N03-09 路径），**不要**另建协议。
5. **接真实传输时的落点**：把 WebRTC/sideband 适配器接到 `capabilities`（真实能力表按供应商文档逐项声明，未知一律不支持）与会话生命期上；客户端只拿短期凭证，工具执行仍回后端（服务端不信任客户端会话配置）。
6. **测试夹具**：需要封存的用例必须先建锚点（`makeAnchor` 辅助函数）；`ANCS_VOICE_SESSION_SECRET`／`buildServer({ voice: { sessionSecret } })` 二选一提供签名密钥。
