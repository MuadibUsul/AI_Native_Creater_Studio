# N15-02 交接：管理员认证、多因素与生产会话

阶段：v0.4 N15 运营 O0 前置；依赖 N15-01/N00-03 已验收。N15-02 身份/MFA/会话工程范围为 **VERIFIED**；不代表运营 O0、生产账号或外部告警已上线。

## 层次与契约

1. Contracts：`packages/contracts/src/ops-auth.ts` 定义环境、角色、会话与 enrollment/revoke 契约；`auth.ts` 的登录响应兼容原 `{user}` 并扩展 TOTP challenge。`env.ts` 增加运营环境和三种时限，生产进程/`live` 不允许隐式 DEVELOPMENT。
2. Migration：0051 建 `admin_principals`、`admin_role_grants`、`admin_sessions`、`two_factor` 与用户 MFA 标志；角色 grant 触发器在插入、更新、删除时递增 principal 版本。N16-02 将从 0051 快照后续生成 0052；不要重排/重写 0051。
3. Auth service：`packages/auth/src/ops.ts` 负责 eligible principal、MFA 后运营会话签发、读取、失效、重验限速和审计；数据库只存运营 token 哈希，Cookie 为独立 HttpOnly SameSite=Strict，生产/预发附 Secure。
4. API：`/auth/verify-totp` 只有无普通会话的成功登录二次挑战才签发 ops cookie；已登录 enrollment 确认不会升级旧会话。`/ops/session`、`/ops/mfa/enroll`、`/ops/reauth`、`/ops/sessions/revoke` 处理运营会话。旧 `/admin` 读写统一由 `requirePlatformAdmin` 依独立 ops session 判定，不再以 `ANCS_PLATFORM_ADMINS` 授权。生产旧 `/admin` 全部读写路径暂时 403，待 N15-03/04 逐动作和逐对象策略、安全投影与 AdminAction 接线。
5. SDK：`auth.verifyTotp` 与 `ops.session/enrollTotp/reauthenticate/revokeSession`。
6. UI：`/sign-in` 的 TOTP challenge、`/admin` 的 enrollment、环境标识、新设备提醒、重验和设备撤销。N16 并行外观改动已保留；Web 生产构建需在 N16 改动收束后统一运行。
7. Tests/docs：专项隔离 DB 集成、合同单测与五个原管理员套件已改为真实 MFA 流程；`docs/verification/N15-02.md` 记录执行命令、边界和限制。

## 运行配置与操作边界

- 生产须 `NODE_ENV=production` 且显式 `ANCS_OPS_ENVIRONMENT=PRODUCTION`；TEST/DEVELOPMENT principal 与 PRODUCTION 不互认。运营会话默认空闲 900 秒、绝对 28800 秒、敏感重验 300 秒，可按 env 调整。
- `ANCS_PLATFORM_ADMINS` 是历史配置字段，保留解析不授予任何权限。生产首个 principal/角色授予需人工选择操作员和可审计治理流程，本次未对用户或生产库执行授予。不要通过旧名单或 SQL 手工插第二身份自批高风险动作。
- TOTP 密文与恢复码密文由 Better Auth 1.7.7 插件管理；项目显式固定恢复码加密配置。设备撤销/退出/角色 grant 变更/MFA 停用即时阻断已有运营会话。新设备通知目前是 audit + 页面内提醒，不是邮件/短信。
- 生产旧 `/admin` 读写均 fail-closed，运营身份自助 `/ops` 仍可用；TEST 旧读写用于 P 系列回归。逐角色、资源/金额/工单的授权与双人审批属于 N15-03/04/05，**O0 不据 N15-02 单项通过**。
