## 0. 决策摘要

Proposal 0.1 擅长回答"如何不出错"：授权、预算、DAG、降级、版本、不伪称成功。

但它没有回答另一个问题：<b>"为什么这样剪是好的？"</b>

在 0.1 中，导演的专业判断主要依赖"选用强模型 + 事后评测"。本提案在<b>不改动 0.1 任何硬约束与数据主权</b>的前提下，新增一层<b>创作智能层</b>，包含五个模块：

| 模块 | 名称 | 一句话 |
| --- | --- | --- |
| A | 剪辑意图图（Edit Intent Graph） | 每个剪辑决策记录"为什么"，让反馈可以编译为定向修改 |
| B | 节奏谱（Pace Score） | 把"节奏感"变成可测量、可对比、可定向修复的曲线 |
| C | 品味先验（Cut Prior） | 从人类剪辑工程文件中学习"类似情境下人怎么剪"，作为导演顾问 |
| D | 风格规格（Style Spec） | 把参考视频反向解析为可确认的风格规格 |
| E | 观众模拟与审片校准 | 虚拟观众、按信息价值回看、结构锦标赛，以及审片模型自身的校准 |

<b>核心原则：新增能力只能提供"依据与建议"，不能成为第二套"谁才是最终时间线"的真相来源。</b>

---

## 1. 对 Proposal 0.1 的缺口分析

| 0.1 中的状态 | 缺口 | 后果 |
| --- | --- | --- |
| 导演输出时间线与 Scene Contract | 决策的"理由"没有被结构化保存 | 用户说"开头再抓人一点"时，系统无法定位该改什么，只能整段重做 |
| <code>paceCurve</code> 仅为 CreativeProfile 的一个参数 | 没有实测节奏的手段 | "节奏拖"无法被 QA 发现，也无法被定向修复 |
| 导演的品味来自模型能力 | 没有利用真实人类剪辑决策作为参照 | 专业度只能靠主观盲评证明，缺少可量化基线 |
| 参考视频为"可选" | 没有把参考视频转成可执行约束的机制 | 外行说不清风格时，系统缺少抓手 |
| Director Review 由模型审看 | 审片模型本身是否可靠没有被校准 | 可能让不可靠的审片结论触发全局重规划 |
| 导演"按需回看" | 没有回看优先级策略 | 回看次数与成本无法优化（对应 0.1 第 16.3 问） |

---

## 2. 增量设计原则

1. <b>不新增第二套真相来源。</b> <code>EditIntent</code>、<code>PaceScore</code>、<code>CutPrior</code>、<code>StyleSpec</code>、<code>AudienceReport</code> 均为<b>可重建的派生视图或附属证据</b>；最终时间线仍只由 <code>ProjectDocument</code> + Edit Operations + revision log 决定。
2. <b>导演可以偏离先验，但必须留下理由。</b> 任何与 <code>CutPrior</code> 建议相反的决策，须写入对应 <code>EditIntent.rejectedAlternatives</code>。
3. <b>每个模块必须通过消融实验才能保留。</b> 相对 0.1 的 B1 基线，无明确增益的模块应关闭或删除。
4. <b>只提取统计特征，不复制内容。</b> 参考视频与人类工程文件只用于抽取风格/决策统计，不复用其画面、声音或文字内容。
5. <b>沿用 0.1 的全部硬约束。</b> 原文件只读、ProductionPolicy、预算预留、迟到结果不得覆盖新 revision、不伪称成功，等等，全部保持不变。

## 3. 模块 A：剪辑意图图（Edit Intent Graph）

### 3.1 问题

当前输出只记录"第 3:12 切到海边"，没有记录"为什么"。反馈（如"这里再燃一点"）无法映射到可执行的修改。

### 3.2 需求

- <b>R-A1</b> 每个 Scene Contract 下可挂载一个或多个 <code>EditIntent</code>。
- <b>R-A2</b> 每个影响成片的 Edit Operation 应能引用 <code>intentId</code>（无引用时标记为"无意图"，并可在审片中被提示）。
- <b>R-A3</b> <code>EditIntent</code> 必须记录：意图类型、目标感受、证据引用、被放弃的备选方案。
- <b>R-A4</b> 用户的自然语言反馈应被<b>编译</b>为"对哪些意图做何种修改"，再由系统计算受影响的最小任务集合（沿用 0.1 的 Scene Contract 版本依赖追踪）。
- <b>R-A5</b> 界面可选择性展示"为什么这样剪"，并允许用户修改<b>意图</b>而不是时间线。

### 3.3 意图类型（初始枚举，可扩展）

<code>HOOK</code>（钩子）· <code>SETUP</code>（铺垫）· <code>EMPHASIS</code>（强调）· <code>RHYTHM</code>（节奏）· <code>COVER_JUMP</code>（掩盖跳切）· <code>BREATHE</code>（喘息）· <code>PAYOFF</code>（回报/高潮）· <code>TRANSITION</code>（过渡）· <code>INFORM</code>（信息传达）

### 3.4 数据契约（建议）

```json
{
  "intentId": "intent_012",
  "sceneId": "scene_01",
  "intentType": "HOOK",
  "targetFeeling": "先给出最美的画面作为开场承诺",
  "timeRange": {
    "start": { "num": 0, "den": 30 },
    "end": { "num": 240, "den": 30 }
  },
  "evidenceIds": ["obs_103", "obs_221"],
  "rejectedAlternatives": [
    { "description": "延时摄影开场", "reason": "与整体温暖克制的调性不符" }
  ],
  "priorAdvice": { "cutPriorId": "prior_adv_007", "followed": false, "deviationReason": "…" },
  "revision": 2
}
```

### 3.4.1 反馈编译示例

| 用户反馈 | 编译结果 | 重算范围 |
| --- | --- | --- |
| "开头不够抓人" | 目标意图：<code>HOOK</code>；动作：提高钩子强度/更换钩子素材 | 仅 scene\_01 及其真实下游 |
| "中间太赶了" | 目标意图：<code>BREATHE</code>/<code>RHYTHM</code>；动作：在指定区间增加喘息 | 仅涉及区间 |
| "我不要这个转场" | 目标意图：<code>TRANSITION</code>；动作：替换转场方式 | 仅相邻两场景 |

### 3.5 最小版本（A0）

- 为 Scene Contract 增加 <code>intents[]</code> 与"理由"文本字段
- 固定意图枚举
- 导演输出时必须填写；QA 抽查"有操作无意图"的比例

### 3.6 验收（待校准）

- 意图覆盖率：影响成片的 Edit Operation 中带 <code>intentId</code> 的比例
- 反馈一次采纳率：用户反馈被正确映射并一次修改成功的比例
- 重算范围：反馈后实际重算的任务数 / 全部任务数

## 4. 模块 B：节奏谱（Pace Score）

### 4.1 问题

"节奏太拖/太赶"是主观描述，QA 无法自动检查，返工也无法定向。

### 4.2 需求

- <b>R-B1</b> 将成片按固定窗口（默认 5 秒，配置项，需实测）切分，每个窗口计算节奏能量。
- <b>R-B2</b> 节奏能量由多个<b>分量</b>组成，分量及权重可配置：
  - 切点密度
  - 语速（词/秒）
  - 画面运动量
  - 音乐/音频能量（响度、节拍密度）
  - 信息密度（字幕/图形/要点出现频率）
- <b>R-B3</b> 导演为每个作品给出<b>目标曲线</b>（来源：<code>CreativeProfile.paceCurve</code>、<code>CutPrior</code> 的体裁统计、<code>StyleSpec</code>）。
- <b>R-B4</b> QA 计算<b>实测曲线</b>，识别与目标偏差最大的区间，输出"偏差报告"。
- <b>R-B5</b> 偏差区间触发<b>定向修复</b>（先确定性修复：换镜头/调速度/增减停顿/调音乐，而不是整片重做）。
- <b>R-B6</b> 对独立生成片段的跨章节统一校正，以节奏谱作为统一依据（对应 0.1 第 16.5 问）。

### 4.3 数据契约（建议）

```json
{
  "paceScoreId": "pace_001",
  "compositionRevision": 7,
  "windowSeconds": 5,
  "components": ["cutDensity", "speechRate", "motion", "audioEnergy"],
  "target": [0.30, 0.35, 0.40, 0.38],
  "measured": [0.31, 0.22, 0.41, 0.37],
  "deviations": [
    { "windowIndex": 1, "delta": -0.13, "suspectedCause": "cutDensity" }
  ]
}
```

### 4.4 最小版本（B0）

- 只计算"每分钟切点数 + 语速"两项
- 输出一条实测曲线，并与导演设定的目标曲线对比
- 偏差超过阈值（配置项）时在审片报告中标记

### 4.5 验收（待校准）

- 实测与目标曲线的平均偏差
- 定向修复后偏差的下降幅度
- 人工盲评中"节奏评分"与实测偏差的相关性（用于判断该指标是否有意义）

## 5. 模块 C：品味先验（Cut Prior）

### 5.1 问题

导演模型很强，但缺少"人类剪辑师在类似情境下怎么选"的经验参照。

### 5.2 数据来源与前提

- 来源：已收集的人类剪辑工程文件（含原始素材引用与最终剪辑决策）。
- <b>前提（必须先确认）：</b> 工程文件的使用授权（来源、是否可用于训练/统计、是否含第三方内容）。授权不明的文件<b>不得</b>进入样本库。
- 工程文件先转换为统一中间格式（只保留剪辑决策相关字段，剔除界面状态、缓存路径等噪声）。

### 5.3 样本定义

<b>一个样本 = 一个人类剪辑决策点 + 其上下文特征 + 人类选择。</b>

| 字段分组 | 示例字段 |
| --- | --- |
| 决策点 | 位置（有理数时间）、决策类型（切/不切、硬切/J-cut/L-cut、保留时长、插入 B-roll） |
| 前后语音上下文 | 是否句末、停顿时长、说话人变化、是否被打断 |
| 前后画面上下文 | 前后镜头景别/运动、连续同景别镜头数、是否有动作进行中 |
| 音频上下文 | 音乐节拍距离、响度变化、环境声连续性 |
| 作品上下文 | 体裁标签、目标时长、平台、整体节奏分段位置 |
| 人类选择（标签） | 实际决策及其参数 |

### 5.4 分阶段能力

| 阶段 | 内容 | 说明 |
| --- | --- | --- |
| <b>C0 统计版</b> | 从样本中计算体裁级统计：镜头时长分布、切点相对停顿的偏移、开头结构、B-roll 插入频率 | <b>不训练模型</b>；可直接喂给导演与节奏谱作为参考，工作量最小 |
| <b>C1 检索版</b> | 按情境特征检索 Top-K 相似决策点，给导演"类似情境下人怎么剪" | 需要特征与相似度定义 |
| <b>C2 顾问模型</b> | 微调小模型预测"此处人类会怎么选" | 作为 Specialist Worker（Cut Advisor）；只提供建议，不直接写入时间线 |

### 5.5 导演使用协议

1. 导演在做切点/镜头选择时，可请求 <code>CutPrior</code> 建议。
2. 导演可采纳或偏离；<b>偏离必须填写理由</b>，落入 <code>EditIntent.priorAdvice</code>。
3. <code>CutPrior</code> 不得绕过 Scene Contract、ProductionPolicy 或质量门禁。
4. 先验建议必须附带<b>依据摘要</b>（相似样本数、体裁、统计范围），不得只给一个裸结论。

### 5.6 评测方法

<b>数据划分：</b> 按<b>作品/创作者</b>划分训练集与留出集（不是按切点随机划分，避免同一作品泄漏）；按体裁分层，保证每个体裁都有留出样本。

| 指标 | 白话定义 | 说明 |
| --- | --- | --- |
| 切点重合率（帧容差） | AI 的切点中，有多少落在人类切点前后 N 帧内 | N 为配置项，需实测（建议同时报告多个容差） |
| 保留片段 IoU | AI 保留的素材区间与人类保留区间的重叠比例 | 衡量"取舍"是否一致 |
| 镜头时长分布差异 | AI 与人类的镜头时长分布有多接近 | 可用 KL 散度或 Wasserstein 距离，选一种并固定 |
| 决策类型准确率 | 硬切/J-cut/L-cut 等类型预测是否一致 | 仅对 C1/C2 适用 |

### 5.7 风险与约束

- <b>品味偏差：</b> 样本只代表样本作者的品味，不等于"好"；必须配合人工盲评，不能把"像人类"当成"更好"。
- <b>风格塌缩：</b> 过度依赖先验可能使作品千篇一律；导演需要偏离机制，评测需要观察多样性。
- <b>体裁错配：</b> 不同体裁的先验混用会得到模糊平均值；样本必须带体裁标签，且检索时分体裁。
- <b>版权与隐私：</b> 样本库只存剪辑决策统计与特征，不存可还原的内容。

## 6. 模块 D：风格规格（Style Spec）

### 6.1 问题

外行难以用语言描述想要的风格，但可以给出喜欢的参考视频。

### 6.2 需求

- <b>R-D1</b> 用户可提交 0 到 N 个参考视频（可选）。
- <b>R-D2</b> 系统测量参考视频，生成 <code>StyleSpec</code>：
  - 镜头时长分布、切点节奏
  - 字幕样式与密度（每分钟条数、位置、字号档位）
  - 音乐进入时间点、能量曲线
  - 色调方向（偏暖/偏冷、对比度档位）
  - 开头结构（前 N 秒的构成）
- <b>R-D3</b> 系统生成 <code>CreativeProfile</code> <b>草案</b>，向用户确认"风格层面"，不要求逐镜头确认。
- <b>R-D4</b> <code>StyleSpec</code> 只保存<b>统计特征</b>，不保存参考视频的画面、声音、文字内容。
- <b>R-D5</b> 用户对草案的修改（如"比参考更慢一点"）应被记录为偏好信号（见 8.3 偏好记忆）。

### 6.3 数据契约（建议）

```json
{
  "styleSpecId": "style_003",
  "source": { "type": "USER_REFERENCE", "referenceCount": 2 },
  "shotDuration": { "medianSeconds": 2.8, "p10": 1.2, "p90": 6.5 },
  "caption": { "perMinute": 12, "sizeTier": "LARGE" },
  "music": { "firstEntrySeconds": 15 },
  "color": { "direction": "WARM", "contrastTier": "MID" },
  "openingStructure": "HOOK_THEN_TITLE"
}
```

### 6.4 验收（待校准）

- 风格距离：成片的实测统计与 <code>StyleSpec</code> 的距离
- 草案确认率：用户一次确认或仅小改的比例

## 7. 模块 E：观众模拟、审片校准与回看策略

### 7.1 虚拟观众（Audience Simulation）

- 多个观众角色（如"首次观看者""目标受众""挑剔的剪辑师"）分别观看粗剪/成片，输出"想离开的时间点与原因"。
- 输出 <code>AudienceReport</code>，其中的"流失点"直接驱动定向修复（先确定性修复）。
- 早期以代理指标为主（节奏谱偏差、钩子质量、信息密度）；若未来有真实发布后的留存数据，再用于校准（需单独的数据与授权评审）。

```json
{
  "audienceReportId": "aud_001",
  "compositionRevision": 7,
  "personas": ["FIRST_TIME", "TARGET_AUDIENCE", "CRITICAL_EDITOR"],
  "dropPoints": [
    { "timeSeconds": 74, "persona": "FIRST_TIME", "reason": "信息重复，节奏变慢", "linkedIntentId": "intent_031" }
  ]
}
```

### 7.2 审片校准（Review Calibration）——<b>审片模型必须先被校准</b>

- <b>R-E1</b> 在把 Director Review / 虚拟观众结论用于触发重规划之前，必须先测量其可靠性。
- <b>R-E2</b> 校准集：同一素材的"人类成片"与"已知较差版本"（可人为构造：乱序、过长镜头、音画错位等）；检验审片能否分出高低。
- <b>R-E3</b> 记录审片模型与人工盲评的一致率；一致率低于阈值（配置项）时，审片结论<b>仅作提示</b>，不得自动触发全局重规划。
- <b>R-E4</b> 避免"导演自评自己"的偏好：审片与导演使用不同模型或不同提示设置，并记录各自版本。

### 7.3 按信息价值回看（Value-of-Information Review）

对每个候选回看对象计算优先级（公式为设计假设，需实测）：

```txt
回看优先级 = 出错概率 × 叙事重要度 ÷ 回看成本
```

- 出错概率：可来自低置信度、多模型分歧、跨模态不一致。
- 叙事重要度：来自 Narrative Blueprint（钩子、高潮、关键转折权重高）。
- 回看成本：时长、分辨率、模型调用费用。
- 此机制直接用于回答 0.1 第 16.3 问：比较 0/1/2/3 次回看对质量的边际提升。

### 7.4 结构锦标赛（Structure Tournament）

- 在 Story Lock 前，由导演提出 K 个结构原型（不同钩子/叙事线/排序，K 为配置项）。
- 仅使用<b>确定性剪辑</b>拼装低清版本（不触发付费生成）。
- 由虚拟观众与节奏谱对各版本打分，选出前 N 个（默认 2）进入下一步；也可作为多版本选项提供给用户。
- 目的：避免导演被首个方案锚定；用户的选择可作为偏好信号。

## 10. 评测与验收

### 10.1 消融实验矩阵

在同一批金样与素材上，至少比较：

| 组别 | 配置 |
| --- | --- |
| B0 | 现有 V6 初剪流程 |
| B1 | 改进素材索引 + 单导演串行（沿用 0.1） |
| B1+A | B1 + EditIntent |
| B1+B | B1 + PaceScore 定向修复 |
| B1+C0/C1/C2 | B1 + 对应阶段的 CutPrior |
| B2+全部 | 0.1 的 B2 + 本提案模块 |

<b>保留规则：</b> 模块相对 B1 无明确且可重复的增益（质量不明显下降且至少一项指标改善、成本可接受），则不进入默认流程。

### 10.2 指标汇总

| 层 | 指标 |
| --- | --- |
| 决策相似度 | 切点重合率、保留片段 IoU、镜头时长分布差异 |
| 节奏 | 实测与目标曲线偏差、修复后偏差下降 |
| 反馈效率 | 反馈一次采纳率、反馈后重算范围 |
| 审片可靠性 | 与人工盲评一致率、校准集区分度 |
| 成品质量 | 人工盲评（叙事、节奏、风格、事实忠实） |
| 成本与时延 | 新增模块的额外费用与耗时 |

### 10.3 拟定门槛（待实测校准，不伪称已达成）

- <b>硬门禁（沿用 0.1 P0）：</b> 原文件不被破坏；用户禁用能力不得执行；总支出不超授权；迟到结果不覆盖新 revision；输出可追溯到源素材。
- <b>新增硬门禁：</b> <code>CutPrior</code> / <code>StyleSpec</code> 不得包含可还原的第三方内容；审片一致率未达门槛时，审片结论不得自动触发全局重规划。
- 各指标具体阈值由 AP-21 的基线评测后确定，<b>不预填数字</b>。

## 11. 新增失败模式与约束

| 失败模式 | 说明 | 约束 |
| --- | --- | --- |
| 把"像人类"当成"更好" | 先验只反映样本作者的品味 | 配合盲评；记录多样性；允许并要求记录偏离 |
| 风格塌缩 | 过度依赖先验导致千篇一律 | 导演偏离机制；评测中加入多样性观察 |
| 指标驱动的机械剪辑 | 为贴合节奏曲线而牺牲叙事 | 节奏谱只触发修复建议；创作取舍仍归导演；叙事评价单独评测 |
| 审片自洽陷阱 | 导演与审片使用同源偏好 | 模型/提示分离；审片校准 |
| 意图字段流于形式 | 导演为填而填 | 抽查意图与操作的一致性；反馈编译的采纳率反向验证 |
| 样本泄漏 | 训练与留出集来自同一作品 | 按作品/创作者划分 |
| 授权不清的工程文件 | 使用了无权使用的数据 | AP-16 授权核查为前置门禁 |
| 参考视频被"复制" | 风格解析滑向内容复用 | 只存统计特征；评审时检查是否可还原内容 |

## 最终建议

<b>不要同时做五个模块。</b> 建议顺序：

1. <b>先做金样集与 C0 统计版（AP-16 到 AP-18、AP-21）</b>：有数据、可量化，并为后续所有改进提供基线。
2. <b>再做 A0 与 B0（AP-19、AP-20）</b>：成本低，让"为什么这样剪"和"节奏是否合适"可被检查。
3. <b>然后做审片校准与反馈编译（AP-23、AP-24）</b>：保证闭环可靠。
4. <b>最后做 StyleSpec、虚拟观众、结构锦标赛与 C1/C2。</b> 前面模块没有被证明有效，就不要扩大投入。

每一步都要对 B1 做消融，证明有增益才保留。这些是设计假设，<b>不是已验证的结论</b>。
