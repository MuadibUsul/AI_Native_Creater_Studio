## 0. 决策摘要

ANCS 不应被改造成“字幕转写 → 视频分类 → 一次性大模型规划 → 批量调用生成工具”的脚本。新增的核心是 <b>具备主动感知、全局导演判断、可恢复任务图和最终成片审片能力的自主制作系统</b>。

在现有“共看片室交互式剪辑”之外，新增 <b>自主制作模式</b>：用户在开工前一次性提交作品意图、成片目标、风格偏好、硬性限制与预算/身份授权，AI 完成素材理解、创作构思、粗剪、视听制作、内部审片、自我修复与交付；默认无需每个镜头向用户请示。完成后用户仍能进入原有共看片室对同一 ProjectDocument 做非破坏性精修。

<b>核心原则：真人与实拍素材是第一等资产；生成式镜头是受控的补充能力，不是默认替代品。</b>

### 已确认的产品意图（来自本轮讨论）

1. 通用剪辑工具，覆盖真人拍摄、Vlog、口播、教育、知识解说、游戏、娱乐、纪录类等，不为每个类型写一套独立流水线。
2. 上传后先做基础素材理解：语音转写、画面内容识别、细节标签、虚拟切段、语气口及其他编辑候选边界；分析层不提前判定内容“有用/无用”。
3. 专业 AI 导演（可选 Claude Opus）通读素材索引并按需回看原视频，自主选择叙事结构和镜头语言。
4. 导演按作品目标调动确定性剪辑、字幕、Remotion、音频、图片/视频生成、HeyGen 等能力，跨片段并行生产。
5. 局部任务返工不能无故阻塞与其无依赖的任务；必要时可回退或局部重规划。
6. 对拍摄遗漏、缺失转场或解释性镜头，可以在符合授权与真实性约束下使用生成式素材补拍。
7. 用户事前给出需求、风格和预算后，正常生产过程中无需反复确认专业创作方案。
8. 保留此前点/线/面/时间轴精确定位、流式语音、交互精修、真实素材非破坏性剪辑与专业面板的长期目标。

## 1. 对原始构想的专业校正

| 原始构想 | 风险/认知盲区 | 建议约束 |
| --- | --- | --- |
| “先转字幕，字幕给出大致理解” | 无对白视频、音乐、视线、表演、游戏事件与情绪节奏无法从字幕推导 | 音频转写、非语音音频事件、视觉总览、镜头边界、元数据并行预处理；最后进行跨模态融合 |
| “把视频剪碎” | 物理切段可能丢失动作的前因后果、气口、镜头连续性、音画同步 | 源文件不可改；建立可重叠多尺度虚拟片段、语义节拍与编辑候选边界 |
| “导演看完一遍后出方案” | 一次决策容易被粗略标签误导；真正的创作判断还取决于粗剪效果 | 先形成可修改的全局制作蓝图，导演有工具可主动观看/倾听原片及组装结果，必要时增量重规划 |
| “工具全部并行” | 部分任务依赖脚本、音轨时长、统一风格或前置镜头；盲并发导致废单 | 有向无环任务图 DAG + 动态资源配额 + 关键路径优先 + 可失效/复用缓存 |
| “生成不满意就打回” | 无界重试造成费用失控及不同版本的结果覆盖 | 评分依据、明确失败原因、最大尝试次数、优先确定性修复、可接受的替代方案与预算熔断 |
| “AI 可以补拍” | 身份/口型/服装/空间/光照连贯性差、事实型内容误导、权利风险 | 真实素材复用优先；缺镜头评估、身份授权、连续性约束、合成来源追踪与事实类用途约束 |
| “不需要用户中途确认” | 与 V6 既有付费生成逐次确认及身份授权规则冲突 | 一次性授权的是预算上限和允许的能力，不是无限支出/无限身份使用；授权不足时自动安全降级而非擅自付费 |
| “导演只要最强大模型即可” | 一次把长视频索引、全部工具、所有镜头塞进上下文不可扩展，且成本高 | 分层项目记忆 + 检索 + 证据链接 + 专项执行 Agent；强导演模型用于高价值创作决策，不代替确定性编辑内核 |

## 2. 产品边界与两个用户体验

### 2.1 两种协作模式（同一工程内核）

<b>A. 自主制作（新增）</b>：上传素材 → 写一句需求/选择可选风格 → 设定项目硬约束、预算与可用生成资产 → 点击制作 → 自动进行；显示粗剪、各章进度与最终结果；异常只在用户授权范围内自动降级，不能静默违反限制。

<b>B. 共看片室（继续保留）</b>：用户与 AI 共同看片，用鼠标点、线、面、时段和语音发出定位编辑命令，按原有可预览、采用/撤销、局部重渲流程执行。

两者共享 <code>ProjectDocument</code>、操作日志、<code>RenderPlan</code>、资产库、字幕轨、版本历史、成本台账。两者不是按视频类型区分；用户可在自主成片后转交互精修。

### 2.2 三种内容模式与自主/交互两条独立维度

- <code>FOOTAGE_EDIT</code>：只剪真实素材，允许确定性效果，不产生生成视频/拟声人脸。
- <code>HYBRID</code>：真实素材为主，允许在授权范围内添加 AI 生成镜头、解说、效果和数字人。
- <code>GENERATIVE</code>：可以从脚本或提示词主导生成，但仍使用同一 ProjectDocument 和编辑内核。

<b>自主/交互是工作方式；FOOTAGE\_EDIT/HYBRID/GENERATIVE 是可用内容来源约束，两者绝不能混成一个枚举。</b>

### 2.3 成功的用户体验

普通用户只需说：“把这40分钟旅游素材剪成6分钟、温暖克制、不要 AI 生成真人镜头、不改原话、制作预算不超过20美元”，系统自主完成一版可回放、可继续编辑、可导出的视频。用户无需逐个批准转场和字幕；全程也不能破坏其硬约束。

## 3. 正确的总体架构：感知、编辑性素材索引、导演、执行、审片

```txt
原始视频 / 图片 / 音频 / 文章 / 参考风格
       │ [只读，内容哈希与授权证据]
       ▼
Media Ingest  ── 音视频代理 / 音轨分离 / 统一时间基 / 完整性校验
       │
       ├── ASR + 说话人 + 词级时间戳 + 静音/呼吸/气口候选
       ├── 非语音事件：配乐、笑声、掌声、节拍、环境音
       ├── 视频场景：镜头边界、相机运动、光照、清晰度、对象
       └── Elorian/Gemini 等视觉模型：分层回看、动作/情绪/人物
       ▼
Multimodal Asset Index（证据可追溯、多尺度虚拟片段）
       │                               ▲
       ▼                               │ 按需主动回看/细听
Director（全局作品意图、叙事蓝图、制作约束）────────┘
       │
       ├── 第一版：可播放粗剪、保留占位资源、稳定故事骨架
       ▼
Production Graph（动态任务 DAG）
       ├── 字幕、音频、音乐、调色、转场、Remotion 等确定性任务
       ├── 素材重新检索和 B-roll 选镜
       ├── AI 图像/视频补镜头、授权数字人/声音任务
       └── 并发预算、依赖/失效、重试/回退、任务工单
       ▼
Versioned Composition / RenderPlan / Partial Rendering
       ▼
Technical QA + Creative Review（导演实际看粗剪与成片）
       ├── 检测到局部技术问题 → 定向修复
       ├── 检测到叙事冲突 → 影响范围重规划
       └── 通过 → 作品版本冻结、导出、成本和来源台账
```

导演不能仅通过文本索引“读懂”全部视频。真正的导演应使用证据检索工具，主动查看关键视觉段、听对白停顿、检查演员表情，并在时间线产生初版后“看片”，而不是评估一张任务 JSON。

## 4. 基础素材理解与非破坏性切分

### 4.1 预处理工作流

1. <b>登记</b>：计算内容哈希，探测编码、帧率、VFR（可变帧率）、时长、旋转元数据、多音轨、多语言、尺寸及拍摄时间；原文件永久只读。
2. <b>生成代理</b>：缩略图、波形、低码率可寻址预览、音轨分离和关键帧预览；复用既有 FFmpeg 能力。
3. <b>并行基础分析</b>：语音转写、词级对齐、说话人分离、非语音声音事件、镜头边界、颜色/运动/质量测量。
4. <b>分层视觉分析</b>：低采样率全局概览；对高动作密度、剪辑跳点、OCR 细字、多人对话和不确定片段进行局部高精度识别。
5. <b>跨模态对齐</b>：将文字、音频、画面、对象、行为链接到源文件精确时间码；保留证据、模型版本和置信度。
6. <b>虚拟切段</b>：产生候选剪点及其原因，不删除、不认定没价值；支持上下文重叠与编辑时重新组织。

### 4.2 避免“只有字幕能理解”的盲区

建立至少五层索引：

- <b>素材层（Asset）</b>：源文件身份、存储、版权、语言、摄制属性和时间基。
- <b>感知层（Observation）</b>：人物、说话词、物体、动作、音乐节拍、画面技术特征及证据区间。
- <b>语义层（Moment）</b>：笑点、观点、示例、问答、冲突、游戏击杀、风景转场、演示步骤等候选“事件”。标记未知而非编造。
- <b>编辑层（Candidate Cut）</b>：气口、停顿、句末、动作匹配、运动断点、可延长的 handles，以及禁止切断区间。
- <b>创作层（Narrative Use）</b>：由导演赋予的用途，例如“钩子”“伏笔”“反应镜头”“解释”“高潮”；<b>只能由创作层判断是否采用</b>。

### 4.3 时间与切点质量

- 音频端使用样本/词级对齐；视频端使用帧/有理数时间，不在业务核心使用浮点毫秒。
- 不要把气口一律删除：呼吸、犹豫和停顿可能具有表演价值；先标记为候选。
- 切点必须存储上下文 <code>handles</code>（例如前后可延伸帧范围）及禁止切断的同步约束。
- 长镜头可生成重叠的动作片段；同一原视频可同时服务多个候选段，素材库不强制“一秒只属于一个片段”。
- VFR 视频必须维护源时间映射；跨音频采样率、帧率和代理尺寸时，导出与原片对齐。

## 5. 导演认知与决策架构

### 5.1 导演不是“一个超大 prompt”

采用 <b>一个创作权威 + 多个专业执行单元</b>，不要让多个创作 Agent 各自决定整部影片如何拍。

- <code>Creative Director</code>：作品核心命题、受众、节奏、情绪弧线、保留/删减取舍、结构变化和冲突裁决。高能力模型，如经实测可用的 Claude Opus；型号可替换。
- <code>Media Researcher</code>：在索引中检索候选素材，提交带时间码的证据，不自行决定最终成片价值。
- <code>Production Planner</code>：把导演蓝图拆解为有依赖、可并行、可核算的制作任务，估算成本与资源。
- <code>Specialist Workers</code>：字幕、音频、动效、镜头生成、数字人等工具型执行者；优先确定性实现。
- <code>Quality Inspector</code>：视频黑帧、音画不同步、字幕遮挡、口型错位等机器质量门禁。
- <code>Director Review</code>：审看粗剪和完整成片的叙事节奏与风格一致性；能够提出局部/全局变更。

“专业”是设计目标，需要由评测证明，不能把高端模型名字视为专业能力保证。

### 5.2 导演的两层计划

<b>Narrative Blueprint（全局，慢变量）</b>：作品一句话主旨、开场承诺、叙事结构、目标观众、情绪曲线、节奏分布、事实约束、风格设定、必须保留的素材、绝对禁用项及镜头/旁白/声音的整体一致性。

<b>Scene Contract（局部，可重排）</b>：每章/镜头的叙事功能、预估时间窗、所需素材类型、输入依赖、画面与音频连续性、允许替代方案、质量目标、关键情节和是否允许 AI 补足。

导演可以修改 Scene Contract，但必须追踪哪些下游任务依赖其版本。不能把某一版首轮规划当作永远不变的命令。

### 5.3 先有可看的粗剪再加重制作

创作流程分为两轮锁定，而不是“所有镜头同时生成”：

- <b>故事锁定（Story Lock，软锁）</b>：先用真实素材、临时字幕、低成本占位图/轨拼出可播放全片；验证故事本身成立。
- <b>镜头制作（Shot Production）</b>：在稳定的段落及场景约束上并行制作图解、B-roll、补镜头、配音、动效等。只有语义稳定、权限和预算满足的任务才能进入高成本生产。
- <b>最终审片（Final Review）</b>：全片观看，检查节奏、信息缺口和连贯性；可释放 Story Lock 并增量修正，但只重算依赖受影响的节点。

对不会花钱且易复算的确定性操作，可以更激进地早并行；对昂贵、耗时且容易因脚本变化失效的生成操作，启动时间应更保守。

## 6. 并行任务图与可恢复制作

### 6.1 任务类型、依赖与生命周期

一个任务至少包含：<code>taskId</code>、<code>projectId</code>、<code>planRevision</code>、<code>sceneId</code>、<code>kind</code>、<code>inputsHash</code>、<code>dependsOn[]</code>、<code>providerCapabilities[]</code>、<code>priority</code>、<code>estimatedCost</code>、<code>reservedCost</code>、<code>attemptLimit</code>、<code>deadlinePolicy</code>、<code>fallbacks[]</code>、<code>qualityCriteria</code>、<code>status</code>、<code>resultArtifactHash</code> 和不可覆盖审计记录。

合法状态示例：<code>PLANNED → READY → RUNNING → VERIFYING → SUCCEEDED</code>；或 <code>RETRYABLE_FAILED / FALLBACK / BLOCKED / CANCELED / SUPERSEDED</code>。

禁止：重复回调覆盖新 revision；高成本任务无限重试；已取消任务晚到结果自动写回作品；未通过授权检查仍派发任务；两路编辑同时写入相同时间线状态而没有 revision 冲突校验。

### 6.2 并发策略

- <b>依赖就绪</b>：只调度所有硬依赖均满足的节点，独立节点不相互阻塞。
- <b>关键路径优先</b>：结合预估运行时间、下游扇出、资源瓶颈和故事重要程度安排优先级；不简单固定 60 秒一片等速分组。
- <b>按资源池限流</b>：CPU、GPU、视频模型 API、生成视频 API、音频 API 各有独立并发与速率配额（RPM/TPM）；自动处理 429、超时及指数退避。
- <b>预算预留</b>：付费任务入队前核验权限并预留上限，计费后按实际消耗对账；状态不明确时停止自动再次扣费、转入待对账。
- <b>版本化提交</b>：执行成果先写入不可变 Artifact，只有版本一致、验证通过才以 ProjectDocument 操作合并，不能让 Worker 直接改前端状态。
- <b>局部失效</b>：全局蓝图修改时只取消/重排依赖被改变字段的节点，未受影响任务的结果按内容哈希复用。
- <b>软占位</b>：中段重生成时其他场景继续；时间线仍可通过占位资产播放粗剪，但最终导出必须明确标记未完成片段或采用替代镜头。

### 6.3 调度示例

- <code>S1</code> 整理素材并构建索引；<code>S2</code> 确立全局叙事结构；<code>S3</code> 生成低清粗剪。
- <code>A4</code> 第2分钟 B-roll、<code>A5</code> 第4分钟字幕、<code>A6</code> 第7分钟动效、<code>A7</code> 第9分钟配乐可根据依赖并行。
- <code>A4</code> 失败时仅 <code>A4</code> 及依赖其<b>成功产物</b>的后续节点暂缓；<code>A5/A6/A7</code> 继续。
- 如 <code>A4</code> 失败使故事高潮不能成立，导演将蓝图从 revision 3 调整为 revision 4，调度器仅重算受影响场景及其真实下游节点。
- 未受影响的已渲染片段按已有 RenderPlan 内容哈希缓存复用。

### 6.4 返工策略（最多有限次数，值为配置项）

1. 先判断原因：素材缺失、技术失败、质量门禁失败、风格偏差还是故事结构错误。
2. 先确定性修复（剪点/混音/字幕/换已有素材），其次再次调用同类生成模型，再次才考虑换供应商。
3. 每次返工必须提供失败证据和精确修改约束，不允许让工具盲目重新生成同一个提示词。
4. 超出尝试、预算或授权范围，按预设降级：现有镜头替代 / 解释性图形 / 留白 / 安全失败交付，不得伪称成功。

## 7. 缺镜头的主动发现与 AI 补拍

### 7.1 自动检测，不是直接生成

每个 Scene Contract 对照现有索引，识别以下缺口：

- 信息缺口：口播讲到的对象没有相应画面、示例或图表。
- 叙事缺口：关键动作未交代、地点与时间发生跳跃、缺乏反应镜头或建立镜头。
- 视觉缺口：镜头角度/景别过于单一、长时间相同构图、转场不顺。
- 连续性缺口：人物姿态、光线、服装、空间方向不一致；AI 生成前先确定是否可能通过剪辑解决。
- 声音缺口：没有环境声、音效承接或可用人声片段。

### 7.2 补救优先级（成本/真实性约束）

1. 在现有实拍素材重新搜索镜头（含未采用时段）。
2. 使用原片的可接受变体：裁切、缓动、局部放大、J/L-cut、声音桥接、定格、合理的反应镜头。
3. 制作可验证的图解、地图、屏幕文字或获得授权的素材库 B-roll。
4. 生成非写实插画、图形或背景。
5. 仅当明确允许且符合真实性约束时，生成写实补镜头、自己的数字人或克隆声音。

### 7.3 补拍保真约束

对写实补拍保存：角色/服装/场景/机位/光线/镜头运动参考、上下镜头色彩和运动趋势、口型与音轨时码，以及哪些部分来自真实拍摄、哪些来自 AI 生成。

<b>真实性规则</b>：不得把 AI 补造的事实画面、他人影像或声音伪装成真实证据；新闻、财经、纪录等事实导向场景必须强化源证据、身份授权与合成标记。对于不合适的镜头，选择图解或明确的重现方式。

<b>身份规则</b>：真人数字人/克隆声音需真实授权，授权范围、撤销、存储隔离和访问审计由服务端校验；用户预授权不等于可以模拟任意第三方人物。

## 8. 用一次性生产授权替代逐次创作确认

### 8.1 可事前锁定的政策

<code>ProductionPolicy</code>：

- 项目总预算上限、生成类任务单次上限、允许供应商/数据出境与存储地域、最大返工次数与制作优先级。
- 是否允许生成视频、写实人物、本人数字人、本人克隆声音、音乐库/第三方素材。
- 必须忠实保留的对白/语句、不能移除的镜头或人物、禁止虚构的数据与事实。
- 声明是否允许 AI 自行对镜头排序、删减、配音、字幕风格、速度和镜头变换做专业判断。
- 发生不确定授权/预算/外部计费状态时的降级规则。

这些是“创作授权与风险边界”，用户不必确认分镜、转场或每个字的字幕，但不能由导演推断用户授予了不存在的权利。

### 8.2 与现有 V6 的裁决冲突

V6 当前有“付费生成先报价、用户确认”和“数字人每次报价后确认”的规则。本提案建议<b>只在用户明确启用自主制作、并签署项目级预算/能力/身份授权时</b>允许机器在权限范围内直接消费；原有交互模式继续逐次确认，直至正式 ADR 接受新模式。不得在实现时偷偷绕过原有校验。

### 8.3 异常不打断生产

预算耗尽、某生成供应商失败、身份未授权等情况：优先自动采取已经允许的方案，并继续其他任务；无法完成核心交付时输出如实标注的草稿或失败报告，不伪造成功，也不默认请求用户逐镜头补充批准。

## 9. 可选视频预设：约束数据，不是独立流水线

预设格式是 <code>CreativeProfile</code>：

- <code>genre</code>：Vlog、口播、教程、游戏、知识解说、访谈、纪录、产品广告等仅用于提示与评测，不是硬编码路由。
- <code>audience</code>、<code>platformAspectRatio</code>、<code>targetDuration</code>、<code>language</code>、<code>paceCurve</code>、<code>captionDensity</code>、<code>soundIntensity</code>、<code>humorLevel</code>、<code>colorDirection</code>、<code>factualityPolicy</code>。
- <code>structureHints</code>：常见叙事结构建议，可自由偏离，不能压过真实素材和硬约束。
- <code>toolPreferences</code>：倾向或禁止某类生成方式，但所有通用能力仍通过工具注册表声明。
- <code>evaluationRubric</code>：该风格最重要的人工/机器验收维度。

典型差异：

| 类型 | 倾向性处理 | 易犯错误 |
| --- | --- | --- |
| Vlog | 建立镜头、环境声、情绪节奏、人物关系 | 快剪导致失去真实感、重复风景 |
| 口播 | 论点清晰、语义停顿、字幕易读、反应/示例 B-roll | 删除有表现力的停顿，机械去气口 |
| 教学 | 步骤完整、屏幕特写、准确的指示和分层图解 | 跳步骤、字幕遮挡界面、未经依据补动作 |
| 游戏 | 玩家身份、事件顺序、HUD、击杀/团战高潮、原声连续性 | 混淆玩家、重复剪辑当新事件、时间错序 |
| 知识解说 | 论点/证据对应、图解、数据来源、概念递进 | 图表虚构、超出原文事实、重动画轻论证 |

不选预设，也必须凭通用导演能力给出像样的第一版；预设只改变偏好、约束和评测标准。

## 10. 工具生态与责任界限

| 工具/引擎 | 合理职责 | 不应承担的职责 |
| --- | --- | --- |
| FFmpeg/现有编辑内核 | 修剪、速度、拼接、混音、转码、代理、终渲 | 决定叙事价值 |
| Remotion | 程序化动画、字幕动效、图表、可参数化视觉包装 | 随意替换全部镜头编辑内核 |
| ASR + 音频分析 | 转写、说话人、词级对齐、气口/声学事件 | 判断停顿“毫无意义” |
| Elorian Glimpse（候选） | 复杂事件、动作、局部视觉细节、主动回看 | 无证据的身份猜测、决定整部影片结构 |
| Gemini 或其他成熟视频 API（候选） | 长时概览、多模态交叉验证、低成本候选扫描 | 硬编码为唯一分析入口 |
| Claude Opus（候选导演） | 全局作品构思、视觉叙事、导演判断、冲突裁决 | 直接无校验修改数据库或执行危险代码 |
| HeyGen/授权语音 API | 经过授权的数字人出镜和配音 | 在无授权下模仿第三方 |
| 图/视频生成供应商 | 补镜头、合成 B-roll、局部场景生成 | 自动替换真实证据 |

所有外部服务一律通过现有 Provider Gateway / 能力注册表，凭据仅在服务端；供应商具体型号、API 可用性、单视频长度、速率限制、数据处理条款需单独实测后启用。

## 11. 核心数据契约（建议）

### 11.1 证据驱动的观察结果

```json
{
  "observationId": "obs_007",
  "assetId": "asset_001",
  "sourceRange": { "start": { "num": 120, "den": 30 }, "end": { "num": 176, "den": 30 } },
  "kind": "SPEECH_PAUSE_CANDIDATE",
  "attributes": { "speakerId": "spk_01", "pauseMsEstimate": 420 },
  "evidence": [{ "type": "AUDIO_RANGE", "sourceAssetId": "asset_001" }],
  "confidence": 0.88,
  "producer": { "provider": "asr-adapter", "model": "configured-model", "revision": "run_20261019" }
}
```

<code>confidence</code> 仅是供应商或校准器的声明，不等于可比较的跨模型客观概率；未知字段应留空，不构造不存在的证据。

### 11.2 可复用场景契约

```json
{
  "sceneId": "scene_05",
  "narrativeGoal": "解释转折原因并保留原话",
  "sourceEvidenceIds": ["obs_007", "obs_041"],
  "candidateAssetRanges": ["range_021", "range_049"],
  "durationRangeFrames": { "min": 120, "max": 210 },
  "needs": ["TITLE_OVERLAY", "REACTION_BROLL"],
  "permissions": { "mayUseSyntheticHuman": false },
  "continuity": { "mustPreserveDialogue": true, "precededBy": "scene_04" },
  "acceptance": ["no_dialogue_word_loss", "audio_video_sync", "narrative_continuity"],
  "revision": 4
}
```

### 11.3 操作与事务边界

- 资产识别与生成产物写入不可变 <code>Artifact</code>；项目权威仍是 <code>ProjectDocument</code> + 结构化 Edit Operations + revision log。
- <code>Narrative Blueprint</code>、<code>Scene Contract</code> 和执行 DAG 是可重建的规划视图；不应成为第二套“谁才是最终时间线”的真相来源。
- 同一操作先验证作品基本版本、素材可用性、成本/授权及时间范围，再原子提交操作日志，由组合投影器产生组合状态。
- 原有 V5 时间基、<code>RenderPlan</code>、Provider Gateway、原素材不破坏和缓存机制全部沿用。

## 12. 评测：不能只看能否导出视频

### 12.1 四层评价

1. <b>素材理解正确率</b>：词与说话人、视觉事件、身份一致性、镜头边界、候选切点、时间码漂移、未知声明的合理性。
2. <b>导演创作质量</b>：人工盲评叙事完整性、节奏、情绪、镜头语言、风格、事实忠实度；要求在“不选预设”时同样评估。
3. <b>并行生产效率</b>：从上传结束到首个可播放粗剪、整片可预览、最终导出的 P50/P95 时延；真实并发增益、等待/返工比例、任务复用比例。
4. <b>工程可靠性与成本</b>：超预算事件、孤儿付费调用、重复扣费、黑帧、音画偏移、静默违约、失败恢复时长、最终实际成本。

### 12.2 最小可复现评测集

- A：10分钟口播（停顿、改口、保留原句）；
- B：20分钟 Vlog（多机位、无人声风景、音乐及临场表演）；
- C：30分钟教学（屏幕字幕、演示步骤、图表真实引用）；
- D：60分钟游戏（HUD、跨局时间重置、重复精彩镜头和群战）；
- E：素材不足的故事（缺建立镜头、人物连续性、授权限制）；
- F：注入故障（视频生成返回 429、迟到回调、身份未授权、费用未确认、单场景重规划）。

需固定金样、记录真实模型版本与调用账单、至少在同一批视频中比较以下三个基线：

- <code>B0</code>：现有 V6 初剪流程。
- <code>B1</code>：改进素材索引 + 单导演串行执行。
- <code>B2</code>：改进索引 + 导演全局规划 + DAG 并发 + 最终审片。

只有 B2 的质量不明显低于 B1，且墙钟/成本/失败恢复有可重复收益时，才扩大并发。

### 12.3 拟定的验收门槛（待实测校准，不伪称已达成）

- <b>P0 硬门禁</b>：原文件不被破坏；用户禁用的生成能力不能执行；禁止无授权身份克隆；总支出不超过授权上限；迟到结果不能覆盖新 revision；输出引用能追踪到源素材；未校验任务不得宣称完成。
- <b>产品目标</b>：10–20分钟素材到第一版可播放粗剪，沿用 V6“≤10分钟”的既定目标；导出、费用、长视频性能均做实测，不填臆造的优化百分比。
- <b>质量检查</b>：所有生成补镜头及事实性图表有来源标记；音频/字幕同步与黑帧检测全部有自动验收脚本；主观成片质量由人工盲评并留存案例。
- <b>并发指标</b>：至少记录串行/4路/8路的实际耗时、P95 和计费差异，并观察质量、429 率和生成废弃率；最佳并发数来自实测而非先验固定。

## 13. 递进式开发任务（在真实 V6 基线上做增量）

### P0｜第一阶段：实现闭环而不是同时接十个模型

- AP-01：为上传素材扩展非破坏性多尺度索引：音频文字、音频事件、视觉事件、候选剪点、置信度和证据引用。
- AP-02：导演加主动检索与回看工具，能用源片区间与低清组装版本检查事实。
- AP-03：增加 <code>Autonomous ProductionPolicy</code> 与预授权预算/生成能力门禁；提出正式 ADR 裁决与 V6 逐次付费确认规则的共存关系。
- AP-04：导演输出 <code>NarrativeBlueprint</code>、<code>SceneContracts</code> 和版本化粗剪，在已有 ProjectDocument 内落地，不新建平行渲染格式。
- AP-05：先串行交付一条10分钟真实素材的“全自动粗剪 → 自检 → 可编辑成片”。记录基线成本、正确率与人工评价。

### P1｜第二阶段：制作图和并发重试

- AP-06：动态 DAG 编排、依赖边/资源池/关键路径、局部失效及版本化结果。
- AP-07：按资源独立限流，预算预留、费用对账、幂等键与超时回调处理。
- AP-08：有限重试与自动降级，支持局部任务失败时独立段继续制作。
- AP-09：整片低清审片 + 故事约束检测 + 定向重规划，检测全局修改造成的最小受影响任务集合。
- AP-10：接真实视觉 Provider（Elorian 作为候选之一），做字幕/视觉/跨模态联合评测而非仅通报接入成功。

### P2｜第三阶段：影视制作能力与后期一致性

- AP-11：素材缺口诊断与补救优先级；先用已有素材/图解，再用授权生成补镜头。
- AP-12：身份、服装、光照、场景、音色、镜头运动连续性及事实性来源门禁。
- AP-13：支持中间件输出（字幕、图形、配乐、数字人视频）独立可编辑轨道，不压死在成片里。
- AP-14：更多 genre 预设和无预设评测集；预设只作为数据，不改变通用导演逻辑。
- AP-15：自动生成说明书式可审计交付：原片证据、AI 合成来源、授权与账单摘要、问题与修复记录。

### 代码触点（必须先阅读实际现有实现，再确定最终函数位置）

- <code>apps/worker</code>：素材理解调度、生产 DAG、供应商任务、导演审片的工作流集成。
- <code>packages/contracts</code>：<code>Observation</code> / <code>SceneContract</code> / <code>ProductionPolicy</code> / <code>ProductionTask</code> / <code>Artifact</code> 的版本化契约。
- <code>packages/domain</code>、<code>packages/kernel</code>：维持唯一 ProjectDocument、纯函数编辑操作、revision 和投影器规则。
- <code>packages/providers</code>：Elorian / Gemini / Claude / HeyGen / ASR / Remotion 适配与真实/Mock 标记、成本与限流。
- <code>apps/web</code>：极简制作入口、章节进度和草稿预览；保留共看片室与高级时间线。
- <code>docs/V06/milestones/</code>、<code>docs/decisions/</code>：每个阶段真实验收、计费、失败证据与正式架构裁决；禁止历史 V4 N 账本扩写。

## 14. 推荐的交付交互

创建作品时仅暴露必要的几个选择：

1. 上传素材或开始一个空白工程。
2. 一句话说明成片目标、时长、受众与平台；风格预设/参考视频为可选。
3. 选择“只用我的素材 / 可以适量 AI 补足 / 以生成为主”；一次性授予项目内的预算和身份使用范围。
4. 开始制作。默认看到<b>作品而非技术编排</b>：首先显示不断更新的低清粗剪，其次是“第几章正在完成/哪些仍在补足”，展开后才可查看详细任务与费用。
5. 自主完成后交付可播放、可编辑的作品，并明确报告哪些采用原片、哪些使用了生成资产、哪些约束不能达到；随时进入共看片室继续编辑。

## 15. 最容易被忽略的失败模式与制度约束

- <b>幻觉传播</b>：一个错误的对象身份被写进全局摘要，会污染全部 Worker。身份证据须可追溯并能更正后失效相关观察。
- <b>声音先于画面失真</b>：观众会明显感知语义被切断、呼吸不自然和响度跳变；音频设计与故事规划不能被当作附属任务。
- <b>过度使用生成</b>：很多项目的真正价值在真人表演与真实事件。导演须以内容目标而非模型调用次数作为优化目标。
- <b>上下文过载</b>：全量帧、完整聊天和所有工具 schema 都塞给最贵模型，将造成高成本和不稳定；分层摘要必须附证据指针，必要时可主动回看。
- <b>创作指标错置</b>：高击杀识别率不等于好看的游戏视频；低剪辑成本不等于有效叙事；要同时测事件识别与成片评价。
- <b>无限提前生成</b>：大量尚未确定的镜头并行生成，会把队列吞吐提升变为废弃资产成本；高费用任务必须在依赖稳定后调度。
- <b>虚假的“全自动”</b>：权限不够时不能擅自生成，也不能假装结果已完成；由预授权的安全降级路径保证无人值守可终止。
- <b>供应商锁定</b>：Elorian、Claude、HeyGen、Remotion 均为候选能力/具体实施方式，不得形成不可替换的项目数据格式。

## 16. 需要后续用真实证据解决的问题

1. Elorian API 是否开放所需的原生视频/主动回看能力？视频大小与时长上限、并发/RPM/TPM、视频 token 计算和数据保留政策是什么？
2. 一段场景到底多少秒适合并发分割？应通过不同片长、重叠长度和事件密度测试决定，而非固定1分钟。
3. “导演真正看片”需要几次回看才能提升质量？按视觉信息缺口和阶段审片风险选取，不追求全片高 FPS。
4. 全自动模式允许哪些云端处理和数据出境选项？隐私敏感素材能否选择本地 ASR 和本地基础索引？
5. 独立片段生成后跨章节的音乐节奏、色彩、表演和声音混音如何做统一校正？应建立项目级风格与终混门禁。
6. 成本、吞吐、字幕质量、叙事评分达到什么水平，才能作为默认流程替代 V6 现有初剪？必须由评测决定。

## 最终建议

不要第一阶段就接入完整的多 Agent 生成矩阵。<b>先做“多模态理解 + 导演主动回看 + 自主粗剪 + 项目级授权 + 成片自检”最小闭环</b>，证明没有用户中途参与时也能剪出合格作品；再实现 DAG 并行、局部失效、补镜头和复杂视听生成。只有这样，ANCS 才会成为可以长期扩展到专业剪辑的产品，而非昂贵但不可靠的自动短视频流水线。
