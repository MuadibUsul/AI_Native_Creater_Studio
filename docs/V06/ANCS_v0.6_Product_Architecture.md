## 一、北极星

**AI 是你的剪辑师，你是放映室里的导演。**

把素材丢进去，AI 凭自己通用的剪辑、导演和调度能力剪出第一版；你边看边用鼠标指位置、用声音说怎么改，AI 当场在画面上改给你看。剪辑技巧由 AI 掌握，用户只表达"哪里不满意、要改成什么样"。想要某种特定风格时，可以额外选一个策略（可选功能），但 AI 剪片并不依赖策略。

可量化的目标：过去两三天的剪辑工作压缩到一小时左右，而且这一小时主要花在你自己的精修上。

## 二、用户与定位

- **通用型剪辑软件：** 专业人士能用，小孩也能用。新手把素材交给 AI 就能得到成片，像有一位剪辑师傅在帮他剪；想套某种风格时再选用"策略剪辑"；专业用户随时展开精细控制。
- **面向全球：** 中文和英文同为一等语言，覆盖界面、语音、字幕、策略说明和 AI 回应。首要市场是中国和美国。
- **服务对象：** 非专业创作者、博主、YouTuber、知识类和口播类作者。

## 三、体验原则（按优先级）

1. **"指着画面说一句就改好"是核心体验。** 第一版就出像样的成片同样重要，两者都要做到。
2. **AI 的能力是通用的，策略是可选的。** AI 的剪辑、导演和调度能力必须是通用的：对每个组件的调用、对整体的编排，都要做到最强、最通用，不依赖任何类型模板或策略包。策略剪辑只是给用户的一个可选小功能（第六节 6.6），不选策略时 AI 同样要剪出好片。
3. **确定性为骨，生成为局部。** 剪切、顺序、时长、调色、音量、字幕都是可精确再改的确定性操作。生成内容（特效、音效、补镜头）是放进时间线的独立素材，生成后能挪、能缩、能改时机，不需要重新生成。不做整段"抽卡"。
4. **AI 在画布上行动，少说话。** 目标明确就直接试改，只在有歧义、要花钱或需要解释结果时简短发言。
5. **改哪里渲染哪里。** 预览和定稿都只重算受影响的片段，整片其余部分复用缓存。
6. **所有 AI 改动都看得见、可撤销。** 每次改动是一个可回看的版本，AI 笔记记录你接受过的偏好并在后续沿用。
7. **面板干净，但能修到精致。** 精度来自三处：精确指点、必要时的直接拖动手柄、改完后在对象旁临时浮出的单个微调控件（比如"再亮一点"之后出现的亮度滑块）。不常驻成排的面板。
8. **花钱的事先说。** 重特效等付费生成先给预估成本，用户确认后才执行，不自动无限重试。
9. **约束是硬的。** "只剪我的素材""不要改我的原话"等要求由服务端强制执行。

## 四、产品形态：四层 + 三个入口

```
入口：素材（拍摄的视频/照片/音频） │ 文章（详细的提示词） │ 参考视频（文件或链接）
  ↓
① 理解  素材索引：镜头、人物、物体、动作、语音转写、节拍、精彩度
② 导演  AI 通用导演：读懂素材与你的一句话需求，决定讲什么、怎么讲、用哪些能力
          （可选输入：用户选用的策略 / 蒸馏出的风格 / 从你的修改中学到的个人偏好）
③ 初剪  AI 自由调度全部组件（剪辑内核、代码动效、生成、音效配乐、字幕、讲述……）剪出第一版并自检
④ 精修  共看片室：指 + 说 → 原地试改 → 采用/撤回；批注式审片 → 统一局部重渲 → 导出
```

导演与调度能力是通用的、贯穿 ②③④ 的核心（第六节 6.1—6.5）；策略只是 ② 的一个可选输入，不选时这一层照常工作。

### 4.1 首批视频类型（按可扩展方式实现）

| 顺序 | 类型 | 参照 | 关键手法 |
|---|---|---|---|
| 1 | 旅游 Vlog | — | 环境交代 → 细节 → 人 → 高潮 → 收尾；卡点剪辑；景别交替；环境声与转场音效；色调统一 |
| 2 | 知识解说 | 小林说 | 讲述主线 + 代码生成的图解动画（图表、示意、手绘感图形）；关键词大字；节奏服从讲述 |
| 3 | 娱乐 | Mr.Beast | 3 秒钩子；极快节奏；大字幕；音效密集；推拉变焦；持续制造悬念 |

这三类是**通用能力的首批打磨与评测目标**，不是三条写死的流水线：AI 的导演与调度代码不按类型分支，任何类型的素材都走同一套通用能力。新增类型等于新增一组评测素材（以及可选的风格预设，见 6.6），不改动核心；表里的"关键手法"是 AI 应当掌握的通用手法在该类型上的常见组合，也是评测的参考，不是硬性模板。

### 4.2 文章转视频（保留）

文章被视为"详细的提示词"。AI 先拆解文章：主题、段落、论点、数据、例子；再分配制作任务：讲述稿（你的声音或 TTS）、代码生成的图解、素材画面、字幕和章节；最后在同一时间线上成片，进入同样的精修流程。

实现上，文章转视频建立在组合模型（ProjectDocument）上，不再依赖旧的 Scene/Article 渲染流水线；新路径就绪后，旧流水线下线。

### 4.3 数字人与嗓音（保留，第二步）

档案里建一次你的形象和声音，项目自动继承。给出文案后，自动生成出镜画面和配音，作为片段插入时间线。只在你明确要求时调用，授权记录可查。

## 五、交互规范

### 5.1 指：鼠标确定"哪里"

| 指的方式 | 例子 | 系统记录 |
|---|---|---|
| 点 | 点字幕、点人、点物体 | 稳定对象 ID + 版本；真实画面里的人/物先记区域证据，需要时再分割或跟踪 |
| 线 | 画轨迹、画分界线、从 A 指向 B、笔刷涂抹 | 线的**用途**（轨迹 / 分界 / 指示 / 保护），用途不明时只问一次 |
| 面 | 框选、套索、笔刷区域 | 区分"固定在画面这个位置"和"跟随这个人/物" |
| 时间 | 时间带上拖选、多段选择、"刚才那句话" | 有理数时间范围（不用浮点毫秒），语义时段带转写证据 |
| 语义选择 | 点一个人说"这个人" | 找出他在全片出现的所有片段，可以一次性作用于全部 |

实际作用范围由四项共同决定：对象或区域、时间段、属性、版本。系统用一行标签实时显示自己的理解，例如"字幕「增长放缓」· 00:12.4–00:15.2 · 只改位置"。

### 5.2 说：流式语音确定"怎么改"

- 体验对标 OpenAI 实时语音对话：可以随时打断，转写边说边出，AI 回应简短。中英文都支持。
- 指代按**发话那一刻**绑定："这个""那里"取说出这个词时鼠标指着的东西。
- 半句话不执行，改口以最后一句为准，例如"删掉这段……不对，是把音乐去掉"。
- 三种"停"严格分开：停止播报、停止试改、取消付费生成。
- 文字输入与语音走同一会话，语音不是唯一通道。

### 5.3 改：原地试改与采用

识别到意图后，在原位置给出试改版本：简单修改 1–2 秒内出现，生成类修改先显示真实进度和占位。之后可以说"就这样"采用，可以继续微调，也可以撤回。说"再来一个"时，在原位并排给出 A/B/C 候选，之前的版本都保留。

### 5.4 批注式审片（移动端优先形态）

1. 看片时逐处标记问题：定位 + 一句话。
2. 和 AI 逐条讨论，确定每一处的修改方案。
3. 全部确定后一次性执行，统一做局部重渲，生成新版本。

桌面端同样可以使用这种模式。移动端先以网页（PWA）形态提供审片、批注和语音，不在手机上做完整剪辑。

### 5.5 体验指标（验收用，实测为准）

| 环节 | 目标 |
|---|---|
| 鼠标指向 → 目标高亮与标签 | ≤ 0.3 s（本地完成） |
| 语音说完 → 显示理解的目标与意图 | ≤ 1 s |
| 简单修改 → 可回放的试改 | ≤ 2 s |
| 局部重渲预览（3–5 s 片段，540p） | ≤ 5 s |
| 上传完成 → 第一版初剪（10–20 分钟素材） | ≤ 10 min，先出可看的部分 |

## 六、AI 的通用剪辑、导演与调度能力（核心）

### 6.1 定位

AI 的剪辑、导演和调度能力是这个产品的核心，必须是**通用的**：对各个组件的调用、对整体的编排，都要做到最强、最通用。

- 不依赖类型模板或策略包。任何素材、任何类型、任何一句话需求，AI 都从素材内容和用户意图出发，自己决定讲什么、怎么讲、用哪些能力。
- 策略剪辑（6.6）是给用户的可选小功能，只在用户选用时作为风格参考进入 AI 的上下文；它不改变、也不限制 AI 能调用的组件和编排方式。
- 导演层（规划、取舍、编排）使用当前最强的模型，不为省钱降级；降本放在理解和执行层（第十节）。

### 6.2 导演：从素材和意图到制作计划

AI 像一位真正的导演和剪辑师那样工作，每一步都是通用能力，不套固定流程：

1. **读素材：** 基于素材索引（第一层）理解有什么——人物、地点、动作、对白、情绪起伏、精彩瞬间、可用的声音。
2. **定意图：** 从用户的一句话、项目约束和 AI 笔记中确定目标：时长、受众、平台、语气、必须保留和禁止的内容。
3. **想结构：** 自己决定叙事结构、段落顺序、开场钩子、高潮和收尾；有策略时参考策略的结构建议，但素材不适配时可以偏离并说明原因。
4. **定手法：** 选镜头、定节奏和剪点、景别搭配、转场、调色、字幕、声音设计（环境声、音效、配乐、讲述）、视觉包装（代码动效、生成内容）。
5. **出计划：** 产出一份可检查的制作计划（结构 + 每段用什么素材和手法 + 需要调用哪些组件 + 预估成本），再交给调度层执行。

### 6.3 调度：统一工具目录，自由组合

- **统一工具目录：** 所有能力都以同一种形式暴露给 AI——编辑内核操作、素材索引查询、代码生成动效、生成式特效、音效与配乐、讲述（TTS/你的声音/数字人）、字幕、局部渲染、自检。每个工具声明输入输出契约、权限、预算、能力等级和是否可撤销。
- **自由组合：** AI 按计划任意组合工具，不存在"某类型只能用某几个工具"的限制。可以并行调用（例如同时生成三处动效和一段配乐），结果统一落到同一条时间线上，全部可撤销、可局部重算。
- **新能力即插即用：** 新增一种组件只需要在工具目录注册（契约 + 权限 + 预算 + 能力声明 + 评测），AI 立刻可以调用；不需要为某个类型写专用流水线。
- **长任务可靠：** 耗时或付费的调用经工作流引擎执行（可恢复、可取消、有预算、不无限重试），外部调用一律经 Provider Gateway 记录模型、费用和产物来源。

### 6.4 自检与修正

初剪和每次重要修改后，AI 低清渲染自己的结果，抽帧并听音频，按**通用质量标准**自查：叙事是否完整、节奏、跳切、黑帧、字幕遮挡、音量突变、音画同步、用户约束是否满足。不合格先自己修，再交给用户。用户选用了策略时，额外检查风格贴合度。

### 6.5 质量与评测

- **通用能力评测集：** 覆盖多种类型（旅游、知识解说、娱乐，以及日常、活动、产品介绍等），每类有金样素材和评分标准（人工评分 + 自动指标）；**以不选策略的条件为主**，衡量 AI 自己的导演与调度水平。
- **策略剪辑评测：** 只衡量"选用策略后是否贴合该风格"，不替代通用评测。
- 模型、提示词、工具目录的变更必须通过评测；初剪质量回归纳入 CI 夜间任务。

### 6.6 策略剪辑（可选功能）

**定位：** 给用户的一个可选小功能。用户想要某种特定风格时（例如"按这个博主的剪法来"），可以选一个策略；不选时 AI 照常用通用能力剪片。

策略包是一份可读、可改、可评测的**数据**，不含执行逻辑：

```
StrategyPack
  id / version / genre / locale[]          类型与适用语言
  summary                                  一段大白话说明（中英）
  knobs[]                                  给用户的少量旋钮：节奏、转场多少、色调强弱、字幕风格……
  editingDna                               可统计的剪辑手法：镜头时长分布、卡点比例、景别序列、
                                           转场/变速/推拉频率、调色倾向、字幕样式、音效习惯、开场钩子结构
  structureHints                           段落结构建议（如旅游：交代 → 细节 → 人 → 高潮 → 收尾）
  agentGuidance                            给 AI 的风格要点（提示词片段，按语言）
  styleRubric                              风格贴合度评分项
  evalSet                                  该风格的金样素材与期望（回归用）
```

- **使用方式：** 选用后，策略要点作为风格参考注入 AI 的上下文。AI 仍然使用全部通用能力规划和执行；策略与素材或用户要求冲突时，以用户要求和素材实际为准，并简短说明偏离之处。
- **不做的事：** 不为策略写专用执行流程；策略不能缩小 AI 可用的工具范围，也不能绕过通用自检。
- **个人风格：** 记录你每次修改的方向（"节奏总被我放慢""总删掉开头的空镜"），形成个人偏好，作为 AI 笔记沿用（与是否选用策略无关）。

### 6.7 蒸馏器（参考视频 → 策略包）

- **输入：** 支持上传文件，也支持粘贴链接（服务端抓取）。版权由项目所有者负责处理；系统只记录来源，不内置审查。
- **分析：** 复用素材理解管线：镜头切分、景别、运动、转写、节拍、字幕和图形样式、调色统计、音效事件。
- **输出：** 一份策略包（6.6），包括可读说明和旋钮，可以直接选用到你的素材上，也可以先编辑再用。
- **边界：** 承诺提炼手法和风格，不承诺还原原作者的工程文件；"品味"类特征只能部分提炼，会在说明里标出可信度。
- **顺序：** 先把通用导演与调度做好（不选策略也能出好片），再提供少量手写的可选风格预设，最后做自动蒸馏。

## 七、制作能力

### 7.1 确定性剪辑（内核）

插入、删除、切分、修剪、移动、错位、涟漪、变换、裁切、透明度、字幕、音频增益/淡变/声像、交叉淡化等，全部由编辑内核纯函数执行，并经操作日志记录，可撤销、可局部重算。这部分已在 V5 M1–M2 完成。

### 7.2 代码生成视频（核心能力）

轻特效、图解动画、文字动效、数据图表、粒子、光效、转场，都由大模型写代码生成：

1. **生成：** 模型根据意图、选区几何和时间范围，写出一个参数化动效组件（基于 Remotion/Canvas/WebGL 等受限运行时）。
2. **执行：** 组件在隔离进程中渲染（沿用现有 Custom Motion 沙箱：无网络、环境变量白名单、时限），输出带透明通道的图层。
3. **使用：** 图层放进时间线，参数（大小、位置、时机、颜色）事后可改，不需要重新生成。
4. **能力探测与回退：** 不假设所有模型都会写这类代码。对每个模型跑一组金样（提示 → 代码 → 渲染 → 检查），通过的才标为"可写动效"；不通过的模型回退到参数化模板库。
5. **候选：** "再来一个"会生成新的组件版本，旧版本保留，可以并排对比。

### 7.3 重特效与生成内容（带成本预估）

| 档位 | 做法 | 适用 |
|---|---|---|
| 1 | 代码生成特效（7.2） | 默认首选：最快、最便宜、最可控 |
| 2 | 生成一个带透明通道的元素（如一团爆炸）贴进选区，并跟随物体 | 爆炸、烟雾、火花等需要写实质感的局部效果 |
| 3 | 对选区做生成式重绘或补镜头（视频生成模型） | 前两档不够时；先报预估成本，生成后验证圈外画面未被改动 |

音效、配乐当场生成或从已授权库复用，采用后保存为真实素材。所有外部调用都经 Provider Gateway，记录模型、费用和产物来源（V5 已建立 Mock/真实区分）。

### 7.4 改哪里渲染哪里（可行，已具备基础）

V5 的 RenderPlan 已经能按时间范围编译和渲染；FFmpeg 后端也已有逐帧一致性测试。局部渲染的做法：

- **分段缓存：** 成片按固定时长切成段（例如 2 秒一段，每段是封闭 GOP，可以独立解码），每段用"该时段的 RenderPlan 切片 + 源素材哈希"做内容哈希缓存。
- **只渲染变化段：** 修改后只有内容哈希变了的段需要重渲；转场、跨段特效等会把影响范围显式扩展到相邻段。
- **拼接不重编码：** 未变化的段直接按流复制拼接；音频混音很便宜，可以整条重混，也可以分段并在接缝处交叉淡化。
- **预览分三档：** 浏览器即时叠加（零等待）→ 服务端低清局部渲染（540p 起，保证人物、文字清晰可辨）→ 定稿高清。
- **收益：** 2 分钟的片子只改一处约 4 秒，重渲量约为全片的 5%（含段对齐的余量）。

## 八、Agent 与 harness（第一版质量的来源）

本节是第六节通用导演与调度能力的实现方式。

- **上下文编译：** 每次请求只送必要信息：项目当前版本摘要、用户选区与指代、相关素材索引片段、AI 笔记，以及（用户选用时）策略要点。不灌入无限聊天记录，工具目录和系统提示等固定部分做提示缓存。
- **工具：** Agent 只能通过统一工具目录（6.3）改作品，每个工具都有契约、权限、版本和预算检查；工具集合对所有类型一致，不因类型或策略裁剪。
- **自检：** 按 6.4 的通用质量标准自查，不合格先自己修；选用策略时额外检查风格贴合度。
- **模型分工（可配置，按评测结果调整）：**
  - 规划与初剪：Opus 5.5；
  - 日常修改：Opus 5.5 低档推理或 Sonnet 5.5；
  - 大量画面理解：Haiku 5.5；
  - 实时对话前台：实时语音模型。
- **评测：** 见 6.5：以不选策略的通用能力评测为主，策略剪辑评测只衡量风格贴合度；模型、提示词或工具目录变更必须过评测。

## 九、架构：后端重，前端轻

```
客户端（轻）                     后端（重）
Web（Next.js）                   API（Fastify）：项目、素材、导出、计费、策略（可选）
  画布播放与叠加层                Realtime Gateway：双语流式语音、指代绑定、打断（新进程）
  时间带 / 对话栏                 Agent Runtime：通用导演、工具调度、自检
  临时微调控件                    Workers：素材理解 / FFmpeg 渲染 / 代码动效沙箱 / 生成调用
Windows：桌面壳包装同一 Web       Provider Gateway：模型路由、预算、计量、Mock 显式化
移动端：PWA 审片与批注            编辑内核 + 操作日志 + RenderPlan + 工作流引擎（V5 已建）
```

- **区域路由：** 中国大陆用户无法直接使用部分海外模型服务（例如 OpenAI 实时语音），Gateway 需要按地区路由到可用的供应商，例如国内的实时语音服务。具体供应商在 V6-2 选型，界面和协议保持一致。
- **国际化：** 界面文案中英双语（当前代码以中文为主，V6-1 起所有新界面都走 i18n）。

## 十、成本模型（估算）

### 10.1 价格假设（2026-10，来自公开报价与第三方整理，仅作规划，以各家官网为准）

| 项 | 单价（约） |
|---|---|
| Claude Opus 5.5 | 输入 $4 / 输出 $20 每百万 token；缓存读取 $0.20 |
| Claude Sonnet 5.5 | $2 / $10；缓存读取 $0.20 |
| Claude Haiku 5.5 | $0.10 / $0.50 |
| OpenAI 实时语音（完整版） | 音频输入 $32 / 输出 $64 每百万 token；按对话时长约 $0.06–0.10/分钟 |
| OpenAI 实时语音（mini） | 约为完整版的 1/3；约 $0.02–0.03/分钟 |
| 语音转写（Deepgram Nova-3 流式） | 约 $0.005–0.009/分钟（多语种更高） |
| 视频生成（Veo 3.1 / Kling / Runway / Seedance） | 约 $0.05–0.40/秒，随档位、分辨率和是否带音频变化 |
| 音效生成 | 约 $0.02/个 |
| 配乐生成 | 约 $0.15/分钟 |
| 数字人（HeyGen 类 API） | 约 $2–6/分钟 |
| FFmpeg 渲染、存储 | 每条视频几美分到几十美分 |

### 10.2 单条视频估算

场景：3 分钟旅游 Vlog，原始素材 20 分钟，精修一小时，其中实时对话约 30 分钟、修改指令约 40 条。

| 环节 | 估算 |
|---|---|
| 素材理解（转写 20 分钟 + 抽帧理解约 600 帧，用 Haiku） | $0.2–0.7 |
| 初剪规划与自检（Opus 5.5，含缓存） | $1–2 |
| 实时语音对话 30 分钟 | 完整版 $2–3；mini 约 $0.6–1 |
| 修改指令 40 条（Agent 决策与工具调用） | $1–2 |
| 代码生成特效 5 个（含 1–2 次重试） | $1.5–4 |
| 音效 20 个 + 配乐 3 分钟 | $0.5–0.9 |
| 局部渲染、终渲染、存储 | $0.1–0.3 |
| **小计（不含生成视频）** | **约 $6–13**（实时语音用 mini 时约 $5–10） |
| 重特效：3 段 × 4 秒，每段尝试 2 次（视频生成） | +$2.5–10 |
| 知识解说加数字人出镜 5 分钟（第二步） | +$10–30 |

### 10.3 降本手段（按收益排序）

1. 实时语音默认用 mini 档，复杂推理交给后台 Agent；在嘈杂环境或用户选择时用按住说话，减少计费音频。
2. 提示缓存：系统提示、工具目录和项目摘要固定在前缀，缓存读取约为原价的 1/20。
3. 画面理解用 Haiku 并批量处理，只对关键片段用更强的模型。
4. 特效优先走代码生成，视频生成只在必要时使用，并先报价。
5. 局部渲染与分段缓存，避免重复渲染。

**目标：** 一条不含视频生成的 3 分钟 Vlog，平台成本控制在 **$5 以内**。V6-1 起记录每条视频的实际成本，用实测数据校正本节估算。

## 十三、风险与未决事项

| 风险 | 应对 |
|---|---|
| 初剪质量达不到"第一版就像样" | 通用导演 Agent + 统一工具目录 + 自检 + 多类型评测集；先在旅游一类做透再扩展 |
| 通用能力被类型或策略逻辑侵蚀（为某类型写死流程） | 导演与调度代码不按类型分支；策略只以数据形式进入上下文；评测以不选策略为主 |
| 实时语音在中国大陆不可用 | 区域路由到国内供应商；协议与界面不变 |
| 代码生成特效质量不稳定 | 金样评测 + 模板回退 + 多候选 |
| 视频生成成本与不确定性 | 第三档才用；先报价；结果作为候选，不覆盖已采用版本 |
| 参考视频链接抓取受平台限制 | 上传文件为保底入口；抓取失败时明确提示 |
| 画幅与源素材比例不一致时的处理策略（拉伸/适配/裁切） | 默认适配（不拉伸），在 V6-1 定稿 |
