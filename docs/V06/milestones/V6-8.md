## 设计要点

- **共用流程**：报价 → 确认 → 预算预留 → 生成一次 → 拉回 → 试改 → 结算/释放/待对账，见 `docs/V06/milestones/V6-7.md`。
- **选区重绘（VIDEO_REGION）**：AI 用 `quote_generation` 报价时给出提示词；片段与范围缺省取你指着的（框了画面但没点片段时取那一刻画面里最上层的素材片段，范围取指着的那一段，超出片段时收在片段末尾）；变速片段暂不支持。执行时在"确认生成"这一轮的草稿里重新找到片段，按源时间裁出那一段、适配到生成画布（等比缩放 + 补边，不拉伸）交给供应商；生成层放在 GEN 轨同一时间，**用裁切只露出框内**——即使供应商改了框外，成片里框外仍是原片。
- **圈外改动如实测量**：生成后逐帧比较框外（灰度差，框内涂黑后统计，换算回全范围亮度），平均差超过 4/255 时在回复与报价卡里说明"供应商把框外也改了，合成时只用了框内"。
- **生成镜头（VIDEO_SHOT）**：按提示词与秒数报价，放在 GEN 轨指定时间（另起一条不覆盖已有生成层，超出时延长序列）。
- **视频生成供应商经进程协议接入**（`ANCS_GENERATION_DRIVER=process`）：stdin 一行 JSON（类型、提示词、时长与上限、画布、源片段与区域路径……），子进程把视频写到指定路径；退出码 0 = 成功（可报告费用），2 = 失败（报告是否已扣费），其他/超时/崩溃 = 结果不明。子进程只拿到白名单环境变量 + `ANCS_GENERATION_PASS_ENV` 列出的变量。参考实现 `scripts/generation-process-example.mjs`（FFmpeg 渐变画面，只演示协议）。
- **娱乐类是数据，不是流水线**：`builtin:entertainment`（高能娱乐）：钩子 3 秒、镜头 0.8–2 秒（中位 1.3 秒）、推拉约每分钟 6 次、大字幕、音效密集；旋钮"节奏（稍缓/默认/更密）""字幕（大字幕/只上关键词）"；风格评分项（3 秒钩子、无死空、镜头时长、字幕、结尾兑现钩子）。导演与调度代码、系统提示、工具目录都不提它（`strategies.test.ts` 的通用性守卫）。评测集模板 `evals/first-cut/entertainment.example.json`：两个不选策略的用例为主，一个选用预设对照。
