- 状态：界面与服务端已交付（真实浏览器 + 真实 FFmpeg 验证）；讨论与执行中的 AI 为脚本导演，真实 Claude 待密钥；语音批注随 V6-2
- 依据：V6 §5.4（批注式审片）、§7.4（改哪里渲染哪里）、§6.3（统一工具目录）、§11；裁决 0018
- 目标体验：手机或桌面逐处批注 → 逐条和 AI 讨论修改方案 → 全部确定后一次执行 → 只重渲改动的分段 → 采用成为新版本

## 设计要点

- **一轮审片绑定所看的版本：** 批注属于一轮（`review_rounds.base_revision`）；上一轮采用后再标记，自动在新版本上开新一轮。
- **讨论与执行都是普通的 AI 轮次：** 同一个通用导演、同一个工具目录、同一个会话（`agent_turns.purpose`）。
  - `DISCUSS_NOTE`：指向取自批注；上下文多一个 `<review>` 块（这一条批注的位置、所指片段、框选、已有方案）；最近轮次只取同一条批注的讨论；改动类工具在这一步**不执行**并告诉 AI 先给方案（工具目录本身不变）。
  - `APPLY_REVIEW`：上下文给出这一轮里已确定的全部批注（含所审版本与当前版本号）；所有修改进入一个草稿，结束时成为一个试改提案。
  - 普通对话（`EDIT`）不混入批注讨论；一次执行的试改可以在共看片室里继续微调（新提案取代它，审片轮沿取代链跟随到最新的试改）。
- **状态由事实派生，不另存：** OPEN / APPLYING / READY / APPLIED 由执行轮与它的提案（含取代链）算出；上次执行没成功时给出原因（失败、被停止、AI 没做改动、试改被撤回）。
- **锁定：** 执行进行中或试改待采用时，批注不能增删改（409 `REVIEW_ROUND_LOCKED`）；登记执行与建轮次在同一事务里（行锁 + 比较上一次的执行轮），Worker 读上下文时批注集合已确定。
- **统一局部重渲：** 一次执行 = 一个提案 = 一次预览请求；预览按时间窗内容哈希复用未改动的分段（V6-1d），实测"复用 3/5 段"。

### 发现并修复

- **视频不能拖动进度（影响共看片室与审片）：** 本地存储下载端点不支持 `Range`，浏览器跳转时回到开头（审片验收里三条批注都落在 00:00–00:02）。现在支持单段字节范围；`apps/api/src/storage-range.test.ts` + `assets.security.test.ts`（206 / Content-Range / 416）。生产目前也只有本地驱动，所以这是线上问题。
- **验收脚本的等待条件：** 受控 `<textarea>` 的文字会进入 DOM 文本，`getByText` 会提前命中输入框；改为等批注卡片出现、表单关闭。
