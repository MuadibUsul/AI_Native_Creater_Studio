### 通用性约束如何落地

- 导演与调度代码不按视频类型或策略分支；工具集合对所有类型一致；策略只以可选数据块进入上下文。
- 单元测试守卫：系统提示与工具说明不得出现类型/风格专用词；未选策略时上下文里没有策略块；工具目录顺序稳定（提示缓存前缀）。

## V6-1d 交付内容（改哪里渲染哪里）

为什么先做：现有浏览器播放器一次只播一个源，无法播放多片段时间线，也无法在采用前播放 AI 提案。V6 §7.4 要求预览来自与终渲染同一个 RenderPlan 的服务端低清渲染（所见即所得），字幕由浏览器叠加。

| 层 | 内容 |
|---|---|
| kernel | `render/slice.ts`（纯函数）：按帧网格切时间窗；视频切片只含窗口内画面并平移到 0 起（不含音频与字幕），切片哈希只取决于窗口内画面与源校验和；整条音频计划不含画面 |
| contracts | `preview.ts`：预览请求/状态/播放地址/字幕/分段统计；渲染档位增加 `encoderPreset`（终渲染缺省 medium，参数与之前完全一致；预览 veryfast） |
| migration | `0090_sequence_previews.sql`：预览行（冻结计划与档位，同序列同计划只渲一次）与内容寻址的分段缓存 |
| domain | `previews.ts`：编译当前版本或提案的计划（提案在事务内真执行后回滚，工程不变）、按画幅选预览档位、去重排队、签名播放地址；源文件优先已就绪的低清代理；每条视频的 AI 成本汇总 `projectAgentCost` |
| worker | `preview-render-handler.ts`：逐窗口查缓存、只渲未命中的窗口（视频段剥离音轨防止拼接错帧）；整条声音单独渲并缓存；流复制拼接 + 混流（faststart）；失败只标记本次预览（不自动重试刷计算） |
| API / SDK | `POST …/sequences/:id/previews`（202，`previews` 归入昂贵端点限流）、`GET /previews/:id`、`GET …/previews/latest`、`GET …/agent-cost`；SDK `previews.*`、`agent.projectCost` |

## 未验证与待办

- **真实 Claude 调用未验证：** 需要项目的 `ANTHROPIC_API_KEY`。当前证据是脚本模型（SCRIPTED）与本地假服务，不能当作真实 Provider 验证。拿到密钥后补一次真实初剪（记录模型、用量、成本与耗时）。
- **初剪质量评测（V6 §6.5）：** 需要真实模型才有意义；拿到密钥后建立旅游素材金样集与评分标准（人工评分 + 自动指标：叙事完整、节奏、黑帧/静音残留、字幕遮挡、声音连续）。
- **视觉理解未做真实调用：** 同上，拿到密钥后用真实素材检查镜头说明质量与单条成本。
- **分析成本计量：** 视觉分析任务的模型用量尚未进入每条视频的成本账（V6-1d 建立统一用量账本后接入）。
- **共看片室待补：** 语音（V6-2）；窄屏/移动审片（V6-4）；1–2 个可选旅游风格预设（策略剪辑小功能）；AI 理解失败时区分"未配置驱动"与"分析失败"的文案；"再来一个"的并排候选（V6-3）。
- **工具目录待补：** 预览自检工具（让 AI 看自己改完的低清预览）、代码生成动效（V6-3）、生成式特效带报价（V6-8）。
- **编辑试改性能：** `edit_timeline` 每条操作都在数据库快照上重新试改整份草稿；素材多时再改为单次加载后内存连续应用。
