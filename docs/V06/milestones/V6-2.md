- 状态：网关、协议、指代绑定与界面已交付；**Issue #9（画布内持续语音、服务端语音回应、可打断）已用真实识别 + 真实合成 + 真实 Claude 在真实浏览器验证**（均经第三方兼容网关，见下文）；Deepgram 真正流式识别待密钥；区域路由（国内供应商）待选型
- 依据：V6 §5.1（指）、§5.2（说）、§9（Realtime Gateway 新进程）、§11；V4 §7（共同注意力）、§8（语音协作、三种停止）；V4 鼠标语音增量设计 §5—§7；裁决 0018
- 目标体验：边看边说、随时打断，"这个/这里"指得准，中英文都支持

## 设计要点

- **新进程 Realtime Gateway（`apps/realtime`）：** 浏览器麦克风 → AudioWorklet 重采样为 16 kHz PCM16 → WebSocket → 网关 → 流式识别端口。网关只做识别、断句与指代绑定；**不读写工程、不调用 AI、不替用户采用**。一句话说完交还浏览器，浏览器把它当作一轮对话发给 API（与打字同一路径、同一套权限/幂等/预算）。
- **鉴权：** 开麦前浏览器向 API 申请语音会话（N05-01 已有，需编辑权限），只拿到短期凭证；网关用同一把 `ANCS_VOICE_SESSION_SECRET` 校验（伪造 401、会话已关闭/过期 409）；浏览器来源白名单（403）。长期 Provider Key 只在网关进程。
- **音频时钟与指代（V6 §5.2）：** 音频时钟 = 已发送的采样数；每次选择或播放位置变化都带着时钟发一条指向样本。识别结果带逐词时间，网关在说出"这个/这里/this/here"那一刻（允许 0.3 秒内紧跟的点击）取指向；"从这里到这里"两处合成范围；没有明确选择时用当时的播放位置（前后各 1 秒）；没有指代词用开口时的选择；什么都没指 = 整条视频。证据种类如实带回（`DEICTIC_WORD` / `PLAYHEAD_AT_WORD` / `SELECTION_AT_START` / `NONE`），纯函数 `packages/domain/src/realtime-attention.ts`。
- **半句话与改口：** 以"但是/不对/除了/逗号"或 "but/except/and" 结尾的话先保留（`held`），后半句来了合成一句，等不到（4 秒）再交出；转写按修订号替换，不做字符串追加。改口（"删掉这段……不对，是把音乐去掉"）由通用导演按最后的说法执行（提示词 `director-v5` 一条通用说明）。
- **三种停止分开：** 停止说话（只停朗读，开口即自动打断）、停止进行中的一轮（"停止"）、撤回试改（"撤回"）——互不替代；朗读不影响试改与工程。
- **双语：** 会话语言跟随界面；识别参数按语言选模型（中文 nova-2 / 英文 nova-3，可配置）；中文转写去掉字间空格。
- **供应商端口：** `StreamingSpeechRecognizer`（`packages/contracts/src/realtime.ts`），Deepgram 实现在网关；国内供应商（区域路由）实现同一端口即可，界面与协议不变。

## Issue #9：画布内持续流式语音（2026-10-15）

依据：GitHub Issue #9（参考 Google Stitch 的画布内持续语音交互）；V6 §5.2、§9；V4 §8（三种停止）。目标：开一次麦一直说，AI 忙时排队、用合成语音回应并且开口即可打断；"停止说话 / 停止这一轮 / 放弃试改·撤销 / 结束语音"各管各的；改动仍只经试改，由用户明确采用；断线、过期、未配置、供应商失败都如实说明，恢复不重复执行、不自动调用付费服务。

### 设计要点

- **语音条在画布里：** 开着语音时看片区加大下边距，画面按画幅缩进让出位置；悬浮语音条（状态 + 框选 + 声音 + 朗读 + 停止说话 + 停止这一轮 + 采用 / 放弃 / 撤销 + 结束）和上方一行反馈浮在这条边上——不压视频、字幕、时间带和播放 / 输入。看片区在深浅主题下都是暗色哑光，语音条用"哑光上"的配色。手机上按钮只留图标（读屏读全名），语音条换成两行，看片区保留最小高度，下方区域滚动。
- **阶段互斥（`voice-phase.ts`）：** 连接中 / 在听 / 正在听你说 / AI 思考中 / AI 正在说 / 正在收尾 / 已结束 / 出错；用户开口优先（打断 AI 的声音）。`data-phase` 同时供验收测量。
- **反馈一行：** 正在说时是边说边出的转写（按修订号替换）+ 绑定的指向；AI 处理时是交出去的那句话 + 排队数；出错时是原因。用户正在说时转写优先于一次性提示。新的一句开始时清掉上一句绑定的指向。
- **话语排队与幂等：** 一句话说完进入队列；AI 有一轮在跑或正在提交时排着，结束后按顺序发出。每句以网关的句子 id 作为这一轮的幂等键（`voice-turn-<id>`）：网络重试、重连都不会让同一句执行两次。发失败的一句停在队首，界面给"重试 / 不要了"，不自动重发。
- **AI 的语音回应（服务端合成）：** 用语音交出的那一轮结束后，浏览器只把轮次 id 发给网关（`speak`）；网关在本会话所属作品里读这一轮回应的开头（至多 360 字、到句号为止，`voiceReplyText`），用 `/audio/speech` 边合成边下发 PCM16，浏览器用 Web Audio 首尾相接播放（`reply-player.ts`）。用户一开口网关先发 `speech-start`、立即中止合成，浏览器立即停播并丢掉之后到的旧音频。没配置服务端合成时退回浏览器朗读并在语音条标注"浏览器朗读"，不显示声音下拉；声音下拉只列部署配置里实际可用的声音。
- **四件事分开：** 停止说话（只停声音）、停止这一轮（取消正在跑的一轮，排队的话一并取消）、采用 / 放弃试改 / 撤销改动（与对话栏同一套操作）、结束语音（只结束语音会话）。停止说话 / 停止这一轮在会话期间一直占位（不适用时禁用），AI 说完时语音条不会重新居中把别的按钮挪到指针下面。
- **OpenAI 兼容识别（`openai-audio.ts`）：** `/audio/transcriptions` 不是流式接口，网关自己做断句：20 ms 帧、自适应噪声底、300 ms 预留、连续 60 ms 有声算开口（立即发 `speech-start`）、静音 700 ms 算说完、单句最长 30 s；说话中每 0.9 s 新音频转写一次出临时文字，说完再转写一次出最终结果。`gpt-4o-transcribe` 没有逐词时间：按发声段与临时转写的"已认出 / 还没认出"估算词时间（指代绑定用）；`whisper-1` 用供应商逐词时间。转写提示说明"简体中文的视频剪辑口令"（不给提示时实测会输出繁体并把"剪短"听成"簡短 / 简短"）。所有请求不自动重试；失败按 401/403 → 密钥无效（结束会话）、429/5xx → 这一句没听清（会话继续）分类，错误里不带 Key。
- **会话门（`voiceSessionGate`）：** 凭证只在握手时校验；网关在交出每一句之前、以及到期那一刻复查会话（过期 / 撤销 / 关闭 / 换代）：失效则这一句不交给 AI，回 `SESSION_EXPIRED` 并以 4401 关闭；浏览器提示"重新连接"（新开会话），不自动重连。
- **Claude 经兼容网关：** Worker 与评测脚本支持 `ANCS_ANTHROPIC_BASE_URL`（https，填到 `/v1` 之前）。

### 未验证与限制（Issue #9）

- **首字延迟：** OpenAI 兼容的分段转写首段文字 2–5 s；要达到"边说边出"的体验需要真正的流式识别（Deepgram 已有适配器，待密钥；或 OpenAI Realtime 转写，未接）。
- **真人与真实声学条件：** 没有真人对着真实麦克风说话；回声消除（AI 的声音从扬声器回到麦克风被当成开口）未测，网关的开口检测会把这种回声当成打断。
- **凭证到期计时器：** 到期那一刻的关闭只有代码与会话门集成测试覆盖（实测用"连接期间关闭会话"走同一道门），没有等满 15 分钟。
- **跨浏览器：** 实时语音只在 Chromium 验证；Firefox / WebKit 未跑语音流程。
- **第三方网关：** 识别、合成、Claude 都经第三方兼容网关，延迟与偶发拒绝可能与官方直连不同。
