# Creator Studio 前端重设计
## Quiet Frame · 静框 / Design v1.0

日期：2026-10-07。源码基线：`main @ 2fa881db7a9d024a03b5077f197f7cedbbeea194`。

**设计结论：保留已有的内容生产规则，重新组织用户看到的工作台。** 主界面围绕作品与分镜，不围绕模型供应商、数据库实体或工程任务。苹果式极简在这里指内容优先、清楚的层级、稳定的空间关系与克制的材质，而不是将整页做成透明玻璃。

本方案是设计决策，不声称存在可被客观证明的“行业最优界面”。发布前仍应通过真实创作者的任务测试验证。

## 1. 审查范围与证据边界

本次读取了默认分支/提交信息、完整前端 app 与 ui 路由/组件目录、核心页面、全局样式、依赖清单、产品规范开篇及相关交接记录；重点逐文件检查 Dashboard、ProjectLayout、Script、Storyboard、SceneEditor、AiEditPanel、RenderReview、StateBlock 和 AnalyticsWorkspace。

这是**前端与相关产品约束的源码审查**，不是全仓安全审计、生产运行截图分析或真实供应商联调。没有运行原仓库，没有把文档中的验收结论当成本次运行结果。部分较大的文件/交接记录按可读范围检查，未声称所有后端文件均逐行阅读。

根 README 的“当前 P00”描述与较新的 P14 交接记录不一致。项目当前进展应参考较新交接和验收证据；也不能把“功能代码交付”当成“所有外部服务已经上线”。交接记录仍列出真实模型、支付、OAuth 等凭据/外部核验边界。[S1][S12]

### 1.1 已有能力，应该保留

- Scene Graph 为作品的权威状态；Web 通过 SDK/API 提交，不直接接数据库或供应商。
- 自然语言先生成修改计划，显示差异，确认后再提交结构化操作。
- 项目与场景 revision、幂等键、锁定约束和冲突处理已有路径。
- 素材预览不默认触发昂贵生成；有 Lite Timeline，但默认折叠。
- 渲染、QA、人工批准与受控导出分离；批准绑定渲染快照。
- 来源、事实数据和许可属于可追溯信息，不能以生成内容代替。
- 加载、空、失败、未登录、无权限、冲突、不可用等状态已有公共表达组件。[S1][S5][S7][S8][S9]

### 1.2 主要问题与改法

| 优先级 | 源码观察 | 对用户的影响 | 重设计处理 |
|---|---|---|---|
| P0 | Dashboard 创建项目表单仅在项目列表为空时显示。[S2] | 创建首个项目后缺少持续可见的新建入口。 | 顶部内容入口与列表标题旁的新建按钮始终保留。 |
| P0 | 七个平级项目页签混合了创作阶段、资产、历史、输出与复盘。[S3] | 初次使用难判断顺序，熟练使用也要反复跳页。 | 脚本 → 分镜与编辑 → 成片 → 交付；资产按需打开，历史进入抽屉，复盘不占主创作流程。 |
| P1 | 根布局固定 `max-w-6xl`、强制深色；全局 CSS 缺乏语义设计变量。[S4] | 编辑器屏幕利用率与全站一致性不足。 | 工作区全宽，文档区受控宽度；统一色彩、间距、状态和组件变量。 |
| P1 | Script 可见入口仅 URL，目标时长写死 120,000 ms。[S6] | 用户输入路径与制作目标不清楚；高级后台能力没有形成清楚入口。 | 独立导入/作品方向步骤。URL、粘贴、文件按后端实际可用能力开放；时长成为显式作品设置。 |
| P1 | Storyboard 纵向堆叠预览、AI 面板、时间线、场景清单。[S5] | 看分镜、改画面、核对旁白时滚动频繁。 | 分镜栏—画布—检查器三栏，旁白与 AI 修改入口保持临近画布。 |
| P1 | 编辑界面直接显示 sceneType、semanticType、revision、毫秒和操作 JSON。[S5][S6][S7] | 专业创作者必须阅读工程语言才能完成普通操作。 | 页面显示“趋势对比”“32 秒”“已保存”；工程明细在“场景信息/版本详情”保留。 |
| P1 | 场景编辑以固定宽预览与属性表单并排，冲突主要提示刷新后重试。[S7] | 小屏承载困难；恢复冲突缺少保留草稿/比较入口。 | 上下文检查器；冲突先保留本地修改，再比较最新版本，不静默覆盖。 |
| P1 | RenderReview 把规格、队列、QA、人工批准作为纵向管理表单。[S8] | 用户需要从多个技术状态中推导下一步。 | 成片预览 + 精简检查清单 + 当前唯一主操作；失败时定位到分镜。 |
| P1 | AnalyticsWorkspace 同时加载表现、建议与 Finance 来源/模板/产物；共用初始失败判断。[S10] | 复盘与制作任务混杂，财经模块异常可能阻挡表现页。 | 性能复盘与财经图形制作拆成独立 feature/query boundary；不修改原 API 权限规则。 |

“渲染前预检”在当前前端是独立按钮，不等于后端没有闸门。本方案要求 UI 对下一步条件给出清楚解释，**不能据此前端观察推断服务端可被绕过**。

## 2. 产品框架

### 2.1 一个主任务

> 交给系统一篇文章或研究，获得可核对、可修改、可交付的专业长视频。

不把 AI 聊天框做成所有功能的唯一入口，不把模型清单做成产品首页，也不把时间线变成唯一工作界面。内容、作品和分镜是主要对象，模型只是完成特定步骤的执行方。[S11]

### 2.2 两级导航

**工作空间级：** 创作台、素材库、创作者身份、扩展工具。设置、预算、成员、隐私在左下。工作区切换显式改变项目、预算、身份和权限上下文。

**作品级：** 脚本、分镜与编辑、成片、交付。当前作品名称在左，当前阶段在中，当前主操作在右。历史和来源通过抽屉查看。作品表现从交付完成页或作品更多菜单进入。

这是一种视图组织方案，**不要求马上更改现有 URL**。旧 deep link 应继续可用。

### 2.3 默认创作流程

```text
输入内容 → 校验与阅读来源 → 确认作品方向
        → 脚本草稿 → 创作者确认/锁定
        → 分镜与低成本草稿 → 局部修改
        → 预检与费用确认 → 昂贵生成/渲染
        → QA → 人工批准 → 下载 / 能力允许的发布
        → 有真实平台数据后复盘
```

自动生成不等于自动批准，草稿不等于成片，送至平台草稿不等于已发布，导出包不等于自动分发。

**新用户默认**：最少必要设置，随内容提议名称、时长与叙事，但必须允许修正。**熟练用户默认**：恢复上次工作，尊重栏目身份和显式预算；避免每次重复向导。

## 3. 视觉语言

### 3.1 概念：Quiet Frame / 静框

“静”是界面退后，“框”是作品进入中心。强调白纸般的阅读、清晰的画面边界和编辑工具的稳定位置。它是设计方向名称，不是强制更改仓库或产品名称。

**默认：暖白工作台，石墨色画布，冰蓝操作高亮。** 几何封面中的铜色、灰绿与蓝灰仅为作品内容，不扩散到全局按钮。全站仍只保留一个主要交互强调色。

| 角色 | 建议值 | 使用规则 |
|---|---|---|
| 画布外背景 | `#F6F6F4` | 全站大面积中性底色 |
| 内容表面 | `#FFFFFF` | 纸张、表单、检查面板 |
| 导航层 | `#EEEFED` | 侧边栏与低优先级承载面 |
| 正文 | `#202322` | 标题、重要内容与主按钮 |
| 次级文字 | `#646B68` | 必需说明，不通过过低对比“做高级感” |
| 强调色 | `#1768B2` | 选中、链接、焦点、关键反馈 |
| 强调浅底 | `#EAF3FC` | 当前选中场景与信息提示 |
| 成功 | `#34735B` | 确认完成；不替代真实服务端状态 |
| 警告 | `#8B641E` | 可处理风险、未核验、缺失来源 |
| 危险 | `#A23A3A` | 操作拒绝、冲突影响、不可逆动作 |
| 分隔 | `#E1E4E0` | 装饰分隔；不能自动当成足够对比的交互边框 |

### 3.2 排版与空间

系统字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans CJK SC", "Microsoft YaHei", sans-serif`。不捆绑 SF 或其他系统字体文件，不假设 Windows 可以呈现 macOS 字体。

工作台标题 36/1.25；营销大标题最大 68；分区标题 23；卡片标题 16；正文 14–16；辅助文字 12–13。时间码用等宽数字；内部毫秒转换为创作者可理解的秒或 `mm:ss`。仅非关键密度信息允许更小字号，不让关键授权/成本/错误提示变成小字。

主要间距：4、8、12、16、24、32、40、48。页面常规边距 40–48，移动端 20–24；卡片16圆角，控件8–10，抽屉16–18。小组件不一律大药丸圆角。

默认桌面导航208；中间工作区流式伸缩；编辑器分镜栏约198，检查器约277，优先将宽度让给画布。文档阅读和设置页限制行长，编辑器不沿用营销网站的窄容器。

### 3.3 材质、动效与图标

玻璃仅用于确有“浮于内容之上”关系的导航或控制层；正文、表格、编辑表单使用实色。Apple 的 Materials 指导区分功能导航层与内容层，本方案沿用这一分层思想，不复制原生私有材质实现。[D1]

动作反馈通常120–180 ms，抽屉180–240 ms，内容轻移不超过4–8 px。不使用无限光晕、视差拖拽、每个卡片悬浮抖动或操作中持续发光。响应 `prefers-reduced-motion`；实际忙碌状态来自任务，不以动画假扮进度。

统一细线图标，18–20 px，笔画约1.6；只有图标的按钮必须有可访问名称。减少无功能装饰线框。Linear 2026-03 的设计复盘同样强调收敛边框、降低导航存在感与中央任务聚焦；这里参考原则，不照搬其产品结构。[D2]

## 4. 13 个页面的高保真设计

### 01 创作台

第一眼只回答“从哪里开始”和“继续哪部作品”。大输入框承接文章链接、正文与资料入口；项目用内容缩略图而不是数据库字段展示。新建入口在零、一、多项目状态下都存在。状态名使用“待确认、编辑中、待审核”，项目卡恢复到实际进行中的阶段。

### 02 新建作品

左侧输入与资料摘要，右侧作品名称、时长、表达方式、声音与主操作。读取失败保持已填资料，明确区分权限限制、解析不支持和临时错误。扫描文档不能伪装成成功提取；生产版可复用现有服务端文档能力，不由浏览器自行绕过解析/安全规则。

### 03 脚本与来源

中间是一张可阅读的文稿，左侧大纲，右侧关联来源。已确认段落可锁定，数字和引用可直接回到原文位置。来源“已关联”不自动等于“事实已核验”。AI 改写先显示差异；锁定内容只建议、不覆盖。

### 04 导演工作台

左侧可定位分镜，中央呈现最终视觉，右侧随选择对象显示画面、声音、来源。旁白紧贴预览，不要求先打开时间线。轻时间线是补充视图，默认只保留简明场景序列，需要排序/时长修正时再展开。桌面分区滚动，避免整页滚到找不到画面。

自然语言输入是“对当前作品/选中场景做什么”的命令框，不能漂移成无对象的泛聊天。AI 修改抽屉包含范围、前后差异、锁定影响、成本影响和确认/拒绝。

### 05 素材库

按图片、图表、声音、文档等类型浏览；展示缩略图与来源/授权状态，详情显示关联作品与版本。财经图表在此进入制作，而不是塞在作品表现页。图表须区分真实数据、结构示意和预测情景；图像生成不能变成事实佐证。

### 06 创作者身份

以身份为对象管理声音、数字人/主持方式、品牌外观，不以“供应商账号”作标题。试听先于付费生成；克隆须明确授权与撤销路径，不能把一个勾选框等同于完成所有验证。未核验能力要显示不可用原因。

### 07 成片与审核

大幅预览与规格在左，检查清单和批准在右。检查聚合为画面字幕、声音节奏、来源授权、版本一致性；细项按需展开。QA 阻止项必须修复；警告不被隐藏。批准按钮绑定当前不可变渲染，草稿修改后需要重新渲染并重新批准。

### 08 交付与发布

平台卡区分直接发布、受限发布、送至草稿、素材包交付。具体按钮由已授权且已核验的后端能力控制，不由平台名字推断。明确最后一步是谁完成；没有真实授权时不能展示“已连接”。手机交接依旧遵守到期、撤销与权限规则，不制造永久公开下载链接。

### 09 作品表现

先显示作品与采样范围，再显示指标、场景留存和可解释建议。未知指标显示“未知/—”，不显示0；关联并非因果。接受建议不静默改栏目或已发布作品。Finance 图表制作不再与复盘共享加载/失败边界。

### 10 扩展工具

围绕新增产物和任务：Shorts、图文、长文、多语言、播客、财经图形。主流程不被扩展卡片占据。启用前明确权限、作用范围、价格与撤销。这里是官方能力目录设计，不等于启动第三方 Marketplace 或越过当前工程暂停门槛。

### 11 设置

普通用户优先看到“脚本/声音/主持人/视频镜头”的可用状态；高级设置再展示具体服务商。平台托管与自有 API 模式分开；前端仅显示凭据掩码，提交与核验走服务端安全路径。订阅权益和 AI 计算用量各自有账本，不能以一个模糊余额混合。

### 12 产品首页

大标题“一篇好文章。一部好作品。”配真实产品结构预览，解释文章到成片的独特流程。省略虚构客户 logo、增长数字和未经核验的速度承诺。营销留白可以大，登录后的工具密度不能照搬营销页。

### 13 设计系统

集中展示颜色、字号、按钮、选中状态、消息层级、间距、圆角与冲突示例。生产版变量应由工程组件使用，不能让设计稿一套数值、代码另一套。

## 5. 必备状态与交互约束

| 情境 | 页面表现 | 保留的数据 / 下一步 |
|---|---|---|
| 初次使用/无项目 | 一项明确创建入口 | 不先强制配置所有供应商 |
| 来源读取失败 | 保留输入并说明原因 | 重试、粘贴、支持的文件导入 |
| 正在解析/规划 | 真实步骤、可离开后返回 | 无确定进度时不用假百分比 |
| 没有可用 Provider | 占位仍可编辑，生成按钮说明原因 | 连接服务或更换方案 |
| 额度不足/报价变化 | 报价与预算差异 | 不自动扣费或偷偷降档 |
| AI 提议修改 | 比较原文/新文，显示范围 | Apply 后才提交；拒绝无副作用 |
| 已锁定/只读权限 | 清楚的不可编辑状态 | 申请权限或显式解锁 |
| 版本冲突 | 保留用户本地修改 | 比较服务器最新版本，不静默覆盖 |
| 生成部分失败 | 定位具体资产/任务 | 仅重试失败项；幂等保证不重复收费 |
| QA 阻止项失败 | 可定位分镜的错误 | 修复后重新渲染，不开放批准 |
| 已批准但内容已变化 | 明确草稿与已批准成片不是同一版 | 新渲染需重新审批 |
| 发布中/结果未知 | 显示处理中或待核对 | reconcile，不直接重复发布 |
| 平台仅支持草稿 | “已送至草稿” | 用户完成平台发布，不显示已发布 |
| 离线/保存失败 | 保留本地草稿，显示未同步 | 恢复连接后以 revision 协议同步 |

最小状态组件应保留现有 `StateBlock` 的覆盖范围，但视觉上按影响范围选择字段提示、面板消息、横幅或整页状态，不把小错误都升级成整页红框。

## 6. 响应式、键盘与可读性

≥1280：完整导航和三栏编辑器。约1100–1279：缩小非核心侧栏；需要时收起检查器。768–1099：紧凑导航、按需检查器。≤760：抽屉式导航、单列内容，分镜改横向切换，场景属性以面板展开。不得单纯缩小桌面三栏字体来塞入手机。

桌面常规按钮建议40 px高、密集次操作可32–36 px；移动主要触控目标建议44–48 px。W3C WCAG 2.2 AA 的 Target Size Minimum 是24 CSS px并有例外，44–48是本产品的触控舒适性目标，不能混称标准强制值。[D4]

正常正文对比度目标≥4.5:1，大字≥3:1；必要控件边界/图形信息按非文本对比要求另行核对。[D3] 所有关键状态同时使用文字与图标，不只靠颜色；焦点可见、抽屉焦点受控、关闭后返回触发项。不能用低对比提示字“做轻盈”。

原型已做键盘与降低动态效果的基础处理，但本次测试**不是完整 WCAG 审计**；正式实现仍需对字段语义、屏幕阅读器、触控目标、双主题对比和缩放做专项验收。

## 7. 工程落地建议

不要将单文件 HTML 直接覆盖 Next.js 项目。它用于页面结构、视觉与交互的参考；实现必须复用现有 hooks、SDK、StateBlock 语义与编辑协议。

先建设 tokens / buttons / fields / tabs / badge / dialog / drawer，再替换外壳和 Dashboard；然后融合 Storyboard 与 Scene Editor 的视图，最后迁移审核、素材、身份、交付和复盘。先解决主任务，不先花时间做一个与编辑器脱节的漂亮营销页。

新的视图建议通过特性开关灰度开放。旧路由、测试标识、权限、锁定、费用账本、QA、manifest 绑定均不能因“视觉简化”而删除。工程任务、路由对照与验收点见 `handoff/IMPLEMENTATION_HANDOFF.md`。
