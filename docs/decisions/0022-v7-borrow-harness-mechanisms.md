# 0022 V7 改向：Agent 运行时留在 ANCS，从 DeepSeek Harness 逐项借鉴机制（取代 0021 的运行时迁移）

- 状态：生效（2026-10-28）。P0 审计完成后，我评估了"迁往 DSH Fork"的价值，结论是：DSH 有价值的是几项具体机制，不是整个运行时，这些机制可以单独借鉴，搬进 ANCS 现有的循环。项目所有者回复"按这个思路吧"。
- 前一裁决编号：`0021-v7-video-native-harness.md`。本裁决取代它的第 1、3、5 条，以及第 6 条中只对 Fork 有意义的部分。
- 依据：P0 审计 `docs/V07/V7_BASELINE_AUDIT.md`（调用链、DSH 静态审计、风险清单）；下文"测量"一节

## 为什么改向

- **ANCS 的循环已经具备迁移想换来的东西。** `runAgentTurnLoop` 每一步都写进 `agent_turns` / `agent_turn_messages`，可以从日志续跑。每次调用模型前都要过三道门禁：月度额度、未定价模型、单轮上限。按用途还有两条限制：讨论批注只能读，自主制作不能生成。草稿留在轮次上，最后以提案交给用户。
- **迁移的成本远大于收益。** 要做的事包括：工具桥、逐轮令牌鉴权、两套会话日志、两个仓库的发布节奏。而所有者已经决定 DSH 代码只能在 Fork 的 CI 里跑，本会话不能运行它，所以每一项都只能靠静态阅读推进，验证周期很长。
- **测量显示，真正的问题集中在少数几处。** 测量方式：用合成素材的真实工具输出，按导演常见顺序调用 19 次工具。
  - 历史里累计 27 张图，15 k 字符文本；
  - 由于每次请求都重发全部历史，前 19 次请求累计带图 264 张次，文本约 101 k 字符。
  - **Claude：** 适配器已经用提示缓存，裁剪旧结果会让缓存失效，大概率得不偿失。
  - **DeepSeek：** Pro 只收文字。只要历史里出现过图片，后面的每一步都改用 Flash。这一轮的剪辑决策因此几乎都由较弱的模型完成，部署方配置的 Pro 只在开头几步生效。

## 决定

1. **Agent 运行时只有 ANCS 自己的循环。**
   - 不建 Fork，不做工具桥，不设运行时开关。
   - P1 为迁移加的切换点、`ANCS_AGENT_RUNTIME`、`video-tool.v1` 契约及其测试全部撤回。它们没有上线过，也没有调用方。

2. **逐项借鉴 DSH 的机制。** 每一项都是独立的小改动，各自有测试和证据，记在 `docs/V07/milestones/B<n>.md`。它们必须遵守两条原则：
   - **模型看到的内容可以从轮次日志重建。** 每次请求都是对 `agent_turn_messages` 的确定性投影，不在内存里藏状态。这是 DSH "模型可见 ⟺ 已记录"在 ANCS 的对应写法。
   - **AGENTS.md 的规则照旧。** 导演与调度代码不按视频类型分支；工具一律进统一目录；外部调用只经 Provider Gateway；业务包不读 `process.env`。

3. **借鉴清单与顺序。** 依据是测量，以及对 ANCS 现状的核对：现在工具串行执行；循环对单次工具调用没有统一的截止时间（只有抽帧子进程自带超时）；也没有重复调用检测。

   | 编号 | 机制（DSH 出处） | 在 ANCS 的做法 | 状态 |
   |---|---|---|---|
   | B1 | 图片卸载（`compaction-image-offload`，以及纯文本模型把图换成文字说明） | DeepSeek 适配器：只发送最新一条消息里的图，更早的图换成一句说明，告诉模型需要时可以再调用看画面的工具。模型按实际发出的内容选择：没有新图的步骤回到部署方配置的模型 | 先做 |
   | B2 | 重复调用提醒（`guard/repeat-tool-reminder`） | 同一工具、同样参数连续调用时，在工具结果里提醒模型，不拦截调用 | 待做 |
   | B3 | 并行只读工具与工具超时（`guard/timeout-policy`） | 同一步的多个 READ 调用并行执行；看画面等慢工具设截止时间，超时作为工具错误返回给模型 | 待做 |
   | B4 | 长历史压缩（`compaction-basic`） | 随 V6-10 长素材一起评估，只用于超长轮次 | 随 V6-10 |
   | — | 工具结果裁剪（`compaction-tool-result-pruner`） | **不采用**：在 Claude 上会让提示缓存失效（见测量） | 不做 |

4. **V6-10 / V6-11 恢复排期。** 0021 暂停它们，是因为要等运行时的归属定下来，现在已经定了。V6-10 排在 B1 之后，B4 随它一起评估。

5. **0021 的其余内容。**
   - 0021 第 2 条的不变量本来就是 ANCS 的现有约束，继续有效：操作日志唯一权威、AI 只写草稿与提案、有理时基、付费生成"报价 → 授权 → 预留 → 对账"。
   - 所有者关于真实花费的决定继续有效：用最便宜的模型、最小额度，每一笔真实花费逐笔审批。
   - 关于 Fork 仓库、DSH 版本与镜像的决定不再需要执行。如果以后重新考虑迁移，那些决定仍是起点。
