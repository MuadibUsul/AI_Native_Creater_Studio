## 决定

1. **V5 是当前的架构权威**；v0.4 总规范仍是**产品需求权威**。冲突优先级更新为：
   用户后续明确要求 → **V5 架构裁决（本文件及后续 V5 ADR）** → v0.4 显式增量 → v0.4 保留内容 → 不冲突的旧规范。
   V5 不缩减 v0.4 §1.1 的任何产品要求，不删除 N 系列任务，也不清零已 `VERIFIED` 的证据。
2. **执行方式**：按 V5 §20 的阶段 M0（止血）→ M1（时间库 + 编辑内核）→ M2（操作日志权威 + 关闭旧写入口）→ M3（能力注册表 + 工作流 + Provider Gateway）→ M4（G0 闭合）→ M5（实时与 Agent）推进。阶段工作以 `V5-Mx` 记录证据与交接（`docs/verification/V5-Mx.md`、`docs/handoffs/V5-Mx.md`），并挂到受影响 N 任务上；不另建第二套任务编号来计算产品完成度。
3. **账本治理**：`scripts/spec-check.mjs` 纳入 `pnpm verify`，强制"VERIFIED 的依赖必须 VERIFIED、每项有独立证据与交接、汇总与明细一致"。依赖降级只能通过 `docs/decisions/` 裁决后加入脚本白名单。
4. **长期分支跑 CI**：`.github/workflows/ci.yml` 对 `codex/**` 推送触发。
