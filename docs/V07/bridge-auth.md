# V7 工具桥鉴权设计（P1 设计，P2 落地）

- 依据：裁决 `docs/decisions/0021-v7-video-native-harness.md`；方案 §2.1、§2.3（SOT-04/05/08）、§3.3、§7；P0 审计 §6.4、R-04、R-09
- 契约：`packages/contracts/src/video-tool.ts`（`video-tool.v1` 调用 / 结果 / 幂等记录 / 令牌声明）
- 状态：设计已定，代码在 P2 与工具桥一起落地。本文件只描述将要实现的行为，不代表已经实现。

## 1. 要防住什么

DSH 进程按"不可信"对待：它未经安全审计，模型可能被素材里的文字诱导，进程本身也可能出错。桥鉴权要保证：

1. DSH 只能对 **ANCS 签发给它的那一轮** 调用工具。不能换工作区、换工程、换轮次，也不能在这一轮结束后继续调用。
2. DSH 不持有任何长期凭据：没有数据库凭据、媒体存储凭据、Provider 密钥，也没有用户会话。
3. 每一次调用，ANCS 都重新核对权限与状态，不因"令牌有效"就跳过。
4. 重试、超时、迟到的响应不会让同一件事执行两次，也不会覆盖人的新改动。
5. 被拒绝的调用一定留下审计记录，并且不产生任何改动。

## 2. 令牌

**签发**
- 时机：ANCS 在开始一轮、决定交给 DSH 运行时执行时签发（`AgentRuntime.runTurn` 的 DSH 实现）。
- 范围：一轮一个令牌，绑定 `workspaceId`、`projectId`、`sessionId`、`turnId`、轮次用途 `purpose`，以及签发与到期时间。声明结构见 `videoBridgeTokenClaimsSchema`。
- 有效期：等于这一轮的最长运行时间，上限 6 小时。轮次结束或取消后，令牌立刻失效（见第 3 节第 2 步），不必等到期。

**格式**
- `base64url(claims JSON)` + `.` + `base64url(HMAC-SHA256(key, claims JSON))`。
- 与语音会话凭证同一做法（`voice-session.ts`）：服务端重新计算签名，用常量时间比较。

**密钥**
- 新增专用密钥 `ANCS_AGENT_BRIDGE_KEY`。
- 不得与 `BETTER_AUTH_SECRET`、语音会话密钥、`ANCS_CREDENTIAL_KEYS` 共用；AGENTS.md 已禁止凭据加密密钥与会话密钥共用，这里同一原则。
- 生产环境缺这把密钥时，选择 DSH 运行时会启动失败。
- 密钥轮换：`v1:` / `v2:` 前缀，校验时接受当前与上一版，签发只用当前版。

**传递**
- 只放在 DSH → ANCS 请求的 `Authorization: Bearer` 头里。
- 不进日志、不进 DSH 会话日志、不进模型上下文；DSH 侧的会话事件只记录令牌 ID `jti`。

## 3. 每次调用的校验顺序

全部在 ANCS 服务端完成，任一步失败都返回 `REJECTED`，工具不运行。

1. 解析信封 `videoToolInvocationSchema`：版本不对、字段多余或参数超限 → `UNSUPPORTED_PROTOCOL` / `ARGS_TOO_LARGE`。
2. 验签与到期：签名不对、过期、`aud` 不是 `ancs-video-bridge` → `UNAUTHENTICATED`。
3. 范围一致：信封里的工作区、工程、会话、轮次必须与令牌声明逐字相等 → 否则 `SCOPE_MISMATCH`。
4. 重读轮次行：轮次必须存在、仍是 `RUNNING`、属于该工作区和工程，工作流没有被请求取消 → 否则 `TURN_NOT_RUNNING`。迟到的调用只留审计。
5. 重查权限：轮次创建者对该工程仍有 `project:write`（与 API 一致）。成员被移除后，这一轮剩下的调用全部拒绝。
6. 工具存在：`toolName` 在统一工具目录里 → 否则 `UNKNOWN_TOOL`。
7. 幂等：按 `turnId + commandId` 查执行记录。
   - `COMMITTED` 且参数哈希相同 → 重放结果（`replayed: true`）；
   - 参数哈希不同 → `COMMAND_CONFLICT`；
   - `RUNNING` → 返回"仍在执行"，DSH 稍后再查；
   - `UNKNOWN` → 不自动重跑，按草稿与提案的实际状态核对后再定。
8. 之后与 legacy 循环完全相同：
   - 用途门禁：批注讨论只读，自主制作不报价，以 `TOOL_ERROR` 返回给模型；
   - zod 校验输入；
   - 执行 `tool.run`；
   - 在同一事务里写草稿、工具记录和执行记录。

花费门禁（工作区月度上限、无单价不调用、本轮上限）在模型调用前检查，不在工具桥上。由谁检查、在哪一侧，按 P0 审计 R-03 在 P2 决定。

## 4. 网络与进程

- DSH 进程的出网只允许两处：ANCS 工具桥地址，和所选模型的 API。由容器或网络策略强制，不依赖 DSH 自觉。
- 工具桥是 ANCS API 上一个单独的内部路由前缀，不对公网暴露。部署时只在内网监听，或由反向代理拒绝外部访问。
- 工具桥接口单独限流：按轮次与工作区计数，复用现有的 Redis 令牌桶。

## 5. 审计

- 每次调用写一条记录：`turnId`、`commandId`、`toolName`、参数哈希、结果状态、拒绝原因、`jti`、耗时、`traceId`。
- 不记录令牌原文、参数原文中的素材内容，也不记录图像。
- 被拒绝的调用同样记录，便于发现异常的 DSH 行为。

## 6. 测试计划（P2 必须全部通过）

| 编号 | 场景 | 期望 |
|---|---|---|
| B01 | 没带令牌 / 令牌格式错 / 签名被改一位 | `UNAUTHENTICATED`，工具未运行，审计有记录 |
| B02 | 令牌过期 | `UNAUTHENTICATED` |
| B03 | 用 A 轮的令牌调用 B 轮，或改了信封里的工程 ID | `SCOPE_MISMATCH` |
| B04 | 跨工作区伪造工程 ID（方案 T11） | `SCOPE_MISMATCH`，不泄漏任何资源信息 |
| B05 | 轮次已完成 / 已取消后再调用（迟到响应） | `TURN_NOT_RUNNING`，草稿与提案不变 |
| B06 | 创建者被移出工作区后继续调用 | 拒绝，草稿不变 |
| B07 | 同一 `commandId` 重发（断网重放，方案 T13） | 重放结果，`replayed: true`，草稿只改一次，不产生第二个提案 |
| B08 | 同一 `commandId` 换参数 | `COMMAND_CONFLICT` |
| B09 | 执行中进程中断 → 记录为 `UNKNOWN` | DSH 重试不会重跑；核对后才继续 |
| B10 | 批注讨论轮次调用改草稿工具；自主制作轮次调用报价 | `TOOL_ERROR`，与 legacy 相同的提示，工具目录不变 |
| B11 | 参数超过 256 KiB；结果超过 1 MB（方案 T24） | 分别拒绝；结果过大时这次调用记为失败、不写草稿 |
| B12 | 密钥轮换：旧版本签发的令牌在过渡期内有效，之后失效 | 符合 |
| B13 | 用 `BETTER_AUTH_SECRET` 或语音会话密钥签的令牌 | 一律无效 |
| B14 | 审计与日志里搜令牌原文 | 搜不到 |

## 7. 不在本设计范围

- **模型调用的花费门禁放在哪一侧（R-03）**：二选一，P2 决定：
  - DSH 在发起模型请求前经桥询问 ANCS；
  - 或模型请求经 ANCS 代理。
- **付费生成的执行**：桥上只有报价（`quote_generation`）。真正的生成由用户在界面确认后走现有的付费生成工作流，与桥无关（P5）。
