# V7 B2 — 重复调用提醒

- 依据：裁决 `docs/decisions/0022-v7-borrow-harness-mechanisms.md` 第 3 条 B2、第 6 条（循环与供应商无关、只追加）
- 借鉴来源：DSH `packages/guard/repeat-tool-reminder`。它统计"同一工具、同样参数"的连续调用次数，达到阈值时提醒模型，只提醒、不拦截。
- 状态：**离线完成**（单元测试、真实 PostgreSQL 上的循环集成测试）；真实模型对提醒的反应 `NOT_VERIFIED`

## 为什么需要

- 导演在一轮里最多调用 24 次模型（自主制作 60 次），之前没有任何重复检测。
- 模型卡住时，可能连续用同样的参数调用同一个工具（比如反复看时间线），直到用完次数，草稿却没有进展。

## 做法

新增纯函数 `packages/domain/src/agent-repeat-reminder.ts`；`runAgentTurnLoop` 每一步执行完工具后调用它：

- **怎么算重复**：同一工具、参数按键排序后完全相同，算一次重复。只是属性顺序不同的两次调用算同一次；参数不同，或中间夹着别的调用（比如一次修改），就重新计数。
  - 所以"改完草稿再看时间线"这种正常用法不会被提醒。
- **阈值**：连续第 3 次温和提醒；第 5、8 次点出工具名与参数，参数超过 500 字符时截断。阈值与 DSH 的缺省一致。
- **只提醒、不拦截**：调用照常执行，提醒作为一段英文文字追加在本步工具结果之后。
- **计数只由轮次日志决定**：续跑后结果相同。DSH 把计数放在内存里；ANCS 的轮次可以中断后续跑，所以从日志重新计算。
- **与供应商无关、只追加**：提醒写进日志，之后的请求原样带着它，不改写已经发出的历史。这就是 Anthropic 推荐的写法："在 tool_result 之后追加一段文字，旧的提醒原样保留"，Claude 的思考块因此不受影响。各适配器怎么转换这段文字：
  - Claude：同一条 user 消息里，排在 tool_result 之后的 text 块；
  - DeepSeek 与 Elorian：tool 消息之后的一条 user 文字消息（新增协议测试锁住）；
  - Gemini：同一轮里排在 functionResponse 之后的 text 分片。
- **涉及的层**：只有领域层的循环与测试。契约、迁移、API、SDK、界面都不适用。界面不显示日志里的消息，提醒只给模型看。
