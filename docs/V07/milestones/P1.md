## 目标

P2 要让 DSH Fork 驱动 Agent 轮次，在那之前先在 ANCS 侧把三样东西准备好：

- 一个可切换、可回退的运行时入口；
- 一份 DSH 侧照着实现的工具桥契约；
- 一份鉴权方案。

同时修好基线里的测试隔离问题，让 legacy 与 DSH 的对照能建立在一次干净的全量运行上。

**本阶段不改变任何用户可见行为**：legacy 仍是缺省也是唯一可用的运行时。所以界面与浏览器验收"不适用"。

**`video-tool.v1` 契约包含：**
- 由 ANCS 工具描述派生的桥上描述：只有 READ 工具可并行；看画面的工具截止时间更长。
- 严格的调用与结果信封：参数超过 256 KiB、结果超过 1 MB 都拒绝，不截断。
- `REJECTED` 必带原因，且一定不改草稿。
- 按 `commandId` 的幂等记录：COMMITTED 重放；UNKNOWN 不盲目重跑。
- 每轮的桥令牌声明。
- GENERATE 保持"只报价"，不新增 QUOTE 枚举。

**桥鉴权设计包含：**
- 一轮一令牌，专用密钥 `ANCS_AGENT_BRIDGE_KEY`，不与任何现有密钥共用。
- 每次调用的 8 步校验：信封 → 验签 → 范围 → 轮次仍在进行 → 权限 → 工具 → 幂等 → 与 legacy 相同的门禁与执行。
- 出网限制、审计字段，以及 14 条 P2 必须通过的测试（B01–B14）。

## 测试隔离：调查结果（更正 P0 的判断）

P0 审计把 `render-execution.integration.test.ts` 的 2 项失败归因于"并行时等锁"。**这个判断是错的**：集成项目配置了 `fileParallelism: false`，测试文件逐个运行，不存在并行文件之间的锁竞争。

已经确认的事实：
- 单独运行这个文件：2/2 通过。
- 运行 `apps/worker/src` 下全部 28 个集成文件：108/108 通过，期间每 2 秒查一次数据库，没有任何语句等锁超过 3 秒。
- 失败时报的是 `beforeEach` 钩子 10 秒超时。这个钩子删除共享测试库的全部工作区。

根因还没定位。为此正在跑一次全量集成：按顺序记录每个测试，同时记录等锁的语句，并让测试库记录超过 2 秒的语句（只改本地测试库的设置）。结果出来之前，不改那 68 个"删除全部工作区"的测试文件，也不调大超时——那会掩盖问题，而不是修好它。
