# V7 B1 — DeepSeek：只发送最新的图，更早的图换成一句说明

- 依据：裁决 `docs/decisions/0022-v7-borrow-harness-mechanisms.md` 第 3 条 B1
- 借鉴来源：DSH `packages/compaction/compaction-image-offload`。它把较早的图永久换成文字说明，之后的请求都按这个决定组装，可以从会话日志重放。DSH 的纯文本模型路线也是把图换成固定的文字。
- 状态：**离线协议测试与离线测量完成；真实 DeepSeek 调用 `NOT_VERIFIED`**（需要花费，等所有者审批）

## 问题

- DeepSeek 的 Pro 只收文字。以前的规则是：只要历史里出现过图片，这一轮后面的每一步都改用 Flash。
- 导演第一次看画面通常在开头几步。于是剪辑、审片、调整这些决策几乎都由 Flash 完成，部署方配置的 Pro 只在开头几步生效。生产环境（darely.xyz）配置的是 `deepseek-v4-pro`。
- 每一步还会重发历史里的全部图片：19 步之后，一次请求要带 27 张图。

## 改动

只改 `packages/providers/deepseek/src/index.ts` 里组装请求的 `toDeepSeekMessages`，以及选择模型的一行：

- **图只出现在最后一条模型回复之后的消息里**，也就是这一步刚拿到的工具结果。模型已经回应过的旧图换成一句说明：`[Images from tool result <id> (<n>) were shown in an earlier step and are omitted now; call the tool again if you need to see them.]`
- **模型按实际发出的内容选择。** 这一步带新图就用 Flash，否则用配置的模型。
- **请求仍然只由轮次日志决定。** 一条消息只在它不再是最新的时候变一次（图换成说明），之后每一步的投影都相同，DeepSeek 的前缀缓存因此继续有效。

**不变的部分：**
- 轮次日志里的图片原样保存，草稿、门禁、计量的逻辑都不变。实际模型仍按 `response.model` 计量，两个模型都要有单价，与以前相同。
- Claude、Gemini 等其他适配器不变。Claude 有提示缓存，旧图留在缓存前缀里，按测量不需要这样做（裁决 0022）。
- 涉及的层：只有 Provider 适配器、测试与文档。契约只改了一行注释；迁移、领域、API、SDK、界面都不适用。

## 取舍（请所有者知悉）

- **每个 token 更贵。** 按 `docs/verification/vps-darely-20261023.md` 记录的峰值价（美元 / 百万 token），Pro 比 Flash 贵：

  | | Pro | Flash | 倍数 |
  |---|---|---|---|
  | 输入 | 1.32 | 0.30 | 4.4× |
  | 输出 | 3.96 | 1.20 | 3.3× |
  | 缓存命中 | 0.044 | 0.006 | 7.3× |

  改动后多数步骤回到 Pro。好在请求体积小了很多（见下表），但每轮实际花多少，要有真实调用才知道。单轮上限、月度上限与"未定价不调用"的门禁照旧生效。
- **看画面的那一步只看到刚取的图。** 以前 Flash 能同时看到之前所有的图；现在要对比两段素材，模型要在同一步里一起取帧，或者再调用一次看画面的工具。占位文字会告诉它可以再调用；工具说明没有改。Worker 进程缓存了已经取到本地的源文件，再取帧只需重新解码单帧，不会重新下载。

## 实测（离线，真实工具输出）

**做法：**
- 用 ffmpeg 生成三段 20 秒的测试素材，上传到本地环境，等画面理解完成；
- 按导演常见顺序真实调用 19 次工具：列素材、检查 ×3、看素材 ×3、找剪点 ×3、看时间线、剪、自检、看成片、量节奏、看时间线、剪、自检、看成片；
- 每一步之前按循环的方式组装请求，分别交给改动前与改动后的适配器。fetch 是注入的，只记录请求体，不联网、不花钱；
- 每次看画面一步只调用一个工具。实际导演常把三段素材放在同一步里一起看，那样 Flash 的步数会更少。

| 20 次请求合计 | 改动前 | 改动后 |
|---|---|---|
| 用 Flash / Pro 的次数 | 15 / 5 | 5 / 15 |
| 发送的图片（张次） | 291 | 27（每张图只发一次） |
| 请求体总量 | 2.85 MB | 0.44 MB（-84%） |
| 最大一次请求 | 262 KB | 98 KB |

逐次结果：
- 改动前：从第 6 次请求起全部是 Flash。体积从 98 KB 一路涨到 262 KB。
- 改动后：只有刚看过画面的第 6、7、8、15、20 次用 Flash，其余都是 Pro。Pro 的请求不超过 23 KB。

测量脚本按约定命名 `scripts/.tmp-*`，不进提交。原始结果在本会话的临时目录。
